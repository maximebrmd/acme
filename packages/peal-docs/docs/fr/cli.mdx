`peal` travaille avec une instance Peal depuis un terminal. Il se connecte en votre nom, dans un navigateur, puis agit avec votre rôle dans chacun de vos espaces de travail : il écrit et supprime des brouillons, importe et récupère des médias, programme, publie, déplace et annule des publications, assure le suivi de celles qui sont parties, lit les statistiques, la facturation, les membres et les invitations, invite des personnes et enregistre une copie de vos données. Connecter des canaux et changer des rôles se font dans l’application web. Un script ou un agent que personne ne surveille la lance avec la [clé d’API](#api-key) d’un espace de travail à la place d’une connexion, et lit ses réponses en [JSON](#json). Ses messages sont en anglais.

## L’obtenir [#install]

Il n’y a pas encore de version publiée. Construisez-le depuis un clone du dépôt, avec Bun installé :

```sh
bun install --frozen-lockfile
bun nx run peal-cli:build
packages/peal-cli/dist/peal --help
```

`packages/peal-cli/dist/peal` est un seul fichier qui embarque Bun : copiez-le n’importe où dans votre `PATH`.

## Choisir l’instance [#instance]

Pointez `peal` vers l’adresse où vous ouvrez Peal, comme `https://peal.example.com`, avec `--api-url` ou `PEAL_API_URL`. L’option l’emporte ; sans l’une ni l’autre, `peal` utilise `http://localhost:3000`, un serveur lancé depuis les sources.

`peal` n’envoie votre connexion ou une clé d’API qu’en HTTPS, ou à cette machine (`localhost`) : en HTTP simple ailleurs, tout ce qui se trouve sur le trajet pourrait les lire, donc la commande est refusée avant d’en envoyer, et `peal doctor` le dit. Pour un serveur auto-hébergé sans TLS sur un réseau de confiance, passez `--insecure-http`, ou définissez `PEAL_INSECURE_HTTP=true`.

```sh
export PEAL_API_URL=https://peal.example.com
peal health
```

`peal health` dit si l’instance répond. Il se termine avec le code 0 quand elle répond, et avec 1 quand elle est injoignable (après 5 secondes) ou répond par une erreur : un script peut donc l’attendre. `peal health --json` affiche ce qu’il a mesuré, `{"healthy": true, "milliseconds": 12, "url": "https://peal.example.com"}`, et [`peal doctor`](#doctor) vérifie le reste de la configuration.

## Se connecter [#login]

```sh
peal login
```

`peal login` affiche une adresse et un code de huit lettres et chiffres :

```text
To sign in to https://peal.example.com, open https://peal.example.com/device in a browser and enter the code WDJB-MJHT.
Or open https://peal.example.com/device?user_code=WDJBMJHT, where the code is filled in.
Waiting for you to approve the sign-in (the code works for 10m)…
```

1. Ouvrez l’adresse. Connectez-vous à Peal si ce n’est pas déjà fait.
2. Vérifiez que le code est celui de votre terminal, puis choisissez **Autoriser**. N’approuvez qu’un code que vous avez demandé vous-même : la personne qui a lancé la connexion reçoit votre accès.
3. De retour dans le terminal, `peal login` indique où il a enregistré la connexion.

Le code reste valable 10 minutes. **Refuser** rejette la connexion, et `peal login` s’arrête.

Quand votre compte a activé la [validation en deux étapes](/settings#two-step), le navigateur demande le code de votre application d’authentification, ou un code de secours, quand vous vous y connectez ; la commande ne change pas. Dans un espace de travail qui l’[exige](/settings#require-two-step) alors que votre compte ne l’a pas activée, chaque commande est refusée, et le dit : activez-la dans les paramètres de compte de l’application web, puis relancez la commande, avec la même connexion. `peal doctor` nomme un tel espace. Aucune commande ne gère la validation en deux étapes, et avec `PEAL_API_KEY` rien ne change : les clés ne sont pas concernées.

`peal` demande à faire ce que votre rôle permet dans vos espaces de travail, à programmer et publier des publications, et à rester connecté. Une connexion faite avant que `peal` demande la publication ne l’a pas : les commandes qui font partir des publications le disent alors, et vous demandent de relancer `peal login` et de l’approuver. Il enregistre la connexion à cette instance dans `credentials.json`, que vous seul pouvez lire, dans le premier de ces dossiers qui est défini :

- `PEAL_CONFIG_DIR` ;
- `$XDG_CONFIG_HOME/peal` ;
- `%APPDATA%\peal`, sous Windows ;
- `~/.config/peal`.

Chaque instance a sa propre connexion, rangée sous son adresse : vous pouvez être connecté à plusieurs. `peal` renouvelle son accès de lui-même, et n’affiche jamais ses jetons.

## Qui suis-je [#whoami]

```sh
peal whoami
```

```text
Signed in to https://peal.example.com as Sam Example <sam@example.com>.
Workspaces:
  Studio (owner)    studio   7c9e6679-7425-40de-944b-e07fc1f90ae7
  Clients (editor)  clients  3f2b8a41-5d6c-4e7f-8a9b-0c1d2e3f4a5b
```

Chaque espace de travail vient avec son slug et son identifiant, que prend `--workspace`. `peal whoami` s’adresse à une personne connectée : avec une [clé d’API](#api-key), il est refusé, car une clé n’est personne.

Quand la connexion ne fonctionne plus, parce qu’elle a été révoquée ou que votre compte a été banni, `peal whoami` le dit et vous demande de relancer `peal login`. Avant toute connexion, il répond que vous n’êtes pas connecté.

## Dans tous les espaces [#across-workspaces]

```sh
peal overview
peal agenda --from 2026-11-20T00:00 --to 2026-11-27T00:00 --workspace clients
peal report --days 90 --csv rapport.csv
```

`peal overview` dit ce qui demande votre attention dans chaque espace de travail auquel vous appartenez : les publications qui ont échoué ou sont à vérifier, les approbations en attente, les canaux à reconnecter ou désactivés, les commentaires qui attendent une réponse, un espace au-delà de son offre, ou une fois que rien ne demande votre attention. Chaque espace montre ce que votre rôle y permet de lire, et un espace qui exige la validation en deux étapes que votre compte n’a pas activée est nommé sans aucun chiffre. `peal agenda` liste ce qui part dans ces espaces, les 14 prochains jours sauf si `--from` et `--to` disent autre chose (31 jours au plus), chaque publication avec son heure en UTC, son espace, ses plateformes, son état et le début de son texte ; `--workspace`, répété, en garde certains, par slug ou identifiant. `peal report` montre les publications, l’engagement, les impressions et les abonnés de chaque espace sur les 7, 30 ou 90 derniers jours (`--days`, 30 par défaut ; `--time-zone`), chacun à côté des jours d’avant, là où votre rôle lit les statistiques ; `--csv` enregistre le rapport en fichier CSV, une ligne par espace, jamais par-dessus un fichier qui existe. Les trois prennent `--json`, `--limit` et `--cursor`, et sont pour une personne connectée : une clé d’API appartient à un seul espace ([Dans tous vos espaces de travail](/settings#across-workspaces)).

## Se déconnecter [#logout]

```sh
peal logout
```

`peal logout` demande à l’instance de révoquer la connexion, puis l’oublie, même si l’instance ne répond pas dans les 5 secondes.

## La lancer avec une clé d’API [#api-key]

Pour un lancement que personne ne surveille, comme une tâche planifiée ou un agent sur un serveur, mettez dans `PEAL_API_KEY` la [clé d’API](/settings#api-keys) d’un espace de travail, et nommez cet espace par son identifiant :

```sh
export PEAL_API_URL=https://peal.example.com
export PEAL_API_KEY=peal_…
export PEAL_WORKSPACE=7c9e6679-7425-40de-944b-e07fc1f90ae7
peal doctor
peal drafts list --json
```

- La clé n’est lue que dans l’environnement. Aucune option ne la prend : une option finit dans l’historique du shell et dans la liste des processus. `peal` ne l’affiche jamais.
- Tant que `PEAL_API_KEY` est définie, elle l’emporte sur une connexion enregistrée. Une valeur vide n’est pas une clé.
- `--workspace` ou `PEAL_WORKSPACE` doit donner l’identifiant de l’espace de travail, pas son slug, et il n’y a pas de valeur par défaut : une clé ne peut pas chercher les espaces de travail. L’identifiant figure dans l’adresse des pages de l’espace de travail dans l’application web (`/app/<id>/settings`), et `peal whoami`, connecté en tant que personne, le liste. Sinon la commande s’arrête avec `workspace_id_required`.
- La clé fait ce que ses permissions permettent, et rien de plus : sans `post:schedule`, elle écrit tout au plus des brouillons. Un refus arrive dans les mots du serveur, avec la permission qui manque.
- Ce que seule une personne fait est refusé avant toute requête (`person_required`) : `peal login`, `peal whoami`, `peal account export` et `peal account apps`, `peal members list`, et toutes les commandes `peal invitations`.
- Une clé que le serveur n’accepte plus, révoquée, expirée ou venue d’un autre serveur, est signalée comme telle (`api_key_refused`), et non comme une connexion à renouveler.

## Vérifier la configuration [#doctor]

```sh
peal doctor
peal doctor --workspace studio --json
```

`peal doctor` vérifie ce qu’un lancement utiliserait, et ne change rien. Lancez-le d’abord, avant qu’un script ou un agent ne fasse quoi que ce soit.

```text
ok  api-url        https://peal.example.com, from PEAL_API_URL.
ok  health         The server answers.
ok  ready          The server and its database both answer.
ok  changelog      The API's latest release is of 2026-11-09: The API as the SDKs' release 0.3.0 calls it: 49 operations. Later entries list what each release adds to it.
ok  credential     The sign-in saved for https://peal.example.com. PEAL_API_KEY is not set.
ok  access         Signed in as Sam Example <sam@example.com>, in 2 workspaces: Studio (studio, 7c9e6679-7425-40de-944b-e07fc1f90ae7, owner); Clients (clients, 3f2b8a41-5d6c-4e7f-8a9b-0c1d2e3f4a5b, editor).
ok  publish-scope  The sign-in has workspace:publish: it can schedule and publish, where your role allows it.
ok  workspace      Commands act in Studio (studio, 7c9e6679-7425-40de-944b-e07fc1f90ae7, owner), from --workspace.
ok  mcp            MCP clients connect to https://peal.example.com/api/mcp: peal mcp shows how.
```

| Vérification    | Ce qu’elle regarde                                                                                                                                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `api-url`       | L’adresse de l’instance, et d’où elle vient : `--api-url`, `PEAL_API_URL` ou la valeur par défaut. Échoue pour du HTTP simple hors de cette machine, sauf si `--insecure-http` l’autorise.                                |
| `health`        | Que le serveur répond, en 5 secondes au plus.                                                                                                                                                                             |
| `ready`         | Qu’il joint sa base de données.                                                                                                                                                                                           |
| `changelog`     | Qu’il répond à `GET /api/changelog`, avec la dernière version de l’API ([Journal des modifications](/api-conventions#changelog)) : un serveur qui n’y répond pas est plus ancien, ou n’est pas un serveur Peal.           |
| `credential`    | Ce qu’un lancement utilise pour s’authentifier : la clé de `PEAL_API_KEY`, ou la connexion enregistrée. Jamais affiché.                                                                                                   |
| `access`        | Que ce moyen fonctionne : qui est connecté et où, ou, pour une clé, qu’elle lit les canaux de l’espace de travail.                                                                                                        |
| `publish-scope` | Si la connexion peut programmer et publier. Ignorée pour une clé, qui a des permissions et pas de scope. Une connexion qui ne l’a pas est `ok` : elle écrit des brouillons, et il ne faut pas chercher à contourner cela. |
| `workspace`     | Dans quel espace de travail agissent les commandes, et d’où vient ce choix.                                                                                                                                               |
| `mcp`           | L’adresse à laquelle se connectent les clients MCP.                                                                                                                                                                       |

Chaque vérification est `ok`, `failing` (en échec) ou `skipped` (ignorée) : une vérification est ignorée quand elle ne peut pas se faire, comme lorsque le serveur ne répond pas, ou qu’elle ne s’applique pas. Une vérification en échec vient avec ce qu’il faut faire, sur une ligne qui commence par `To do:`. `peal doctor` se termine avec le code 1 dès qu’une vérification échoue.

Avec `--json`, il affiche `{"checks": [{"name", "status", "detail", "fix"}], "ok"}` sur la sortie standard, `fix` seulement là où il y a quelque chose à faire, et, quand une vérification échoue, l’[échec](#json) `checks_failed` sur la sortie d’erreur, avec le nom des vérifications en échec dans `failed`.

## Connecter un client MCP [#mcp]

```sh
peal mcp
```

`peal mcp` affiche le point d’accès MCP de l’instance et une configuration que la plupart des clients MCP acceptent, et prévient quand l’instance ne laisse pas les clients MCP s’enregistrer eux-mêmes. [Connecter un client MCP](/mcp) explique la suite.

## Choisir l’espace de travail [#workspace]

Chaque commande ci-dessous agit dans un espace de travail. Nommez-le avec `--workspace` (ou `-w`), par son identifiant court (slug) ou son identifiant, ou définissez `PEAL_WORKSPACE` une fois pour les commandes qui suivent. Si vous n’appartenez qu’à un espace de travail, `peal` le prend ; si vous appartenez à plusieurs sans en nommer aucun, il liste leurs slugs et s’arrête. Avec une [clé d’API](#api-key), donnez l’identifiant de l’espace de travail.

```sh
export PEAL_WORKSPACE=studio
peal drafts list
peal drafts list --workspace clients
```

Chaque commande fait ce que votre rôle y permet, comme l’application web : un lecteur lit, un éditeur écrit, programme, publie et assure le suivi, un propriétaire ou un administrateur invite. Quand l’instance refuse, `peal` dit pourquoi (votre rôle, le statut de la publication, la formule) et se termine avec le code 1. Le refus finit par l’identifiant de la requête et le code de l’erreur, comme `Request 019a7b2f-9a04-7b61-8c3d-2e5f7a1b4c68 (forbidden).` : citez cet identifiant quand vous demandez de l’aide ([Requêtes et réponses](/api-conventions#requests)).

## Canaux [#channels]

```sh
peal channels list
peal channels list --platform youtube --status disabled --search "client a"
peal channels rename <channel-id> "Client A"
peal channels rename <channel-id> --clear
peal channels disable <channel-id>
peal channels enable <channel-id>
peal channels capabilities [<channel-id>] [--json]
peal channels lookup <channel-id> [<lookup>] [--region <country>] [--language <tag>] [--vanity-name <name>] [--limit <n>] [--cursor <cursor>] [--json]
peal channels tiktok <channel-id>
peal channels defaults show <channel-id>
```

`peal channels list` liste les canaux de l’espace de travail avec leurs identifiants, que les brouillons et les publications prennent, le [nom que l’espace de travail a donné à chacun](/channels#name) devant son identifiant sur la plateforme, et si chacun publie, est désactivé ou est à reconnecter ; une dernière ligne les compte par état. `--platform`, `--status` (`active`, `disabled` ou `refreshNeeded`) et `--search`, un texte que contient l’identifiant du canal ou l’un de ses noms, restreignent la liste, tous les filtres devant être vrais, une page à la fois (`--limit`, puis le `--cursor` qu’affiche la page précédente) ; les nombres portent alors sur tous les états, quel que soit celui que demande `--status`. Avec l’une de ces options, `--json` affiche la page (`items`, `nextCursor`, `counts`) ; sans aucune, il affiche la liste des canaux, comme toujours. Connecter un canal se fait dans l’application web.

`peal channels rename` donne à un canal le nom par lequel votre espace de travail le désigne, de 60 caractères au plus, affiché dans Peal à côté de l’identifiant que la plateforme donne au compte et envoyé à aucune plateforme ; sans nom, ou avec `--clear`, il retire ce nom. `peal channels disable` [désactive un canal](/channels#turn-off) : rien ne part sur lui, et une publication dont l’heure arrive pendant ce temps échoue sur ce canal, part sur les autres, et n’est pas envoyée plus tard. Le canal garde sa connexion, son historique et sa place dans votre formule. `peal channels enable` le réactive : il publie de nouveau, ou indique qu’il est à reconnecter quand sa plateforme a cessé d’accepter l’accès de Peal entre-temps. Les trois demandent le droit de connecter des canaux.

`peal channels capabilities` montre [ce qu’un canal accepte](/api-overview#capabilities) : comment son texte est compté et limité, les médias qu’il accepte avec les limites de chaque type de fichier, les options de sa plateforme (que règle `peal drafts save --options`) et ce que le compte lui-même restreint, lu sur la plateforme à ce moment-là. Sans canal, la commande résume chaque plateforme en une ligne.

`peal channels lookup` demande à la plateforme d’un canal les données du compte auxquelles ses options se rapportent : sans recherche, la commande liste celles du canal ; avec une recherche, elle la lance, comme `peal channels lookup <channel-id> youtubeVideoCategories --region FR` pour les catégories où une vidéo YouTube peut être classée en France. `peal channels lookup <channel-id> pinterestBoards` liste les tableaux d’un compte Pinterest, et `pinterestBoardSections --board <board-id>` les sections d’un tableau. Une recherche paginée se termine par le `--cursor` qui lit sa page suivante. Elle ne change rien. Avec `--json`, les deux commandes affichent la réponse du serveur en JSON, pour les scripts.

`peal channels tiktok` lit les réglages d’un canal TikTok sur TikTok, comme TikTok le demande avant une publication : sous quel nom il publie, les audiences qu’une publication peut choisir (son `privacyLevel`, sans valeur par défaut), les interactions que le compte a désactivées, qui restent désactivées, et sa vidéo la plus longue, ou pourquoi il ne peut pas publier aujourd’hui. Publier sur TikTok vaut acceptation de sa confirmation d’utilisation de la musique, et de sa politique sur le contenu de marque pour un contenu de marque.

`peal channels defaults` montre, enregistre et efface les [options par défaut](#default-options) d’un canal : ce que prend une nouvelle publication sur ce canal quand elle n’en donne pas.

## Brouillons [#drafts]

```sh
peal drafts list                  # du plus récent au plus ancien ; --limit et --cursor les parcourent
peal drafts save --text "Le catalogue de printemps est sorti" --channel <channel-id> --channel <channel-id>
peal drafts save --post <post-id> --text "Le catalogue de printemps sort aujourd’hui"
peal drafts save --post <post-id> --options '<channel-id>={"platform":"youtube","title":"Catalogue de printemps","madeForKids":false}'
peal drafts save --post <post-id> --tag "Campagne de printemps"
peal drafts save --text "Le catalogue de printemps est sorti" --set Lancement --default-signatures
peal drafts discard <post-id>
```

- `peal drafts save` sans `--post` écrit un nouveau brouillon, pour les canaux que nomme `--channel` (aucun pour l’instant convient). Avec `--post`, il modifie ce brouillon : le texte, quand `--text` est donné, et les canaux, quand un `--channel` l’est. Ce que vous laissez de côté reste tel quel, médias et [options des plateformes](/scheduling#options) des canaux qu’il garde compris.
- `--then <text>`, répété, donne au brouillon les parties qui le suivent, comme les prend `peal post`, avec `--then-delay <seconds>` entre elles. Un brouillon que vous modifiez garde ses parties sans `--then`, et prend les nouvelles à leur place avec.
- `--options <channel-id>=<json>` règle les options de la plateforme d’un canal, en JSON avec sa `platform` : pour YouTube, `title` et `madeForKids` (tous deux nécessaires pour programmer), `privacy`, `tags`, `categoryId`, `notifySubscribers`, `containsSyntheticMedia`, `license`, `embeddable`, `publicStatsViewable`, `defaultLanguage`, `recordingDate` (comme `2026-11-27`), `thumbnailMediaId` (un JPEG ou un PNG de la [médiathèque](/media), par son identifiant) ; pour TikTok, `privacyLevel` (nécessaire, l’un de ceux que liste `peal channels tiktok`), `disableComment`, `disableDuet`, `disableStitch`, `commercialContent`, `brandOrganic`, `brandContent`, `aiGenerated`, le `videoCoverTimestampMs` d’une vidéo, le `photoTitle`, l’`autoAddMusic` et le `photoCoverIndex` d’une publication photo ; pour Pinterest, `boardId` (nécessaire, l’un de ceux que liste `peal channels lookup`), `boardSectionId`, `title`, `link`, `coverSecond`, `dominantColor` ; pour LinkedIn, `visibility` (`public` par défaut, `connections` sur un profil, ou `loggedIn`), `disableReshare`, `mentions` (des pages d’entreprise, chacune un `name` et un `urn` que `peal channels lookup` trouve sur un canal de page d’entreprise), `linkUrl` avec son `linkTitle` et une `linkDescription`, et le `documentTitle` d’un document PDF ; pour Google Business Profile, `postType` (`standard` par défaut, `event` ou `offer`), `title`, `startsAt` et `endsAt` (nécessaires pour un événement ou une offre, comme `2026-11-27T09:00`, à l’heure de l’établissement), `callToAction` avec `callToActionUrl`, et pour une offre `couponCode`, `redeemUrl` et `terms` ; pour Mastodon, `visibility`, `contentWarning`, `sensitive`, `language`, `quotePolicy` ; pour Bluesky, `languages`, `contentLabel`, `replies` (`everyone`, `nobody`, ou `limited` à ceux de `replyFollowers`, `replyFollowing` et `replyMentioned` qui valent `true`), `disableQuotes` ; pour Threads, `replyControl`, `topicTag`, `linkAttachment` ; pour X, `replySettings`, `communityId`, `shareWithFollowers`, `paidPartnership`, `madeWithAi` (voir [les options de Mastodon, Bluesky, Threads et X](/scheduling#feed-options)) ; pour Instagram, `format` (`story`, envoyée sans le texte), le `shareToFeed`, le `coverMediaId` (un JPEG de la médiathèque), le `thumbOffsetMs`, l’`audioName` et le `trialReel` d’un reel, et `collaborators` (des noms d’utilisateur, chacun invité) ; pour Facebook, `format` (`story` ou `reel`) et le `videoTitle` d’une vidéo ou d’un reel (voir [les formats de publication](/scheduling#formats) et [les options de YouTube, TikTok, Instagram et Facebook](/scheduling#media-options)). Répétez-le pour plusieurs canaux ; il remplace en entier les options de ce canal.
- `--tag <id-ou-nom>` range le brouillon sous l’une des [étiquettes](#tags) de l’espace de travail ; répétez-le pour plusieurs. Sans lui, un brouillon que vous modifiez garde ses étiquettes ; avec lui, il prend celles données à leur place.
- `--set <id-ou-nom>` nomme l’un des [groupes de canaux](#sets) de l’espace de travail au lieu d’en lister les canaux ; répétez-le pour plusieurs. Le brouillon est aussi pour les canaux connectés du groupe, avec les options que le groupe garde pour eux là où `--options` n’en donne pas. Un canal du groupe qui n’est plus connecté est laissé de côté, et `peal` dit lequel.
- `--signature <id-ou-nom>` place l’une des [signatures](#signatures) de l’espace de travail sous le texte du brouillon, sur tous les canaux, et `--default-signatures` celle par défaut de chaque canal. Une signature fait alors partie du texte du brouillon, et n’est jamais ajoutée sous un texte qui se termine déjà par elle.
- Un nouveau brouillon prend les [options par défaut](#default-options) d’un canal là où il n’en donne pas ; un brouillon que vous modifiez garde ce qu’il a.
- Un brouillon ne part à aucune heure. Son texte, ses médias et ses options sont vérifiés contre les règles de chaque plateforme quand il est programmé, avec `peal posts schedule` ou dans l’application web.
- `peal drafts discard` supprime un brouillon pour de bon. Une publication programmée ou partie n’est pas un brouillon : déprogrammez-la ou annulez-la plutôt.

## Écrire et envoyer une publication [#post]

```sh
peal post "Le catalogue de printemps est sorti" --channel <channel-id> --at 2026-11-20T10:00 --time-zone Europe/Paris
peal post "Le catalogue de printemps est sorti" --channels <channel-id>,<channel-id> --now
peal post "Le catalogue de printemps est sorti" --channel <channel-id> --at 2026-11-20T09:00:00Z \
  --media ./couverture.jpg --alt "Un catalogue papier ouvert sur une table en bois" \
  --idempotency-key catalogue-printemps-2026-11-20
peal post "Le catalogue de printemps est sorti" --channel <channel-id> --at 2026-11-20T10:00 --time-zone Europe/Paris --dry-run
peal post "Le catalogue de printemps est sorti" --channel <channel-id> --now --wait 30
```

`peal post` écrit une publication et l’envoie en une seule commande, au public des comptes que connectent ses canaux. Ce qui part ne peut pas être repris depuis Peal.

- **Quand.** `--at` la programme, `--now` la publie aussitôt, `--queue <nom-ou-identifiant>` ou `--default-queue` la place sur le prochain créneau libre d’une [file d’attente](#queues), et l’une d’elles est obligatoire : publier n’est jamais le comportement par défaut. `--at` prend un instant avec son décalage, comme `2026-11-20T09:00:00Z` ou `2026-11-20T10:00:00+01:00`, ou une heure locale sans décalage, comme `2026-11-20T10:00`, lue dans `--time-zone` (ou `--zone`), un fuseau IANA comme `Europe/Paris`. Sans l’option, le fuseau est `TZ`, puis celui de votre ordinateur. Une heure locale que les horloges sautent ou répètent dans ce fuseau est refusée : donnez l’instant avec son décalage.
- **Où.** `--channel` (ou `--channels`) nomme un canal par son identifiant ; répétez-le, ou séparez les identifiants par des virgules. `--set <id-ou-nom>` nomme un [groupe de canaux](#sets), et vaut pour ses canaux connectés : il faut au moins un canal ou un groupe. Un canal d’un groupe qui n’est plus connecté est laissé de côté, et `peal` dit lequel après la publication ; quand il n’en reste aucun et qu’aucun `--channel` n’est donné, rien n’est publié.
- **Médias.** Chaque `--media` est un fichier, importé d’abord ; une adresse `https://`, que le serveur va chercher ; ou l’identifiant d’un média que l’espace de travail a déjà, tel que `peal media list` le montre. Ils s’affichent dans l’ordre donné, 20 au plus. Le premier `--alt` décrit le premier `--media`, le deuxième le deuxième.
- **Fil.** Chaque `--then <text>` ajoute une partie à la suite de la publication, dans l’ordre donné, en texte seul : une réponse à la partie précédente sur les plateformes qui ont des [fils](/scheduling#threads). `--then-delay <seconds>` fait attendre chaque partie ce temps-là après le départ de la précédente, un jour (86400) au plus ; sans lui, elles se suivent. Une plateforme qui prend une publication seule refuse la publication.
- **Options.** `--options <channel-id>=<json>` règle les [options de la plateforme](/scheduling#options) d’un canal, comme les prend `peal drafts save`. Un canal pour lequel vous n’en donnez pas prend les options d’un groupe que vous nommez, puis les [options par défaut](#default-options) du canal.
- **Signatures.** `--signature <id-ou-nom>` place l’une des [signatures](#signatures) de l’espace de travail sous le texte, sur tous les canaux ; `--default-signatures` place celle par défaut de chaque canal. Une signature fait partie du texte de la publication : elle compte dans la limite de chaque plateforme, et n’est jamais ajoutée deux fois.
- **Étiquettes.** `--tag <id-ou-nom>` range la publication sous l’une des [étiquettes](#tags) de l’espace de travail ; répétez-le pour plusieurs.
- **Liens courts.** `--shorten-links` envoie ses liens raccourcis, sur un serveur qui a des [liens courts](/scheduling#short-links), et `--no-shorten-links` tels qu’écrits ; sans l’un ni l’autre, la publication prend le choix par défaut de l’espace de travail. `peal short-links list` lit ensuite leurs clics.
- **La relancer.** `--idempotency-key` prend le texte de votre choix, de 255 caractères au plus, comme un UUID : dans les 24 heures, la même clé avec la même publication répond la publication créée la première fois, sans en faire une autre ; avec une autre publication, elle est refusée. Sans elle, `peal` n’envoie aucune clé. Pour relancer une publication avec des médias, donnez à `--media` des identifiants de médias : fichiers et adresses sont stockés de nouveau à chaque lancement, ce qui en fait une autre publication.
- **Deux fois la même publication.** En dehors des clés, une publication dont le contenu (le texte que reçoit le canal et les mêmes médias, dans le même ordre) part déjà sur l’un de ses canaux à moins de 23 heures de son heure est refusée, et `peal` nomme la publication qui l’a déjà. `--allow-duplicate` la laisse passer, quand vous voulez vraiment publier deux fois la même chose ([Publications en double](/posting-api#duplicates)).
- **Vérifier d’abord.** `--dry-run` vérifie la publication et ne publie rien : il dit ce qui serait refusé, et quels canaux d’un groupe seraient laissés de côté.
- **Attendre le résultat.** Avec `--now`, `--wait <seconds>` (60 au plus) attend que chaque canal ait son résultat avant de répondre. Quand le temps est écoulé avant, la publication continue de se publier : `peal posts wait` attend la suite.

La publication est d’abord vérifiée contre la plateforme de chaque canal. Quand elle enfreint une règle, rien n’est publié, et `peal` liste chaque violation sur sa propre ligne, avec son canal, sa plateforme, son option ou son média, et la limite.

## Publications [#posts]

```sh
peal posts list
peal posts list --from 2026-11-01T00:00:00Z --to 2026-12-01T00:00:00Z
peal posts list --tag "Campagne de printemps"
peal posts show <post-id>
peal posts attempts <post-id>
peal posts wait <post-id> --seconds 30
peal posts import publications.csv --dry-run
peal posts import publications.csv --idempotency-key campagne-printemps-2026-11
peal posts schedule <post-id> --at 2026-11-20T10:00 --time-zone Europe/Paris
peal posts schedule <post-id> --at 2026-11-20T09:00:00Z --channels <channel-id>,<channel-id>
peal posts publish <post-id>
peal posts reschedule <post-id> --at 2026-11-21T10:00 --time-zone Europe/Paris
peal posts unschedule <post-id>
peal posts cancel <post-id>
peal posts repost <post-id> <target-id>
peal posts confirm <post-id> <target-id> published --permalink https://mastodon.example/@studio/1
peal posts confirm <post-id> <target-id> not-published
peal posts unpublish <post-id> --channel <channel-id> --yes
peal posts edit <post-id> --channel <channel-id> --text "Ouverture des portes à 19 h, pas 18 h."
peal posts changes <post-id>
peal posts tag <post-id> --tag "Campagne de printemps" --tag Intemporel
peal posts duplicate <post-id>
```

- `peal posts list` liste les publications de l’espace de travail, quel que soit leur état, une page à la fois, avec ce que chacune est devenue ([Lister les publications](/posting-api#search)). `--tag` garde les publications rangées sous une [étiquette](#tags).
- `peal posts attempts` liste chaque tentative de Peal pour publier la publication, par canal, envoi et tentative : quand elle a commencé, comment elle a fini, le code qui accompagne un refus, celui de la plateforme ou celui de Peal, et quand Peal a réessayé.
- `peal posts show` affiche le statut et l’heure de la publication, ses étiquettes quand elle en a, puis une ligne par canal, qui commence par l’identifiant de sa cible, avec ce qui s’y est passé : échouée et pourquoi, non confirmée et pourquoi, ou publiée à son adresse (et gardée privée, quand YouTube a gardé privée une vidéo publique ou non répertoriée), puis les options de la publication sur chaque canal qui en a.
- `peal posts wait` attend que chaque canal d’une publication ait son résultat, jusqu’à `--seconds` (60 au plus), puis montre la publication dans son état du moment. Attendre ne change rien : relancez-le quand le temps s’est écoulé avant.
- `peal posts import` crée et envoie les publications que liste un fichier CSV, une par ligne, avec les colonnes `text`, `channels` (des identifiants de canaux, ou un [groupe de canaux](#sets) par son identifiant ou par un nom sans espace, virgule ni point-virgule) et `at`, et au besoin `media`, `time_zone`, `allow_duplicate` et `idempotency_key` ([Importer des publications depuis un fichier CSV](/posting-api#import)). Chaque ligne est d’abord vérifiée, et rien n’est créé si une seule n’est pas valide. `--dry-run` ne fait que vérifier le fichier. `--idempotency-key` permet de relancer l’import sans risque pendant 24 heures : les lignes déjà créées ne le sont pas deux fois.
- `peal posts schedule` programme un brouillon pour `--at`, lu comme le lit `peal post`, sur les canaux qu’il a, ou sur ceux que nomme `--channel`. Son texte, ses médias et ses options doivent respecter les règles de chaque plateforme, sinon rien n’est programmé.
- `peal posts publish` publie maintenant un brouillon, ou une publication programmée, sur ses canaux. Elle atteint le public des comptes, et ne peut pas être reprise depuis Peal une fois partie.
- `peal posts reschedule` déplace une publication programmée à une autre heure. Un brouillon est alors programmé, sur les canaux qu’il a.
- `peal posts unschedule` ramène une publication programmée à l’état de brouillon : elle ne part à aucune heure tant qu’elle n’est pas reprogrammée. Une publication déjà en cours de publication ne peut pas être déprogrammée.
- `peal posts cancel` annule pour de bon un brouillon ou une publication programmée : elle ne part sur aucun canal. Une publication déjà en cours de publication finit avec ce que ses canaux ont fait, et ceux qui n’ont pas encore reçu l’envoi sont annulés. Pour modifier une publication programmée et la garder, déprogrammez-la plutôt.
- `peal posts repost` renvoie la publication, maintenant, sur un canal où elle a échoué ou n’est pas confirmée. Quand elle n’est pas confirmée, vérifiez d’abord sur la plateforme : elle est peut-être déjà en ligne.
- `peal posts confirm` enregistre ce que vous avez trouvé sur la plateforme pour une publication que Peal n’a pas pu confirmer : `published`, avec son adresse si vous l’avez, ou `not-published`, qui la marque en échec sur ce canal pour que `peal posts repost` puisse la renvoyer. [Programmer des publications](/scheduling) explique comment finissent les publications.
- `peal posts unpublish` supprime une publication partie de ses plateformes, pour tout le monde, toutes les parties d’un fil ([Dépublier une publication](/scheduling#unpublish)) : d’un canal avec `--channel` (son identifiant, son nom d’utilisateur exact, ou sa plateforme et son nom d’utilisateur, comme dans `--channel "bluesky studio.example"` ; un nom d’utilisateur que partagent deux canaux de la publication est refusé, en les listant), ou de chaque canal où c’est possible. C’est définitif : il demande d’abord, sauf avec `--yes`, et avec `--json` il exige `--yes`. `--wait <secondes>`, avec `--channel`, attend la fin de la suppression. `peal posts changes` liste ce qui a été demandé à la publication une fois partie, et `peal posts list --removed` les publications retirées d’un canal.
- `peal posts edit` remplace le texte d’une publication en ligne sur un canal, sur Mastodon et Google Business Profile ([Modifier une publication en ligne](/scheduling#edit-live)) : `--channel` le désigne comme `peal posts unpublish`, `--text` est le nouveau texte, `--part <n>` la partie d’un fil (depuis 0, la publication elle-même). Seul le texte change, et la modification est publique immédiatement. `--wait <secondes>` attend la fin de la modification ; `peal posts changes` dit comment elle s’est passée.
- `peal posts duplicate` crée un nouveau brouillon qui dit ce que dit une publication ([Dupliquer une publication](/organise#duplicate)), quel que soit son statut : son texte, ses médias, ses canaux avec leur texte et leurs options, et ses étiquettes. Ce que l’espace de travail n’a plus (un canal déconnecté, un média ou une étiquette supprimés) est laissé de côté, et `peal` le dit. Le brouillon n’a pas d’heure, et la publication elle-même ne change pas.

## Étiquettes [#tags]

```sh
peal tags list
peal tags create "Campagne de printemps" --colour green
peal tags update "Campagne de printemps" --name "Printemps 2027" --colour teal
peal tags delete "Printemps 2027"
peal posts tag <post-id> --tag Intemporel
```

- Les étiquettes sont les libellés sous lesquels un espace de travail range ses publications, 100 au plus. Elles ne disent rien aux plateformes : rien d’une étiquette ne part avec une publication.
- `peal tags create` prend un nom de 40 caractères au plus, qu’aucune autre étiquette de l’espace de travail ne porte, quelle que soit sa casse, et une couleur avec `--colour` (`gray` sauf indication contraire, `red`, `orange`, `amber`, `green`, `teal`, `blue`, `purple` ou `pink`).
- Partout où une commande prend une étiquette, donnez son identifiant ou son nom, quelle que soit sa casse : `peal tags list` montre les deux.
- `peal tags update` change le nom, la couleur ou les deux, et garde ce que vous laissez de côté. Ses publications gardent l’étiquette.
- `peal tags delete` supprime définitivement une étiquette et la retire de chaque publication qui la portait ; les publications restent.
- `peal posts tag` range une publication sous les étiquettes que nomme `--tag`, 10 au plus, à la place de celles qu’elle avait ; sans `--tag`, il les retire toutes. Une publication prend des étiquettes quel que soit son statut, partie ou non.
- Tout membre qui lit les publications lit les étiquettes ; créer, modifier et supprimer une étiquette, et étiqueter une publication, demandent le droit de modifier les publications.

## Signatures [#signatures]

```sh
peal signatures list
peal signatures create "Formule de fin" --text "L’équipe du Studio" --default
peal signatures create "Fédivers" --text "#studio" --platform mastodon
peal signatures update "Formule de fin" --text "À la semaine prochaine"
peal signatures delete "Fédivers"
```

- Une signature est un texte qu’un espace de travail garde pour terminer ses publications, de 2000 caractères au plus ; un espace de travail en garde 50. Elle est faite pour tous les canaux, pour les canaux d’une plateforme (`--platform`) ou pour un seul canal (`--channel <channel-id>`).
- `--default` en fait la signature par défaut là où elle s’applique : les publications qui demandent les signatures par défaut (`--default-signatures`) la prennent à cet endroit, celle de l’espace de travail sous le texte de la publication, celle d’une plateforme ou d’un canal sous le texte que ce canal a à la place. La signature qui était celle par défaut à cet endroit ne l’est plus.
- Une fois sous le texte d’une publication, une signature fait partie de ce texte : elle compte dans la limite de chaque plateforme quand la publication est programmée, et elle n’est jamais ajoutée sous un texte qui se termine déjà par elle. Une publication en plusieurs parties (`--then`) est signée sous sa dernière partie.
- Partout où une commande prend une signature, donnez son identifiant ou son nom, quelle que soit sa casse : `peal signatures list` montre les deux.
- `peal signatures update` change ce que nomment ses options (`--name`, `--text`, `--whole-workspace`, `--platform` ou `--channel`, `--default` ou `--no-default`) et garde le reste. Les publications qui portent déjà le texte de la signature le gardent tel qu’il était.
- `peal signatures delete` supprime définitivement une signature ; les publications qui portent déjà son texte le gardent.
- Tout membre qui lit les publications lit les signatures ; en créer, en modifier et en supprimer une demandent le droit de modifier les publications.

## Groupes de canaux [#sets]

```sh
peal sets list
peal sets create "Lancement" --channel <channel-id> --channel <channel-id>
peal sets create "Vidéos" --channel <channel-id> --options '<channel-id>={"platform":"youtube","madeForKids":false}'
peal sets update "Lancement" --name "Jour du lancement"
peal sets delete "Vidéos"
peal post "Le catalogue de printemps est sorti" --set Lancement --at 2026-11-20T09:00:00Z
```

- Un groupe de canaux est une sélection des canaux de l’espace de travail gardée sous un nom, de 50 canaux au plus, avec les options que prennent les publications sur certains d’entre eux (`--options`, comme les prend `peal drafts save`) ; un espace de travail garde 50 groupes. `peal post --set` et `peal drafts save --set` nomment un groupe au lieu d’en lister les canaux.
- Partout où une commande prend un groupe, donnez son identifiant ou son nom, quelle que soit sa casse : `peal sets list` montre les deux. Un import CSV ne nomme un groupe que par son identifiant ou par un nom sans espace, virgule ni point-virgule.
- `peal sets list` montre les canaux de chaque groupe, et dit lesquels ne sont plus connectés. Une publication créée avec le groupe les laisse de côté et le dit ; elle ne part jamais sur moins de canaux en silence.
- `peal sets update` change le nom, les canaux (ceux que nomme `--channel` remplacent ceux du groupe) ou les options, et garde ce que vous laissez de côté, sauf les canaux qui ne sont plus connectés : un groupe n’est enregistré qu’avec des canaux connectés, et c’est donc aussi ainsi qu’on en retire un. Les publications créées avec le groupe auparavant gardent leurs canaux.
- `peal sets delete` supprime définitivement un groupe ; ses canaux, et les publications créées avec lui, restent.

## Files d’attente [#queues]

```sh
peal queues list
peal queues create "Weekdays" --slot mon@09:30 --slot wed@09:30 --slot fri@17:00 --zone Europe/Paris --channel <channel-id>
peal queues update "Weekdays" --slot tue@12:00 --default
peal queues show "Weekdays"
peal queues preview "Weekdays" --count 5
peal queues reshuffle "Weekdays"
peal queues delete "Weekdays"
peal post "Un conseil intemporel" --default-queue
peal post "Un conseil intemporel" --queue Weekdays --channel <channel-id> --dry-run
peal posts queue <post-id> --queue Weekdays
peal posts list --queue Weekdays
```

- Une [file d’attente](/fr/scheduling#queues) est un emploi du temps hebdomadaire de créneaux dans un fuseau horaire, pour certains canaux et au plus un groupe de canaux (`--set`). `--slot` prend un jour (`mon` ou `monday`…, en anglais) et une heure sur 24 heures, comme `mon@09:30` ; répétez-le, 100 au plus. `--zone` est le fuseau IANA de la file, `TZ` ou celui de votre ordinateur sans lui. Un espace de travail garde 20 files, et une file se nomme par son identifiant ou son nom, quelle que soit sa casse.
- `peal queues update` garde ce que vous laissez de côté, sauf les canaux qui ne sont plus connectés ; `--slot` remplace la semaine et `--clear-slots` la vide, `--channel` remplace les canaux et `--clear-channels` les retire tous, `--no-set` retire le groupe de canaux, `--default` en fait la file par défaut. Les publications placées par la file gardent leur heure. `peal queues delete` les laisse programmées.
- `peal queues preview` liste les prochains créneaux, libres ou pris, et où irait une publication ajoutée maintenant : rien n’est retenu.
- `peal queues reshuffle` place les publications en attente dans une file sur ses créneaux tels qu’ils sont maintenant, dans l’ordre de leurs heures, celles déplacées à la main comprises ([comment](/fr/scheduling#reshuffle)), et dit combien ont été déplacées et combien sont restées (en anglais, comme toute la ligne de commande). Quand le déplacement s’arrête, à un mois où l’abonnement n’a plus de place, faute de créneau, ou parce que la file a été enregistrée entre-temps, la commande le dit avec le nombre de publications restantes : relancez-la. Avec `--json`, elle affiche la réponse de l’API.
- `peal post --queue <nom-ou-identifiant>` place une publication sur le prochain créneau libre de cette file (`--queue=<nom-ou-identifiant>` aussi), et `peal post --default-queue` sur celui de la file par défaut. Chacune est l’une de `--at`, `--now`, `--queue` et `--default-queue`, et sans `--channel` ni `--set` la publication va sur les canaux de la file. Avec `--dry-run`, la commande affiche le créneau qu’elle prendrait.
- `peal posts queue` place un brouillon, ou une publication programmée, sur le prochain créneau libre d’une file (`--queue`, ou celle par défaut). `peal posts list --queue` liste les publications placées par une file.

## Publications répétées [#recycling]

```sh
peal recycling start <post-id> --every 2w --count 6 --variant "Ouvert tout l’été, comme avant."
peal recycling list --status active
peal recycling show <rule-id>
peal recycling update <rule-id> --until 2026-12-31 --variant "Une autre façon de le dire"
peal recycling pause <rule-id>
peal recycling resume <rule-id>
peal recycling end <rule-id>
peal posts list --recycling <rule-id>
```

- `peal recycling start` [répète](/scheduling#recycling) une publication programmée ou en ligne : `--every` prend un nombre et `d`, `w` ou `m` (1d à 365d, 1w à 52w, 1m à 12m) ; `--count` le nombre de publications en tout, celle-ci comprise (2 à 100) ; `--until` le dernier jour ; `--variant`, répété, les textes dits à tour de rôle après celui de la publication, 10 au plus ; `--queue` une file d’attente, par nom ou identifiant. La commande affiche les trois prochaines publications et la variante de chacune.
- `peal recycling update` change le nombre (`--no-count` le retire), la date de fin (`--no-until`) ou les variantes (`--variant` les remplace toutes, `--no-variants` les retire). `pause` et `resume` l’arrêtent et la relancent ; `resume` relance aussi une règle terminée faute de place dans l’offre, pour un texte refusé, ses canaux, les créneaux de sa file ou sa publication annulée ou remise en brouillon (une fois programmée de nouveau), et `resume --variant` lui donne d’autres variantes, comme un texte refusé le demande. `end` l’arrête pour de bon ; les publications créées restent. Un nombre, un jour ou plus de 10 variantes hors limites est refusé avant tout envoi.
- `peal recycling list` affiche 50 règles par page (`--limit`, 100 au plus) et une ligne `More:` avec le `--cursor` de la suivante.
- `peal posts list --recycling` liste les publications créées par une règle.

## Flux [#feeds]

```sh
peal feeds preview https://blog.example/feed.xml --template "Nouveau sur le blog : {title}"
peal feeds add https://blog.example/feed.xml --channel <channel-id> --template $'{title}\n\n{link}'
peal feeds add https://blog.example/feed.xml --mode queue --queue Semaine
peal feeds list
peal feeds show <feed-id>
peal feeds items <feed-id>
peal feeds update <feed-id> --template "{title} : {link}"
peal feeds pause <feed-id>
peal feeds resume <feed-id>
peal feeds remove <feed-id>
```

- `peal feeds add` suit un [flux](/fr/scheduling#feeds) : ce qu’il contient alors n’est jamais publié, et chaque élément qui paraît ensuite devient un brouillon, ou avec `--mode queue` une publication sur le prochain créneau libre de la file (`--queue`, par nom ou identifiant ; la file par défaut sinon), sans que personne ne le lise avant. `--channel` (répété, ou des identifiants séparés par des virgules) et `--set` disent où vont ses publications, `--template` ce qu’elles disent (`{title}`, `{link}`, `{summary}`), et `--picture` joint l’image de chaque élément, importée dans la médiathèque.
- `peal feeds preview` lit une adresse et affiche ses trois éléments les plus récents tels que le modèle les écrirait, sans rien garder. `peal feeds items` affiche ce que sont devenus ses 50 éléments les plus récents, jamais ce qu’ils disaient.
- `peal feeds update` change les canaux, le mode, la file (`--default-queue` prend la file par défaut de l’espace de travail, et l’une ou l’autre va avec `--mode queue` ou un flux déjà sur une file), le groupe (`--no-set` le retire), le modèle ou l’adresse (lue aussitôt) ; `pause` et `resume` l’arrêtent et le relancent, `resume` le lisant aussitôt. `remove` cesse de le suivre ; ses brouillons et publications restent.

## Options par défaut [#default-options]

```sh
peal channels defaults show <channel-id>
peal channels defaults set <channel-id> --options '{"platform":"youtube","madeForKids":false,"privacy":"unlisted"}'
peal channels defaults clear <channel-id>
```

- Les options par défaut d’un canal sont celles que prend une nouvelle publication sur ce canal quand elle n’y donne aucune [option de plateforme](/scheduling#options) et qu’aucun groupe de canaux qu’elle nomme n’en donne : un nouveau brouillon, et une publication créée en une seule commande. Un brouillon que vous modifiez garde ce qu’il a.
- `--options <json>` prend les options de la plateforme du canal, en JSON avec sa `platform`, comme `peal drafts save --options` les prend après l’identifiant du canal. Elles remplacent celles que le canal avait, et peuvent être incomplètes.
- Les options par défaut sont un point de départ, jamais un moyen de contourner les règles : une publication qui les prend est vérifiée quand elle est programmée comme une publication qui les aurait écrites elle-même.
- `peal channels defaults clear` laisse le canal sans options par défaut ; les publications déjà créées gardent les leurs.

## Médias [#media]

```sh
peal media upload ./couverture.jpg --alt "Un catalogue papier ouvert sur une table en bois"
peal media import https://files.example/printemps/couverture.jpg --alt "Un catalogue papier ouvert sur une table en bois"
peal media generate --prompt "Un catalogue papier ouvert sur une table en bois, lumière du matin" --aspect landscape
peal media list                   # du plus récent au plus ancien ; --limit et --cursor les parcourent
peal media show <media-id>
peal media describe <media-id> --text "Un catalogue papier ouvert sur une table en bois"
peal media delete <media-id>
```

- `peal media upload` envoie un fichier dans les médias de l’espace de travail : JPEG, PNG, GIF ou WebP jusqu’à 16 Mio, MP4 ou QuickTime jusqu’à 1 Gio, ou un document PDF jusqu’à 100 Mio et 300 pages, reconnu à son extension. Le fichier va directement au stockage des médias, puis Peal le vérifie et le lit.
- `peal media import` fait récupérer au serveur une image, une vidéo ou un document PDF à une adresse `https://` publique, sans identifiants, en 90 secondes au plus ([Images et vidéos](/media#import)). Pour les fichiers plus lourds ou plus lents, utilisez `peal media upload`.
- `peal media generate` fait créer au [fournisseur d’images](/settings#image-provider) de l’espace de travail, ou sinon au modèle d’images de l’instance, une image d’après `--prompt` (de 1 à 1 000 caractères, envoyés tels quels à ce fournisseur) dans les médias de l’espace de travail, au format `--aspect` `square` (par défaut), `landscape` ou `portrait` ([Générer une image](/media#generate)). Avec le modèle de l’instance, elle coûte 5 des demandes à l’assistant du jour de l’espace de travail, avec le fournisseur de l’espace de travail aucune ; l’image est marquée comme créée par IA : réglez la mention IA de la plateforme dans les options de la publication, et décrivez-la avec `--alt` quand vous la joignez. Un espace de travail sans fournisseur à lui, sur une instance sans modèle d’images, est refusé.
- `peal media list` liste les images et vidéos de l’espace de travail, de la plus récente à la plus ancienne, avec les identifiants que les publications prennent et si chacune est prête. `--limit` prend 100 au plus.
- `peal media show` affiche un média : son type, sa taille, quand il a été stocké, s’il est prêt à être joint, et sa description. Après un envoi ou une récupération, il dit quand une vidéo que Peal lit encore devient `ready`.
- `peal media describe` règle la description d’un média dans la médiathèque avec `--text`, ou la retire avec `--clear`. Les publications qui l’ont déjà joint gardent leur texte alternatif.
- `peal media delete` supprime un média définitivement. Il dit d’abord quels brouillons le montrent et le perdent, puis demande (`--yes` sinon, et avec `--json`) ; un média qu’une publication programmée montre est refusé, avec ces publications.
- `--alt` dit ce que montre le fichier, pour les personnes qui ne peuvent pas le voir.

Chaque commande affiche l’identifiant du média. Seul un média `ready` va dans une publication.

## Le fournisseur d’images de l’assistant [#assistant]

```sh
peal assistant image-provider show
peal assistant image-provider set --base-url https://images.example.com/v1 --model <le-modèle-de-votre-fournisseur> < cle.txt
peal assistant image-provider set --base-url https://images.example.com/v2 --model <le-modèle-de-votre-fournisseur> --keep-key
peal assistant image-provider clear
```

- Ces commandes gèrent le [fournisseur d’images](/settings#image-provider) de l’espace de travail, et demandent `assistant:configure` (propriétaires, administrateurs, et les clés à qui il a été donné).
- `set` ne prend jamais la clé en argument, que l’historique du shell et la liste des processus garderaient : dans un terminal, il la demande sans afficher ce que vous tapez ; sinon, il la lit sur l’entrée standard, jusqu’à sa fin, sans son dernier saut de ligne. `--keep-key` garde la clé déjà enregistrée, que le serveur accepte seulement tant que `--base-url` reste exactement le même (pour changer le modèle seul) ; toute autre adresse redemande la clé.
- `show` affiche l’adresse, le modèle et si la clé peut encore être lue, jamais la clé. `clear` retire le fournisseur et supprime sa clé, après avoir demandé (`--yes` sinon).

## Relectures et approbations [#review]

```sh
peal approvals list
peal approvals approve <post-id> --approval <approval-id> --subject <fingerprint>
peal approvals request-changes <post-id> --approval <approval-id> --subject <fingerprint> --comment "Dites jeudi, pas vendredi."
peal approvals policy
peal approvals policy --set always
peal review show <post-id>
peal review comment <post-id> --text "Très bien." --reply-to <comment-id>
peal review link <post-id> --access comment --hours 48
peal review links <post-id>
peal review revoke <link-id>
```

- `peal approvals list` affiche les publications qui attendent une [approbation](/review), avec l’heure demandée pour chacune et qui a demandé. `approve` en programme une ; approuvée après son heure, elle redevient un brouillon. `request-changes` la renvoie en brouillon avec votre commentaire. Les deux décident de ce que vous avez lu : `list` et `peal review show` affichent, pour chaque publication qui attend, les `--approval` et `--subject` qu’une décision prend, et une publication qui a changé depuis n’est pas décidée (`peal` le dit ; relisez-la).
- La ligne de commande est une application : sous la politique qui retient les publications des applications, ce qu’elle programme attend, et elle n’approuve que ce qu’un membre a demandé dans l’application web.
- `peal approvals policy` montre quelles publications attendent ; `--set never`, `contributorsAndApplications` ou `always` le change, pour les propriétaires et les administrateurs.
- `peal review show` affiche la publication telle que chaque canal la recevra, ses approbations et ses commentaires, fil par fil. Ce que les personnes invitées ont tapé est affiché comme du texte, les caractères de contrôle remplacés.
- `peal review link` crée un lien de relecture (`--access view` ou `comment`, par défaut ; `--hours`, 14 jours sinon) et affiche son adresse, une seule fois. Un lien qui permet d’approuver se crée dans l’application web seulement : la ligne de commande est une application, et approuverait ainsi ses propres publications. `links` liste les liens d’une publication sans leur adresse, et `revoke` en termine un.

## Sortie pour les scripts [#json]

`--json` affiche la réponse de l’API en un seul document JSON sur la sortie standard, et rien d’autre, avec les instants en ISO 8601, en UTC. Toutes les commandes qui lisent ou changent quelque chose par l’API la prennent, ainsi que `peal health` et `peal doctor` ; `peal login`, `peal logout` et `peal mcp` ne la prennent pas.

```sh
peal post "Le catalogue de printemps est sorti" --channel <channel-id> --now --json
peal posts show <post-id> --json
```

- Le document est la réponse du point d’accès que la commande appelle, telle que la [référence de l’API](/reference) la décrit : une publication, une page avec `items` et `nextCursor`, un tableau.
- Une commande dont le point d’accès répond sans corps, comme `peal drafts discard`, `peal invitations revoke` ou `peal webhooks delete`, affiche `null`.
- `peal billing --json` contient les deux réponses qu’il lit, sous `billing` et `standing` ; `peal health --json` et `peal doctor --json` affichent des documents qui leur sont propres ([Choisir l’instance](#instance), [Vérifier la configuration](#doctor)).

Sous `--json`, un échec est lui aussi un seul document JSON, sur la sortie d’erreur, avec le code de sortie 1, et la sortie standard reste vide :

```json
{
  "error": {
    "code": "forbidden",
    "message": "This API key does not have the permission post:schedule. An owner or an admin of the workspace gives it to the key, or creates a key that has it.",
    "permission": "post:schedule",
    "reason": "missingPermission",
    "requestId": "019a7b2f-9a04-7b61-8c3d-2e5f7a1b4c68"
  }
}
```

Pour un refus de l’API, `error` est l’erreur telle que le serveur l’a envoyée : son `code`, son `message`, le `requestId` et ses propres champs ([Codes d’erreur](/api-conventions#error-codes) liste tous les codes). Décidez d’après `code`, jamais d’après `message`. La ligne de commande a ses propres codes pour ce qui l’arrête avant une réponse de l’API, ou à sa place :

| Code                      | Quand                                                                                                                                      |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `invalid_usage`           | Les arguments sont illisibles : une option inconnue, un argument manquant.                                                                 |
| `unreachable`             | L’instance n’a rien répondu : connexion refusée, hôte inconnu, délai dépassé.                                                              |
| `unhealthy`               | `peal health` a reçu une réponse qui n’est pas celle d’un serveur en bonne santé.                                                          |
| `unexpected_answer`       | L’instance a répondu quelque chose que le contrat de l’API ne décrit pas : elle est peut-être plus ancienne, ou n’est pas un serveur Peal. |
| `not_signed_in`           | Aucune connexion n’est enregistrée pour l’instance, et `PEAL_API_KEY` n’est pas définie.                                                   |
| `sign_in_expired`         | La connexion enregistrée ne fonctionne plus : relancez `peal login`.                                                                       |
| `api_key_refused`         | L’instance a refusé la clé de `PEAL_API_KEY` : révoquée, expirée, ou venue d’un autre serveur.                                             |
| `person_required`         | La commande s’adresse à une personne connectée, et `PEAL_API_KEY` est définie.                                                             |
| `workspace_id_required`   | Avec une clé d’API, aucun espace de travail n’est nommé, ou il l’est autrement que par son identifiant.                                    |
| `workspace_required`      | Vous appartenez à plusieurs espaces de travail et n’en avez nommé aucun.                                                                   |
| `workspace_unknown`       | Vous n’appartenez à aucun espace de travail de ce slug ou de cet identifiant.                                                              |
| `no_workspace`            | Vous n’appartenez encore à aucun espace de travail.                                                                                        |
| `credential_store_failed` | La connexion n’a pas pu être lue dans `credentials.json`, ou y être enregistrée.                                                           |
| `checks_failed`           | `peal doctor` a trouvé des vérifications en échec, nommées dans `failed`.                                                                  |
| `refused`, `failed`       | Tout autre refus ou échec de la ligne de commande, avec la raison dans `message`.                                                          |

Une réponse au statut d’erreur qui ne porte aucune erreur de l’API a le code général de l’API pour ce statut, comme `internal_error`, et le `requestId` quand le serveur en a donné un.

Un agent qui lance des commandes plutôt que des outils MCP travaille de la même façon : [Publier depuis un agent IA](/agents#cli).

## Statistiques [#analytics]

```sh
peal analytics summary                                     # les 30 derniers jours, aujourd’hui compris
peal analytics summary --from 2026-10-01 --to 2026-10-31 --time-zone Europe/Paris
peal analytics post <post-id>
peal analytics dashboard --days 7                          # par rapport aux 7 jours précédents
peal analytics channel <channel-id> --days 30
peal analytics best-times --channel <channel-id> --days 90
peal analytics export posts --output posts.csv --from 2026-10-01 --to 2026-10-31
peal analytics export accounts --format json --output accounts.ndjson
```

`peal analytics summary` additionne les compteurs des publications parues sur une période : au total, par canal, et les publications qui ont le plus fait réagir. Les jours suivent `--time-zone`, un fuseau IANA comme `Europe/Paris` ; sans lui, `TZ`, puis le fuseau de votre ordinateur. `peal analytics post` affiche les derniers compteurs d’une publication sur chaque canal où elle est partie. Un tiret remplace un compteur que la plateforme ne donne pas. Voir [Statistiques](/analytics).

`peal analytics dashboard` montre une période à côté du même nombre de jours avant elle : chaque total avec ce qui a changé, les abonnés avec ce qu’ils ont gagné, chaque canal, et les meilleures publications. `peal analytics channel` affiche un canal jour par jour : abonnés, abonnements, vues, portée, et les interactions gagnées par ses publications. Les deux acceptent `--days 7`, `30` ou `90` (30 par défaut), ou `--from` et `--to`. `peal analytics best-times` dit quand les publications d’un canal ont le mieux marché, par jour de la semaine et par heure dans `--time-zone`, sur `--days 30`, `90` (par défaut) ou `180` : les meilleures heures, et combien de publications compte chaque heure pesée. C’est le passé du canal, jamais une prévision, et rien n’est classé sous 20 publications ([Quand les publications ont le mieux marché](/analytics#best-times)). `peal analytics export posts` ou `accounts` enregistre les chiffres dans le fichier que nomme `--output`, en CSV ou, avec `--format json`, un objet JSON par ligne ; il ne remplace aucun fichier.

## Facturation [#billing]

```sh
peal billing
```

`peal billing --json` affiche les deux réponses de l’API en un seul document, sous `billing` et `standing`. Sans cette option, la commande affiche la formule et l’abonnement de l’espace de travail, et, pour chaque limite (canaux, membres, publications qui partent ce mois-ci, demandes à l’assistant aujourd’hui, médias stockés), ce qui est utilisé de ce que la formule permet, et si l’espace de travail peut encore commencer son essai. Il ne change rien : les propriétaires et administrateurs commandent, résilient ou se rétractent sur la page **Facturation** de l’espace de travail ([Abonnements et facturation](/billing)). Sur une instance qui ne facture pas, rien n’est limité.

## Utilisation [#usage]

```sh
peal usage
peal usage --from 2026-10-01 --to 2026-10-31
```

`peal usage` affiche l’abonnement de l’espace de travail, chaque limite face à ce qui est utilisé maintenant, puis, sur des jours UTC (les 30 derniers sauf si `--from` et `--to` disent autre chose, 92 au plus), les publications parties par plateforme, les jours-canal, les publications sur les plateformes qui facturent à la publication, et une ligne pour chaque jour qui a quelque chose : ses publications, les canaux, membres et médias tels que le relevé du jour les a trouvés (un tiret pour un jour sans relevé), et ses demandes à l’assistant. `--json` affiche la réponse de l’API telle qu’elle est venue. Il ne change rien, et rien n’y est facturé ([Utilisation](/billing#usage)).

## Liens courts [#short-links]

```sh
peal short-links status
peal short-links set-default on
peal short-links list --post <post-id>
peal short-links show <link-id> --from 2026-11-01 --to 2026-11-30
```

`peal short-links status` indique si le serveur a des [liens courts](/scheduling#short-links) et si les nouvelles publications de l’espace de travail en demandent par défaut, ce que `peal short-links set-default on` ou `off` change (propriétaires et administrateurs). `peal post` et `peal drafts save` suivent ce choix par défaut, sauf si `--shorten-links` ou `--no-shorten-links` en décide autrement pour la publication. `peal short-links list` liste les liens de l’espace de travail, du plus récent au plus ancien, avec leurs clics sur des jours UTC (les 30 derniers sauf `--from` et `--to`, 92 au plus), ceux d’une publication (`--post`) ou d’un canal (`--channel`), une page à la fois (`--limit`, `--cursor`) ; `peal short-links show` affiche les clics d’un lien jour par jour. Les décomptes sont approximatifs : les lecteurs automatisés sont écartés, et rien des visiteurs n’est conservé ([Clics sur les liens courts](/analytics#short-links)). `--json` affiche la réponse de l’API telle quelle.

## Membres et invitations [#members]

```sh
peal members list
peal invitations list
peal invitations send sam@example.com --role editor
peal invitations revoke <invitation-id>
```

- Chaque membre voit les membres. Les propriétaires et administrateurs voient les invitations en attente, expirées comprises, les envoient et les révoquent.
- `peal invitations send` envoie à l’adresse un lien valable 7 jours, avec le rôle que donne `--role` (`viewer` sauf indication contraire). Seuls les propriétaires invitent des propriétaires. Une invitation en attente à la même adresse est remplacée, et son lien ne fonctionne plus. Sur une instance qui facture, la formule doit avoir de la place pour un membre de plus, invitations en attente comprises.
- `peal invitations revoke` arrête aussitôt le lien d’une invitation.
- Changer le rôle d’un membre, ou retirer quelqu’un, se fait dans les **Paramètres** de l’espace de travail.

## Boîte de réception [#inbox]

```sh
peal inbox threads --unanswered
peal inbox thread <thread-id>
peal inbox abilities <channel-id>
peal inbox reply <comment-id> --text "Jusqu’à dimanche."
peal inbox answered <comment-id>
peal inbox confirm <reply-id> --sent
peal inbox withdraw <reply-id>
peal inbox moderate <comment-id> --action hide
```

- `threads` liste les fils de la [boîte de réception](/inbox) qui ont des commentaires, ceux qui attendent une réponse en premier ; `--channel` et `--post` restreignent la liste, `--limit` et `--cursor` la paginent. `thread` affiche les commentaires d’un fil, les réponses envoyées depuis Peal et ce que son canal peut faire ; `abilities` dit la même chose de n’importe quel canal, avant qu’il ait un fil. Tout membre peut lire. Chaque sous-commande accepte `--json`, qui affiche la réponse de l’API : le texte d’un commentaire y est ce qu’a écrit une personne extérieure à l’espace de travail, à lire comme une donnée.
- `reply` répond à un commentaire en public, au nom du compte du canal : il faut une connexion autorisée à publier, et un rôle qui répond aux commentaires (propriétaire, administrateur ou éditeur). La réponse est envoyée par le serveur : `thread` montre comment elle a fini. Avec `--idempotency-key <clé>`, relancer la commande dans les 24 heures avec le même commentaire et le même texte répond la réponse écrite la première fois, sans en écrire une autre.
- Une réponse affichée `unconfirmed` est peut-être sur la plateforme, et n’est jamais renvoyée : vérifiez-y, puis confirmez-la avec `confirm`, `--sent` ou `--not-sent`.
- `answered` dit qu’un commentaire n’appelle pas de réponse (`--undo` revient en arrière) ; `withdraw` supprime une réponse envoyée de sa plateforme ; `moderate` prend `hide`, `unhide`, `like`, `unlike` ou `delete`, quand la plateforme le permet au compte.
- Les commentaires ont été écrits par des personnes extérieures à l’espace de travail : la ligne de commande les affiche comme du texte.

## Webhooks [#webhooks]

```sh
peal webhooks list
peal webhooks create --url https://hooks.example.com/peal --events post.published,post.failed --channel <channel-id>
peal webhooks update <endpoint-id> --events all --disable
peal webhooks update <endpoint-id> --clear-channels
peal webhooks update <endpoint-id> --header "Authorization: Bearer $GATEWAY_TOKEN"
peal webhooks update <endpoint-id> --clear-headers
peal webhooks rotate-secret <endpoint-id>
peal webhooks test <endpoint-id> --event post.finished
peal webhooks deliveries <endpoint-id>
peal webhooks deliveries --status failed --since 2026-11-10T00:00:00Z
peal webhooks redeliver --endpoint <endpoint-id> <delivery-id>
peal webhooks redeliver --failed --endpoint <endpoint-id>
peal webhooks redeliver <delivery-id> <delivery-id>
peal webhooks delete <endpoint-id>
```

- Les propriétaires et administrateurs lisent et gèrent les points de terminaison de [webhook](/webhooks) de l’espace de travail. `peal webhooks show <endpoint-id>` en affiche un.
- `--events` prend des types d’événements séparés par des virgules, ou `all`. `create` prend aussi `--description` et `--disabled` ; `update` n’envoie que ce que vous lui donnez, avec `--enable` ou `--disable` pour activer ou désactiver le point de terminaison.
- `create` et `rotate-secret` affichent le secret de signature, une seule fois : enregistrez-le à ce moment. Après un renouvellement, l’ancien secret signe encore pendant 24 heures, à côté du nouveau.
- `--channel` (répété, ou des identifiants séparés par des virgules) limite un point de terminaison à ces chaînes, et `--clear-channels` lui fait de nouveau entendre toutes les chaînes ; `--workspace-id`, avec `--partner` sur `create`, limite un point de terminaison partenaire à ces espaces de travail, et `--clear-workspaces` retire la liste. `update` remplace une liste qu’on lui donne.
- `--header "Nom: valeur"` (répété, 5 au plus) ajoute un [en-tête à vous](/webhooks#headers) à chaque livraison, et `--clear-headers` sur `update` les retire ; `update` remplace tous les en-têtes par ceux qu’on lui donne. Les valeurs ne sont plus jamais affichées ni répondues : `show` liste les noms des en-têtes. Elles ne vont qu’à l’hôte pour lequel elles ont été données : une `--url` sur un autre hôte, pour un point de terminaison qui a des en-têtes, demande de redonner chaque `--header` avec sa valeur, ou `--clear-headers`. Votre shell garde ce que vous tapez dans son historique : donnez une valeur depuis une variable, comme ci-dessus.
- `test` envoie un événement `webhook.test`, ou avec `--event` un exemple de ce type, marqué `sample: true`.
- `deliveries` montre comment chaque livraison s’est terminée, la plus récente d’abord : celles d’un point de terminaison, ou sans lui celles de tous, avec `--status`, `--event`, `--since` et `--until` (des instants avec leur décalage).
- `redeliver` renvoie des livraisons : une avec `--endpoint` et son identifiant, comptée comme un renvoi un à un ; plusieurs par identifiant ; ou `--failed --endpoint <endpoint-id>` pour les échouées d’un point de terminaison, les plus anciennes d’abord, 100 par appel, avec `--since`, `--until` et `--event`, qui ne vont qu’avec `--failed`. Il affiche ce qu’il a ignoré et pourquoi, et combien il en reste : relancez-le pour celles-là. Quand il ne renvoie rien, il se termine en refus (`nothing_redelivered`, code de sortie 1). Ses arguments sont des identifiants de livraison : une ligne de commande plus ancienne prenait d’abord le point de terminaison (`redeliver <endpoint-id> <delivery-id>`), qui se nomme maintenant avec `--endpoint` ; un identifiant de point de terminaison donné comme livraison est ignoré, et la commande le dit.

## Journal d’activité [#activity]

```sh
peal activity list
peal activity list --operation posts.schedule --limit 50
peal activity list --actor <user-id|api-key-id> --json
```

`peal activity list` liste les requêtes qui ont demandé à changer quelque chose dans l’espace de travail, les plus récentes d’abord : quand, l’opération, le statut répondu et le code de l’erreur, qui a demandé, par quelle clé ou quelle application, les identifiants que nommait la requête, et l’identifiant de la requête. Les propriétaires le lisent, ainsi qu’une clé à qui un propriétaire a donné `activity:read` ; un événement est gardé {{keep-activity-fr}} ([Le journal d’activité](/settings#activity)).

- `--operation` ne garde qu’une opération, comme `posts.schedule`, ou `mcp.create_draft` pour un outil du point d’accès MCP ; `--actor` ne garde que ce qu’a demandé un membre, désigné par son identifiant d’utilisateur, ou une clé d’API, désignée par le sien.
- `--limit` prend 100 au plus. Quand il en reste, la dernière ligne donne la commande de la page suivante, avec son `--cursor`.

## Liens de connexion [#links]

```sh
peal links create --platform linkedin
peal links create --platform mastodon --hours 24 --locale fr
peal links create --platform instagram --channel <channel-id>
peal links list
peal links show <link-id>
peal links revoke <link-id>
```

- `peal links create` crée un [lien de connexion](/channels#connect-links) : une page hébergée où le propriétaire d’un compte de cette plateforme le connecte à l’espace de travail, sans compte Peal. Elle affiche l’adresse du lien, une seule fois : remettez-la par un canal de confiance. Pour les membres qui peuvent connecter des canaux.
- `--hours` dit combien de temps il fonctionne, de 1 à 720 (168 par défaut) ; `--locale` la langue dans laquelle sa page s’ouvre ; `--channel` reconnecte ce canal au lieu de connecter un nouveau compte ; `--return-url` où la page renvoie la personne une fois terminé, une adresse sur une origine que le compte partenaire de l’espace de travail a enregistrée.
- `peal links list` montre ceux qui attendent, et ceux utilisés, révoqués ou expirés depuis moins de 30 jours ; `show` dit quels canaux un lien a connectés, ou comment sa dernière connexion a échoué ; `revoke` en reprend un.

## Compte partenaire [#partner]

```sh
peal partner show
peal partner keys
peal partner workspaces --external-id cus_42
peal partner usage --from 2026-11-01 --to 2026-11-30
```

Pour les propriétaires et administrateurs d’un espace de travail qui a un [compte partenaire](/embedding) : `show` affiche ce que voient ses clients, les origines vers lesquelles les pages hébergées peuvent les renvoyer, et ce qu’il détient ; `keys` liste ses clés, jamais les clés elles-mêmes ; `workspaces` liste les espaces de travail qu’il possède, du plus récent au plus ancien, avec leurs identifiants externes et leurs canaux, `--external-id` en trouvant un exactement et `--name` cherchant ; `usage` affiche ce que le compte a utilisé par client sur une période de jours UTC (`--from`, `--to`, les 30 derniers par défaut, 92 au plus) : sur la première page, ce qu’il détient aujourd’hui et les totaux ; puis une ligne par espace de travail, l’identifiant externe en premier, son espace principal en tête de la première page, `--limit` et `--before` paginant comme l’[API](/embedding#usage), et la commande de la page suivante, sur les mêmes jours. Créer et supprimer ces espaces revient à l’API partenaire, avec une clé partenaire, et créer une clé aux **Paramètres** de l’espace de travail.

## Publicités [#ads]

Ces commandes suivent la page [Publicités](/fr/ads) : lisez-la d’abord, car
une mise en avant dépense de l’argent. Aucune commande ne se connecte à un
réseau publicitaire, ne connecte un compte publicitaire, n’active les
dépenses ni ne fixe le plafond mensuel : une personne le fait dans
l’application web. Mettre en avant depuis une connexion demande le scope
`workspace:ads`, que `peal login --ads` demande et qui n’est jamais demandé
sans cette option ; `peal doctor` dit si la connexion le détient.

| Commande                                                                    | Ce qu’elle fait                                                                                                                                                                                               |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `peal ads status`                                                           | Dit ce que le serveur propose pour les publicités : rien, la lecture des comptes publicitaires, ou aussi les mises en avant.                                                                                  |
| `peal ads accounts`                                                         | Liste les comptes publicitaires connectés : réseau, devise, état, si un propriétaire a autorisé chacun à dépenser, et son plafond mensuel.                                                                    |
| `peal ads account <account-id>`                                             | Affiche un compte publicitaire, son plafond et ce que ses mises en avant engagent ce mois-ci.                                                                                                                 |
| `peal ads campaigns <account-id> [--from <AAAA-MM-JJ>] [--to <AAAA-MM-JJ>]` | Liste les campagnes du compte telles que lues en dernier, avec ce que leurs publicités ont fait sur la période (les 30 derniers jours par défaut, 366 au plus).                                               |
| `peal ads list <account-id> [--campaign <campaign-id>] [--from …] [--to …]` | Liste les publicités du compte, celles d’une campagne avec `--campaign`, chacune avec la publication de l’espace de travail qu’elle promeut.                                                                  |
| `peal ads insights <account-id> [--from …] [--to …]`                        | Additionne ce que les publicités du compte ont fait chaque jour : dépense, impressions, couverture, clics, résultats.                                                                                         |
| `peal ads post <post-id>`                                                   | Affiche les chiffres organiques d’une publication à côté de ses chiffres payants, par compte publicitaire, et ses mises en avant : côte à côte, jamais additionnés.                                           |
| `peal ads boosts [--post <post-id>] [--cursor <cursor>]`                    | Liste les mises en avant de l’espace de travail, de la plus récente à la plus ancienne.                                                                                                                       |
| `peal ads boost show <boost-id>`                                            | Affiche une mise en avant, où elle en est, et les requêtes que Peal a envoyées au réseau publicitaire pour elle.                                                                                              |
| `peal ads boost quote …`                                                    | Vérifie une mise en avant sans rien créer : ce qu’elle peut coûter au plus, ses jours, et la marge sous le plafond mensuel.                                                                                   |
| `peal ads boost create … [--idempotency-key <key>] [--yes]`                 | **Dépense de l’argent.** Chiffre, affiche ce qui sera dépensé et pendant combien de temps, demande confirmation, puis met la publication en avant.                                                            |
| `peal ads boost pause <boost-id>`                                           | Met une mise en avant en pause ; elle ne dépense rien pendant ce temps. Sans risque à relancer.                                                                                                               |
| `peal ads boost resume <boost-id> [--yes]`                                  | **Dépense de l’argent.** Relance une mise en avant en pause jusqu’à sa fin, après confirmation.                                                                                                               |
| `peal ads boost stop <boost-id> [--yes]`                                    | Arrête une mise en avant définitivement, après confirmation.                                                                                                                                                  |
| `peal ads audit [--cursor <cursor>]`                                        | Liste le journal d’audit des publicités, qui ne répond qu’aux propriétaires (`ads:authorize`) : avec une clé d’API à laquelle un propriétaire a donné cette permission, car aucune application ne la détient. |

`boost quote` et `boost create` prennent les mêmes options :

| Option                                     | Sens                                                                                                                                                                                    |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--account <account-id>`                   | Le compte publicitaire qui paie. Obligatoire.                                                                                                                                           |
| `--post <post-id>`                         | La publication publiée à mettre en avant. Obligatoire.                                                                                                                                  |
| `--channel <channel-id>`                   | Le canal où elle est mise en avant : une Page Facebook, ou un compte Instagram connecté par sa Page. Obligatoire.                                                                       |
| `--total <montant>` ou `--daily <montant>` | Le budget pour toute la durée, ou par jour, dans l’unité de la devise (`50`, `50.00`). L’un des deux, exactement. Plus de décimales que la devise n’en a : refusé.                      |
| `--currency <EUR>`                         | La devise du budget. Obligatoire, jamais supposée : ce doit être celle du compte publicitaire, et rien n’est jamais converti.                                                           |
| `--ends <instant>`                         | La fin. Obligatoire : au moins un jour après le début, 90 jours au plus.                                                                                                                |
| `--starts <instant>`                       | Le début. Maintenant, si l’option est omise.                                                                                                                                            |
| `--time-zone <zone>`                       | Le fuseau dans lequel `--starts` et `--ends` sont lus quand ils sont écrits sans décalage.                                                                                              |
| `--countries <FR,BE>`                      | Codes pays ISO alpha-2, 25 au plus. Obligatoire.                                                                                                                                        |
| `--age-min <n>`, `--age-max <n>`           | De 18 à 65 (65 veut dire 65 ans et plus). 18 et 65 par défaut.                                                                                                                          |
| `--not-special-category`                   | Déclaration obligatoire : Peal ne met pas en avant les publicités sur le logement, l’emploi, les produits ou services financiers, ni les enjeux sociaux, les élections ou la politique. |
| `--beneficiary <nom>`, `--payer <nom>`     | Qui bénéficie de la publicité et qui la paie : obligatoires quand un pays est dans l’Union européenne.                                                                                  |
| `--idempotency-key <key>` (create)         | Rend la commande sûre à relancer : la même clé ne crée jamais une seconde mise en avant. Générée et affichée si elle est omise.                                                         |
| `--yes` (create, resume, stop)             | Répond d’avance à la confirmation. Obligatoire avec `--json`, et quand l’entrée n’est pas un terminal : la commande refuse alors avec `confirmation_required` plutôt que de demander.   |

## Vos données [#account]

```sh
peal account export                       # peal-data-2026-11-09.json, dans ce dossier
peal account export --output ~/peal-data.json
peal account apps
```

- `peal account export` enregistre une copie de tout ce que Peal garde sur vous, comme la page des paramètres du compte : votre compte, vos sessions, espaces de travail, invitations, applications connectées, notifications, préférences, les publications que vous avez écrites, et le contenu des espaces de travail dont vous êtes le seul membre. Elle ne contient ni mot de passe, ni jeton, ni clé, ni carte. Vous seul pouvez lire le fichier (mode 600), et `peal` n’écrase jamais un fichier sauf si vous ajoutez `--force`. Peal vous prévient par e-mail à chaque copie, en précisant qu’elle vient de la ligne de commande.
- `peal account apps` liste les applications qui agissent pour vous, dont cette ligne de commande et les clients MCP, avec ce qu’elles peuvent faire et où. Révoquez-en une depuis les **Paramètres du compte**, dans l’application web : aucune application n’en révoque une autre.
- Supprimer votre compte se fait aussi dans les **Paramètres du compte**.

<Callout type="note" title="Pourquoi les clients MCP ne le peuvent pas">
  Votre export et vos applications connectées vous sont ouverts dans
  l’application web et dans cette ligne de commande, que vous connectez depuis
  votre propre terminal et qui écrit sur votre propre disque. Aucun outil MCP ne
  les donne : un client MCP transmet ce que ses outils répondent à un modèle
  d’IA, et votre export contient les adresses de vos sessions et tout ce que
  vous avez écrit. L’instance les refuse à tout client OAuth autre qu’`peal`.
</Callout>

## Réglages [#settings]

| Variable             | Rôle                                                                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `PEAL_API_URL`       | L’adresse de l’instance, sauf si `--api-url` est indiqué. Par défaut : `http://localhost:3000`.                                                              |
| `PEAL_INSECURE_HTTP` | `true` laisse la connexion ou la clé d’API partir en HTTP simple vers un serveur qui n’est pas cette machine, comme `--insecure-http`. Désactivé par défaut. |
| `PEAL_API_KEY`       | Une clé d’API d’espace de travail à utiliser à la place d’une connexion enregistrée, sur laquelle elle l’emporte ([La lancer avec une clé d’API](#api-key)). |
| `PEAL_WORKSPACE`     | L’espace de travail où agissent les commandes, par slug ou identifiant, sauf si `--workspace` est indiqué. Avec une clé d’API, par identifiant.              |
| `TZ`                 | Le fuseau des jours d’`peal analytics summary`, et celui où `--at` est lu, sauf si `--time-zone` est indiqué.                                                |
| `PEAL_CONFIG_DIR`    | Le dossier où est enregistré `credentials.json`.                                                                                                             |
| `XDG_CONFIG_HOME`    | Sans `PEAL_CONFIG_DIR`, la connexion va dans son dossier `peal`.                                                                                             |
| `APPDATA`            | Sans l’une ni l’autre, sous Windows, la connexion va dans son dossier `peal`.                                                                                |
| `HOME`               | Sinon, la connexion va dans `~/.config/peal`.                                                                                                                |

`peal --help` liste les commandes, et `peal <commande> --help` en décrit une.
