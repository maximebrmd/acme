Peal sert le Model Context Protocol (MCP) : un assistant IA, ou tout autre client MCP, peut travailler dans un espace de travail pour vous : lire ses publications, médias, statistiques, facturation et membres, écrire des brouillons, programmer et publier des publications quand vous l’y autorisez, assurer le suivi des publications parties et inviter des personnes. Le client se connecte en votre nom, dans un navigateur, et agit dans le seul espace de travail que vous choisissez, sans dépasser ce que votre rôle permet. [Publier depuis un agent IA](/agents) déroule une publication entière.

## Le point d’accès [#endpoint]

Le point d’accès est `/api/mcp`, à l’adresse où vous ouvrez Peal, comme `https://peal.example.com/api/mcp`. Il parle Streamable HTTP, dans les révisions 2026-07-28, 2025-11-25 et 2025-06-18 du protocole.

`peal mcp`, depuis la [ligne de commande](/cli#mcp), affiche le point d’accès et une configuration que la plupart des clients MCP acceptent :

```json
{
  "mcpServers": {
    "peal": {
      "type": "http",
      "url": "https://peal.example.com/api/mcp"
    }
  }
}
```

Donnez au client cette adresse, ou cette configuration, comme sa documentation l’indique pour un serveur distant en HTTP.

## Connecter le client [#sign-in]

Peal connecte les clients MCP avec OAuth. Vous ne donnez aucune clé au client : à sa première requête, Peal lui répond qu’il lui faut un jeton, et lui indique où le demander.

1. Le client s’enregistre auprès de Peal, puis ouvre un navigateur sur la page de connexion de Peal. Connectez-vous si ce n’est pas déjà fait.
2. **Choisissez un espace de travail.** Le client n’agit que dans celui-là. Pour l’utiliser dans un autre, connectez-le de nouveau et choisissez l’autre.
3. Peal montre ce que le client demande, et où il vous renvoie ensuite. Quand il demande à publier, cette permission a sa propre ligne, avec une case que vous pouvez décocher pour ne le laisser écrire que des brouillons ([Ce que le client peut faire](#scopes)). Vérifiez les deux, puis choisissez **Autoriser**, ou **Refuser**. Peal ne vérifie pas qui a fait un client qui s’est enregistré lui-même, et le dit : n’en autorisez un que si vous lui faites confiance et avez lancé la connexion vous-même.

De retour dans le client, ses outils fonctionnent. Peal retient votre réponse pour ce client et cet espace de travail : le connecter de nouveau ne repose pas la question.

<Callout type="note" title="Si le client ne peut pas s’enregistrer">
  La plupart des clients MCP s’enregistrent eux-mêmes avant de se connecter, ce
  qu’un serveur Peal n’autorise que si son administrateur l’active
  (`MCP_DYNAMIC_REGISTRATION`, voir [Auto-hébergement](/self-hosting#mcp)).
  `peal mcp` prévient quand ce n’est pas le cas.
</Callout>

## Ce que le client peut faire [#scopes]

La page de consentement liste ce que le client demande :

| Permission                                                                                                                                       | Scope               | Ce qu’elle permet                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Savoir que c’est vous                                                                                                                            | `openid`            | L’identifiant de votre compte                                                                                                                                                                                |
| Voir votre nom et votre photo, voir votre adresse e-mail                                                                                         | `profile`, `email`  | Votre profil                                                                                                                                                                                                 |
| Rester connectée en votre absence, jusqu’à ce que vous la déconnectiez                                                                           | `offline_access`    | Renouveler son accès sans vous                                                                                                                                                                               |
| Lire l’espace de travail : publications, canaux, médias et statistiques                                                                          | `workspace:read`    | Lire, sans rien changer                                                                                                                                                                                      |
| Faire ce que votre rôle permet dans l’espace de travail, comme rédiger des brouillons et gérer les médias, sans rien programmer ni publier       | `workspace:write`   | Tout ce que votre [rôle](/scheduling#roles) permet, lecture comprise, sauf ce qui fait partir des publications : rien de ce qu’il fait n’atteint une plateforme                                              |
| L’autoriser à programmer et publier des publications sur vos comptes connectés, et à y répondre aux commentaires, où tout le monde peut les voir | `workspace:publish` | Ce que votre rôle permet de ce qui fait partir des publications, et la lecture : programmer, déplacer, publier et republier une publication, la déprogrammer, l’annuler, et confirmer ce qu’elle est devenue |

Publier est une permission à part. La page de consentement la montre sur sa propre ligne, avec une case cochée au départ : décochez-la, et le client reçoit le reste de ce qu’il a demandé, sans plus. Sans elle, un client qui peut écrire rédige toujours des brouillons, que vous relisez et programmez vous-même ; un client qui ne peut que lire lit toujours.

Un client connecté avant que publier ait sa propre permission n’a que celle d’écrire : il ne publie rien, et ne déprogramme, ne republie ni ne confirme plus rien, tant que vous ne l’avez pas connecté de nouveau en autorisant la publication. Une connexion garde jusque-là les permissions qu’elle a reçues.

Un client qui n’a aucune des trois permissions sur l’espace de travail ne peut rien faire. Son accès dure 15 minutes à la fois, et le client le renouvelle de lui-même. Chaque requête vérifie que vous appartenez toujours à l’espace de travail et n’êtes pas banni.

## Outils [#tools]

Chaque outil agit en votre nom, dans l’espace de travail où le client s’est connecté, avec les mêmes vérifications que l’application web : votre rôle décide de ce qu’il peut faire, et un client se voit refuser ce que vous ne lui avez pas permis, avec un message qui nomme la permission manquante : tout changement pour un client autorisé à lire seulement, et tout ce qui fait partir des publications pour un client que vous n’avez pas autorisé à publier. Pour lui en donner plus, connectez-le de nouveau et autorisez-le à ce moment-là.

Ces outils lisent, et ne changent rien :

| Outil                     | Ce qu’il répond                                                                                                                                                                                                                                                                                      |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `whoami`                  | Vous, et l’espace de travail où agit le client, avec votre rôle et ce que le client peut y faire                                                                                                                                                                                                     |
| `list_workspaces`         | Vos espaces de travail et votre rôle dans chacun, en marquant celui où agit le client                                                                                                                                                                                                                |
| `list_channels`           | Les [canaux](/channels) de l’espace de travail, et si chacun publie ou est à reconnecter. Jamais leurs jetons.                                                                                                                                                                                       |
| `list_drafts`             | Les brouillons de l’espace de travail, du plus récent au plus ancien, une page à la fois                                                                                                                                                                                                             |
| `list_posts`              | Les publications programmées entre deux instants, séparés de 62 jours au plus : celles qui restent à partir, celles qui sont parties, avec ce qui s’est passé sur chaque canal, et celles qui ont été annulées. Les brouillons n’en font pas partie.                                                 |
| `get_post`                | Une publication : ce qu’elle dit, quand elle part, et ce qui s’est passé sur chaque canal, avec les identifiants de ses cibles, leurs options de plateforme, et pourquoi l’une a échoué                                                                                                              |
| `list_post_attempts`      | Chaque tentative de Peal pour publier une publication, canal par canal, avec son résultat et le moment où Peal a réessayé                                                                                                                                                                            |
| `list_media`              | Les images et vidéos de l’espace de travail, de la plus récente à la plus ancienne, une page à la fois, avec leur type, leur taille, leurs dimensions, leur durée et leur description, et une adresse qui montre chacune pendant une heure. Seul un média `ready` peut être joint à une publication. |
| `get_tiktok_creator`      | Les réglages d’un canal TikTok, lus sur TikTok : sous quel nom il publie, les audiences qu’une publication peut choisir, les interactions désactivées, sa vidéo la plus longue. Il lit TikTok, hors de Peal.                                                                                         |
| `analytics_summary`       | Les compteurs des publications parues sur une période, dans un fuseau, comme les montrent les [Statistiques](/analytics)                                                                                                                                                                             |
| `analytics_dashboard`     | Une période à côté de la précédente, en un appel : totaux, abonnés et ce qu’ils ont gagné, par canal et par plateforme, chaque jour, et les meilleures publications                                                                                                                                  |
| `channel_analytics`       | Un canal jour par jour : ses abonnés, ses vues et sa portée, et ce que ses publications ont gagné                                                                                                                                                                                                    |
| `post_analytics`          | Les compteurs d’une publication sur chaque canal où elle est partie, au fil du temps                                                                                                                                                                                                                 |
| `get_billing`             | La formule de l’espace de travail, ses limites, ce que l’espace de travail utilise de chacune, et chaque abonnement avec ses prix                                                                                                                                                                    |
| `list_members`            | Les membres de l’espace de travail, avec leur nom et leur rôle, comme chaque membre les voit ; leur adresse e-mail seulement avec `includeEmails`                                                                                                                                                    |
| `list_invitations`        | Les invitations en attente, pour qui peut inviter ; les invitations au rôle de propriétaire, pour les propriétaires seuls                                                                                                                                                                            |
| `list_webhooks`           | Les points de terminaison de [webhook](/webhooks) de l’espace de travail, avec leur état et depuis quand leurs livraisons échouent, pour les propriétaires et administrateurs ; jamais leurs secrets de signature                                                                                    |
| `list_webhook_deliveries` | Les livraisons récentes d’un point de terminaison de webhook : le type de chaque événement, s’il a été livré, le dernier code de réponse du destinataire, les tentatives faites et la prochaine                                                                                                      |
| `list_approvals`          | Les publications qui attendent une [approbation](/review) : l’heure demandée pour chacune, qui a demandé et comment                                                                                                                                                                                  |
| `get_post_review`         | Une publication telle que chaque canal la recevra, ses commentaires, par les membres et par les personnes venues par un lien, et les approbations demandées avec ce qui a été décidé                                                                                                                 |
| `server_health`           | Si le serveur Peal tourne et joint sa base de données                                                                                                                                                                                                                                                |

Deux autres lisent [ce qu’un canal accepte](/api-overview#capabilities), pour qu’un client n’ait pas à connaître les règles de chaque plateforme. Ils ne changent rien, et peuvent interroger la plateforme du canal, hors de Peal (`openWorldHint`) :

| Outil                      | Ce qu’il répond                                                                                                                                                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `get_channel_capabilities` | Comment le texte d’un canal est compté et limité, les médias qu’il accepte, les options de sa plateforme champ par champ, ses recherches, si Peal lit les compteurs de ses publications, et ce que le compte lui-même restreint       |
| `run_channel_lookup`       | Une [recherche](/api-overview#lookups) d’un canal : les données du compte auxquelles ses options se rapportent, comme les catégories où une vidéo YouTube peut être classée ou les tableaux d’un compte Pinterest, une page à la fois |

Ces outils changent quelque chose. Chacun indique au client, par les annotations d’outils de MCP, s’il détruit ou écrase (`destructiveHint`), si l’appeler de nouveau ne change rien de plus (`idempotentHint`), et si son effet sort de Peal (`openWorldHint`), pour qu’un client puisse vous demander avant de l’appeler :

| Outil               | Ce qu’il fait                                                                                                                                                                                                                                                                                                                                                                     | Détruit ou écrase | Rappelé, ne change rien de plus | Hors de Peal |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- | ------------------------------- | ------------ |
| `create_draft`      | Enregistre un nouveau brouillon, avec les parties qui le suivent dans un [fil](/scheduling#threads) (`content.followUps`) et les [options des plateformes](/scheduling#options) de ses canaux LinkedIn, TikTok, YouTube, Pinterest et Google Business Profile. Il ne part à aucune heure tant qu’il n’est pas programmé, par vous dans l’application web ou avec `schedule_post`. | non               | non                             | non          |
| `update_draft`      | Remplace le texte, les médias et les canaux d’un brouillon par ceux donnés. Ses options restent sur les canaux qu’il garde, sauf si l’appel en donne d’autres.                                                                                                                                                                                                                    | oui               | oui                             | non          |
| `discard_draft`     | Supprime un brouillon pour de bon.                                                                                                                                                                                                                                                                                                                                                | oui               | oui                             | non          |
| `import_media`      | Récupère une image, une vidéo ou un document PDF à une adresse HTTPS publique et l’ajoute aux médias de l’espace de travail : en 90 secondes au plus, images jusqu’à 16 Mio, vidéos jusqu’à 1 Gio, documents jusqu’à 100 Mio. Il ne publie rien. Chaque appel ajoute un nouveau fichier.                                                                                          | non               | non                             | oui          |
| `schedule_post`     | Programme un brouillon pour un instant, dans un fuseau IANA, sur les canaux qu’il a ou sur ceux donnés. Il est d’abord vérifié contre la plateforme de chaque canal. Demande la publication.                                                                                                                                                                                      | non               | non                             | oui          |
| `publish_post`      | Publie maintenant un brouillon, ou une publication programmée pour plus tard, sur ses canaux : elle part en quelques secondes, et ne peut plus être arrêtée une fois lancée. Demande la publication.                                                                                                                                                                              | non               | non                             | oui          |
| `create_post`       | Crée une publication et l’envoie en un seul appel, maintenant ou à un instant. Demande la publication.                                                                                  | oui               | oui                             | non          |
| `repost_target`     | Publie de nouveau une publication, maintenant, sur un canal où elle a échoué ou n’est pas confirmée. Demande la publication.                                                                                                                                                                                                                                                      | non               | non                             | oui          |
| `confirm_target`    | Enregistre ce que vous avez trouvé sur la plateforme pour une publication non confirmée : publiée, ou non publiée, qui l’y met en échec. Demande la publication.                                                                                                                                                                                                                  | oui               | oui                             | non          |
| `invite_member`     | Envoie à quelqu’un une invitation à l’espace de travail, avec un rôle. Une invitation en attente à la même adresse est remplacée.                                                                                                                                                                                                                                                 | oui               | non                             | oui          |
| `revoke_invitation` | Révoque une invitation en attente : son lien ne fonctionne plus.                                                                                                                                                                                                                                                                                                                  | oui               | oui                             | non          |
| `create_webhook`    | Ajoute un point de terminaison de [webhook](/webhooks) : Peal envoie ensuite les événements auxquels il est abonné à son adresse, un serveur hors de Peal. Demande la publication.                                           | non               | non                             | oui          |
| `request_changes`   | Renvoie en brouillon une publication qui attend, avec un commentaire qui dit quoi changer. « Demande la publication » : il faut la permission de programmer et publier (`workspace:publish`), et un rôle qui programme des publications : propriétaire, administrateur ou éditeur. Ce qu’envoient `schedule_post`, `publish_post`, `create_post` et `repost_target` est public sur les plateformes, et Peal ne peut pas le reprendre une fois parti. Dans un espace de travail qui demande des [approbations](/review#policy), ce que ces outils envoient ou programment attend : la réponse porte l’état `awaitingApproval`, et la publication ne part qu’une fois approuvée par une personne. `approve_post` et `request_changes` demandent la publication avec un rôle qui approuve les publications, puisque approuver une publication, c’est la faire partir.

Avant d’être programmée, une publication est vérifiée contre la plateforme de chaque canal : longueur du texte, types, tailles et nombre de médias, options requises, et ce que le compte lui-même refuse. Si quelque chose ne va pas, rien n’est programmé, et le refus liste toutes les violations d’un coup, chacune avec son canal, et son champ ou son média ([Comment lire les refus](/agents#refusals)).

Les annotations sont des indications qu’un client peut vous montrer ; les vérifications de droits sont celles du serveur.

### Commentaires [#inbox-tools]

| Outil                    | Ce qu’il fait                                                                                                                                                         |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list_comment_threads`   | Les fils de la [boîte de réception](/inbox) qui ont des commentaires, ceux qui attendent une réponse en premier, avec des nombres et jamais le texte des commentaires |
| `get_comment_thread`     | Un fil entier : ses commentaires avec l’identifiant public et le nom de leurs auteurs, les réponses envoyées depuis Peal, et ce que son canal peut faire              |
| `reply_to_comment`       | Répond à un commentaire en public, au nom du compte du canal. Demande la publication                                                                                  |
| `confirm_comment_reply`  | Enregistre ce que vous avez trouvé sur la plateforme pour une réponse dont Peal n’a pas pu connaître l’issue. Demande la publication                                  |
| `withdraw_comment_reply` | Supprime une réponse envoyée de sa plateforme. Demande la publication                                                                                                 |
| `mark_comment_answered`  | Dit qu’un commentaire n’appelle pas de réponse, ou en attend de nouveau une. Demande la publication                                                                   |
| `moderate_comment`       | Masque, montre, aime, n’aime plus ou supprime un commentaire, quand sa plateforme le permet au compte. Demande la publication                                         |

Un commentaire est un texte écrit par quelqu’un d’extérieur à votre espace de travail, et peut être écrit pour orienter un assistant. Les outils disent à l’assistant de le traiter comme une donnée, et une réponse ne part que par `reply_to_comment`, pour lequel votre client vous demande votre accord comme pour tout ce qui atteint une plateforme. Une réponse dont l’issue n’est pas connue n’est jamais renvoyée par un outil : vous vérifiez sur la plateforme, puis vous confirmez.

### Ce qu’aucun outil ne donne [#account-data]

Aucun outil n’exporte vos données ni ne liste les applications qui agissent pour vous. Un client MCP transmet tout ce que ses outils répondent à un modèle d’IA, et votre export contient les adresses de vos sessions, vos invitations et tout ce que vous avez écrit : l’instance refuse les deux à tout client OAuth autre que la [ligne de commande](/cli#account), que vous connectez depuis votre propre terminal et qui les enregistre dans vos propres fichiers. Les paramètres du compte, dans l’application web, les montrent aussi.

## Limites [#limits]

- Une instance Peal ne sert les clients MCP que si son adresse est en HTTPS, ou sur `localhost` pour le développement. Ailleurs, le point d’accès refuse toutes les requêtes.
- Le point d’accès refuse les requêtes envoyées depuis des pages web (avec un en-tête `Origin`) : connectez un client qui tourne sur votre ordinateur ou sur un serveur.
- Les **Paramètres du compte**, dans l’application web, listent les clients que vous avez autorisés et les déconnectent ; `peal account apps` les liste depuis la [ligne de commande](/cli#account). Quitter l’espace de travail arrête tous les clients qui y agissent.
