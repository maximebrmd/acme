Un espace de travail qui publie tous les jours se répète : les mêmes canaux, la même formule de fin, les mêmes noms de campagne. Peal les garde pour lui :

- les étiquettes classent les publications ;
- les signatures les terminent ;
- les groupes de canaux les démarrent ;
- les options par défaut d’un canal remplissent ce qu’il reçoit toujours.

Tout cela appartient à l’espace de travail : chaque membre les lit, et ceux qui peuvent modifier les publications les modifient.

## Qui peut faire quoi [#roles]

| Rôle           | Étiquettes, signatures, groupes de canaux et options par défaut |
| -------------- | --------------------------------------------------------------- |
| Propriétaire   | Lire et modifier                                                |
| Administrateur | Lire et modifier                                                |
| Éditeur        | Lire et modifier                                                |
| Contributeur   | Lire et modifier                                                |
| Lecteur        | Lire                                                            |

Les modifier demande le droit de modifier les publications. Par l’API, c’est `post:update`, et les lire `post:read`.

## Étiquettes [#tags]

Une étiquette est un nom et une couleur : une campagne, un client, un thème. Une publication a jusqu’à 10 étiquettes, et un espace de travail en garde jusqu’à 100.

<Steps>
  <Step title="Ajoutez une étiquette">
    Dans les **Paramètres** d’un espace de travail, choisissez **Étiquettes**
    pour en ajouter une. Donnez-lui un nom de 40 caractères au plus, qu’aucune
    autre étiquette de l’espace de travail ne porte quelle que soit sa casse, et
    choisissez sa couleur parmi les neuf de la palette.
  </Step>
  <Step title="Étiquetez une publication">
    Dans l’éditeur, sous **Étiquettes**, cochez celles de la publication, ou
    ajoutez-en une. Une publication déjà partie s’étiquette sur sa page : les
    étiquettes ne disent rien aux plateformes, elles changent donc quel que soit
    l’état de la publication.
  </Step>
</Steps>

Renommez une étiquette, donnez-lui une autre couleur ou supprimez-la dans **Paramètres**, **Étiquettes**. Supprimer une étiquette la retire de ses publications, qui gardent tout le reste.

Les étiquettes se voient sur le calendrier, par un point de la couleur de chacune sur la publication, et dans la liste des brouillons. Au-dessus du calendrier :

- **Étiquettes** ne montre que les publications classées sous l’une des étiquettes cochées ;
- **Canaux** ne montre que celles qui partent sur l’un des canaux cochés ;
- avec les deux, une publication doit correspondre aux deux.

Le calendrier dit combien de publications les filtres masquent, et un bouton les efface.

## Signatures [#signatures]

Une signature est un bloc de texte par lequel un espace de travail termine ses publications : une formule de fin, une mention, une série de hashtags. Un espace de travail en garde jusqu’à 50, de 2 000 caractères au plus chacune.

Dans les **Paramètres**, choisissez **Signatures** pour en ajouter une. Donnez-lui un nom, son texte, et dites à quoi elle sert : tout l’espace de travail, une plateforme, ou un canal. Utilisez-la ensuite de l’une de ces deux façons :

| Comment        | Ce qui se passe                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Dans l’éditeur | **Signature** liste les signatures de l’espace de travail. En choisir une la place sous le texte pour tous les canaux, ou sous le texte propre à un canal, après une ligne vide.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Par défaut     | Cochez **Ajouter par défaut aux nouvelles publications**. Une nouvelle publication propose alors, cochée, l’option d’ajouter la signature par défaut à l’enregistrement : quand vous l’enregistrez, la signature par défaut de l’espace de travail se place sous son texte, et l’éditeur affiche le texte tel qu’enregistré. Celle d’une plateforme ou d’un canal remplace celle de l’espace de travail à cet endroit : la publication reçoit un texte propre à ce canal, signé avec elle. Décochez l’option pour une publication qui doit partir sans. Il y a une signature par défaut pour l’espace de travail, une par plateforme et une par canal. |

Une fois ajoutée, une signature est du texte de la publication comme le reste :

- elle compte dans la limite de chaque plateforme quand la publication est programmée, si bien qu’une publication qui passait sans elle peut être refusée avec elle ;
- elle n’est jamais ajoutée sous un texte qui se termine déjà par elle : enregistrer deux fois, ou l’ajouter à la main à une publication qui l’a déjà, n’ajoute rien ;
- elle se place sous la dernière partie d’une publication en plusieurs parties (un [fil](/guides/posts#threads)), les parties qui la précèdent restant telles quelles ;
- modifier ou supprimer la signature plus tard laisse telles quelles les publications qui la portent.

Les publications créées par l’API, MCP ou la ligne de commande ne prennent une signature que si elles la demandent : rien n’est ajouté à un texte sans qu’on le demande.

## Groupes de canaux [#sets]

Un groupe de canaux est une sélection de canaux de l’espace de travail gardée sous un nom, comme « Lancement » ou « Client A », avec les [options](/guides/posts#options) que les publications prennent sur certains d’entre eux. Un groupe compte jusqu’à 50 canaux, et un espace de travail garde jusqu’à 50 groupes.

- Pour en enregistrer un, cochez les canaux d’une publication, remplissez leurs options, puis choisissez **Enregistrer la sélection comme groupe**.
- Pour en utiliser un, choisissez **Groupe de canaux** au démarrage d’une publication : cela coche ses canaux et remplit les options qu’il garde.
- **Paramètres**, **Groupes de canaux** liste les groupes et permet d’en renommer un, de changer ses canaux ou de le supprimer.

Un groupe garde les canaux qu’on lui a donnés. Quand l’un d’eux est déconnecté par la suite :

- le groupe le liste toujours, signalé comme n’étant plus connecté ;
- une publication qui utilise le groupe part sur ses autres canaux, et Peal dit quel canal a été laissé de côté, dans l’éditeur et dans la réponse de l’API (`warnings`), jamais en silence ;
- une publication dont le groupe n’a plus aucun canal connecté, et qui ne nomme aucun autre canal, est refusée ;
- enregistrer de nouveau le groupe en retire le canal déconnecté.

## Options par défaut d’un canal [#defaults]

Certains canaux prennent toujours les mêmes [options](/guides/posts#options) : le même tableau Pinterest, la même audience YouTube. Les options par défaut d’un canal sont celles qu’une nouvelle publication prend sur ce canal quand elle n’en donne aucune.

- Elles peuvent être incomplètes. Une publication qui les prend est vérifiée à sa programmation exactement comme une publication qui les aurait écrites elle-même : elles ne contournent jamais les règles d’une plateforme.
- Les options sont prises dans cet ordre : celles de la publication, puis celles d’un groupe de canaux, puis celles par défaut du canal.
- Seule une nouvelle publication les prend : un brouillon que vous modifiez garde ce que vous lui donnez.

Définissez-les par l’API, MCP ou la ligne de commande :

```sh
peal channels defaults set 0190f3a0-0000-7000-8000-00000000c004 \
  --options '{"platform":"youtube","privacy":"unlisted"}'
```

## Dupliquer une publication [#duplicate]

Sur la page d’une publication, ou depuis son entrée dans le calendrier, **Dupliquer** crée un nouveau brouillon qui dit ce que dit la publication : son texte, ses médias, ses canaux avec leur texte et leurs options propres, et ses étiquettes. La copie n’a pas d’heure, et vous en êtes l’auteur. Ce que l’espace de travail n’a plus est laissé de côté : un canal déconnecté depuis, un média supprimé depuis.

Pour envoyer la même publication à plusieurs moments, dupliquez-la et programmez chaque copie.

## Par l’API [#api]

Tout ce qui précède se trouve dans l’[API HTTP](/developers), sous `/api/workspaces/{workspaceId}`, dans les [outils MCP](/developers/mcp/tools#tools) et dans la [ligne de commande](/developers/cli).

| Quoi                                     | Points d’accès                                                                                    |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Étiquettes                               | `GET`, `POST …/tags`, `PATCH`, `DELETE …/tags/{tagId}`, `PUT …/posts/{postId}/tags`               |
| Signatures                               | `GET`, `POST …/signatures`, `PUT`, `DELETE …/signatures/{signatureId}`                            |
| Groupes de canaux                        | `GET`, `POST …/channel-sets`, `PUT`, `DELETE …/channel-sets/{channelSetId}`                       |
| Files d’attente                          | `GET`, `POST …/queues`, `GET`, `PUT`, `DELETE …/queues/{queueId}`, `GET …/queues/{queueId}/slots` |
| Options par défaut                       | `GET`, `PUT`, `DELETE …/channels/{channelId}/default-options`                                     |
| Dupliquer                                | `POST …/posts/{postId}/duplicate`                                                                 |
| Publications classées sous une étiquette | `GET …/posts/search?tagId=…`                                                                      |

Une publication nomme ce qu’elle prend à sa création. Celle-ci part sur les canaux du groupe « Launch », prend la signature par défaut de chaque canal, et est classée sous une étiquette :

```sh
curl -X POST "https://peal.example/api/workspaces/$WORKSPACE_ID/posts/send" \
  -H "Authorization: Bearer $PEAL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "channelIds": [],
    "channelSets": ["Launch"],
    "content": { "text": "We are live.", "media": [], "overrides": [] },
    "defaultSignatures": true,
    "tagIds": ["0190f3a0-0000-7000-8000-00000000a001"],
    "when": { "_tag": "now" }
  }'
```

- `channelSets` nomme des groupes par leur identifiant ou par leur nom, quelle que soit la casse ; `channelIds` peut alors être vide. La publication part sur les canaux connectés des groupes et sur les canaux qu’elle liste.
- `defaultSignatures` place sous son texte la signature par défaut de chaque canal, et `signatureId` une signature sur tous les canaux.
- `tagIds` classe la publication. Mettre à jour un brouillon sans `tagIds` garde ses étiquettes.

Quand un groupe liste un canal qui n’est plus connecté, la publication est créée sans lui et la réponse le dit :

```json
{
  "id": "0190f3a0-0000-7000-8000-00000000d010",
  "status": "scheduled",
  "warnings": [
    {
      "_tag": "channelsDropped",
      "channelSetId": "0190f3a0-0000-7000-8000-00000000b001",
      "channelSetName": "Launch",
      "channelIds": ["0190f3a0-0000-7000-8000-00000000c001"]
    }
  ]
}
```

`POST …/posts/validate` prend les mêmes champs et répond les mêmes `warnings` : un script le sait donc avant d’envoyer. Dans un [import CSV](/developers/posting/bulk#import), la colonne `channels` prend l’identifiant d’un groupe, ou son nom quand celui-ci ne contient ni espace, ni virgule, ni point-virgule.

Une [clé de partenaire](/developers/embedding) utilise les groupes, signatures et étiquettes de chaque espace de travail que son partenaire possède, comme le fait la clé propre à cet espace.
