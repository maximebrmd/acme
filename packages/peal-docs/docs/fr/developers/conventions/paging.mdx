## Pagination [#paging]

Les listes qui peuvent grandir sans fin se lisent page par page, les plus récents d’abord :

1. Envoyez `limit`, la taille d’une page, dans la requête.
2. La réponse est un objet qui porte les éléments de la page (`items`) et un `nextCursor`.
3. Passez `nextCursor` en `cursor` pour lire la page suivante, et arrêtez-vous quand il vaut `null`.

Un curseur est une chaîne opaque, valable pour la liste dont il vient, avec les mêmes filtres : ailleurs, il répond 400 `bad_request`.

| Liste                                    | Une page contient | Au plus |
| ---------------------------------------- | ----------------- | ------- |
| `GET …/posts/drafts`                     | 20                | 50      |
| `GET …/media`                            | 30                | 100     |
| `GET …/webhooks/{endpointId}/deliveries` | 30                | 100     |
| `GET …/activity`                         | 30                | 100     |
| `GET /api/me/notices`                    | 20                | 100     |

Les chemins qui commencent par `…` sont sous `/api/workspaces/{workspaceId}`.

La première page :

<CodeGroup>

```bash curl
curl "https://api.example.com/api/workspaces/$WORKSPACE_ID/activity?limit=2" \
  -H "Authorization: Bearer $PEAL_API_KEY"
```

```ts TypeScript
const page = await peal.activity.list({ workspaceId, limit: "2" });
```

La page suivante, avec le `nextCursor` ci-dessus, et une boucle qui les lit toutes (les SDK n’ont pas d’aide qui le fasse pour vous) :

<CodeGroup>

```bash curl
curl "https://api.example.com/api/workspaces/$WORKSPACE_ID/activity?limit=2&cursor=MDE5YTdiMzAtNmYxOC03YTk1LTlkMDctMWMyYjNhNGQ1ZTZm" \
  -H "Authorization: Bearer $PEAL_API_KEY"
```

```ts TypeScript
let cursor: string | undefined;

do {
  const page = await peal.activity.list({ workspaceId, limit: "100", cursor });

  for (const entry of page.items) {
    console.log(entry.operation, entry.status);
  }

  cursor = page.nextCursor ?? undefined;
} while (cursor !== undefined);
```

</CodeGroup>

### Les listes qui prennent une plage [#ranges]

Deux listes prennent plutôt une plage, et répondent d’un coup tout ce qu’elle contient :

| Liste                                            | Ce qu’elle répond                                                              | Plage                       | Sinon                |
| ------------------------------------------------ | ------------------------------------------------------------------------------ | --------------------------- | -------------------- |
| `GET …/posts?from=…&to=…`                        | Les publications programmées entre deux instants, `from` compris et `to` exclu | Séparés de 62 jours au plus | `invalid_time_range` |
| `GET …/analytics/summary?from=…&to=…&timeZone=…` | Le résumé des publications parties sur une plage de jours, bornes comprises    | 366 jours au plus           | `invalid_date_range` |

Les listes qu’un espace de travail garde courtes répondent en entier, sous forme de tableau : ses canaux, ses membres, ses invitations en attente, ses clés d’API et ses points de terminaison de webhook.
