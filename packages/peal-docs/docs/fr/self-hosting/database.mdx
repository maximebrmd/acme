Peal garde ses données et ses tâches durables dans une seule base Postgres, que nomme `DATABASE_URL`. Le serveur tient lui-même son schéma à jour.

## Base de données [#database]

Au démarrage, le serveur applique les migrations de la base de données qu’il n’a pas encore appliquées, un serveur à la fois, et n’écoute qu’une fois qu’elles sont terminées. Chaque partie de Peal range ses tables dans un schéma Postgres à elle (`assistant`, `auth`, `channels`, `legal`, `media`, `notifications`, `publishing`) ; les tables de l’exécuteur de tâches (`cluster_*`) sont dans `public`.

Le serveur exécute ses tâches durables depuis la même base, et les garde par des verrous consultatifs de session tant qu’il tourne.

<Callout type="warning" title="Pas de pooler en mode transaction">
  Connectez le serveur à Postgres directement, ou par un pooler en mode session.
  Un pooler en mode transaction donne une autre connexion à chaque requête, ce
  qui perd ces verrous.
</Callout>

| Réglage                  | Par défaut | Ce qu’il fait                                                                                                                              |
| ------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `DATABASE_URL`           | aucune     | La base Postgres. Chaque processus serveur y ouvre jusqu’à 10 connexions.                                                                  |
| `AUTH_DB_POOL_MAX`       | `5`        | Les connexions que chaque processus serveur ouvre en plus, pour la connexion des utilisateurs.                                             |
| `PEAL_CLUSTER_RETENTION` | `30 days`  | Un nettoyage quotidien supprime les traces des tâches terminées depuis plus longtemps. Les tâches encore en attente sont toujours gardées. |

[Variables d’environnement](/self-hosting/environment-variables#core) détaille chacun, `AUTH_DB_POOL_MAX` sous [Connexion](/self-hosting/environment-variables#sign-in).
