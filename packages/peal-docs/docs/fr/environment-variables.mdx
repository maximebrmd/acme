Le serveur, l’application web et la ligne de commande lisent de simples variables d’environnement : ils tournent sur n’importe quel hôte. Cette page liste chacune de celles qu’ils lisent. Les valeurs indiquées sont des exemples.

Le serveur tourne en mode production quand `NODE_ENV` vaut `production`, comme son image le définit. Les réglages marqués « obligatoire en production » n’y ont pas de valeur par défaut, et le serveur refuse de démarrer sans eux. Ailleurs, ils valent par défaut l’environnement de développement : un serveur lancé depuis les sources n’a besoin que de `DATABASE_URL`.

## Serveur [#server]

### Essentiel [#core]

| Variable                 | Par défaut                                          | Rôle                                                                                                                                                                                                                                                                                                                          |
| ------------------------ | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`           | aucune : obligatoire                                | La base de données Postgres, comme `postgres://peal:secret@postgres:5432/peal`. Connectez-vous directement ou par un pooler en mode session, jamais en mode transaction.                                                                                                                                                      |
| `PUBLIC_URL`             | obligatoire en production ; `http://localhost:3001` | L’adresse où l’on ouvre Peal : l’application web, comme `https://peal.example.com`. Les liens des e-mails, la connexion, les retours des plateformes et l’adresse du point d’accès MCP sont construits depuis son origine. Les clients MCP ne se connectent que si elle est en HTTPS, ou sur un hôte local comme `localhost`. |
| `NODE_ENV`               | `development`                                       | `production` active le mode production : réglages obligatoires, limites de débit de la connexion, et aucune valeur par défaut de développement.                                                                                                                                                                               |
| `PORT`                   | `3000`                                              | Le port d’écoute du serveur HTTP.                                                                                                                                                                                                                                                                                             |
| `HOSTNAME`               | `peal-server`                                       | Le nom du serveur parmi les exécuteurs de tâches enregistrés dans la base. Chaque processus serveur a besoin du sien ; Docker y met l’identifiant du conteneur.                                                                                                                                                               |
| `PEAL_CLUSTER_RETENTION` | `30 days`                                           | Combien de temps les traces des tâches terminées, comme celle d’une publication diffusée, sont gardées avant qu’un nettoyage quotidien les supprime, en durée anglaise comme `7 days`. Les tâches encore en attente sont toujours gardées.                                                                                    |

### Connexion [#sign-in]

| Variable                          | Par défaut                                             | Rôle                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BETTER_AUTH_SECRET`              | obligatoire en production ; un secret de développement | Le secret qui signe les sessions et chiffre ce que la connexion stocke : au moins 32 caractères aléatoires, comme `openssl rand -base64 32`. Qui le connaît peut se connecter à la place de n’importe qui. Gardez-le secret.                                                                                                                                                                |
| `BETTER_AUTH_SECRETS`             | non définie                                            | Pour changer de secret : des entrées `version:secret` séparées par des virgules, la plus récente en tête, comme `2:<nouveau>,1:<ancien>`. Lue par Better Auth lui-même : quand elle est définie, le secret de la première entrée sert, et les autres, avec `BETTER_AUTH_SECRET`, déchiffrent encore ce que les anciens secrets ont chiffré.                                                 |
| `AUTH_IP_HEADERS`                 | obligatoire en production ; `x-forwarded-for`          | Les en-têtes, séparés par des virgules, qui portent l’adresse du client, que les limites de débit de la connexion et les signalements d’erreurs de l’application web comptent. Ne nommez qu’un en-tête que votre frontal définit en remplaçant celui du client : `cf-connecting-ip` derrière Cloudflare, `x-forwarded-for` derrière Caddy. Voir [Devant Peal](/self-hosting#reverse-proxy). |
| `AUTH_TRUSTED_PROXIES`            | aucune                                                 | Les adresses ou plages CIDR, séparées par des virgules, des proxies qui ajoutent à `X-Forwarded-For`. L’adresse du client est alors lue depuis la droite, après eux.                                                                                                                                                                                                                        |
| `TRUSTED_ORIGINS`                 | aucune                                                 | Les origines, en plus de `PUBLIC_URL` et séparées par des virgules, autorisées à envoyer des requêtes connectées qui changent quelque chose. `media-cors` les laisse aussi importer des médias.                                                                                                                                                                                             |
| `AUTH_REQUIRE_EMAIL_VERIFICATION` | `true`                                                 | `false` permet de se connecter avant d’avoir confirmé son adresse e-mail.                                                                                                                                                                                                                                                                                                                   |
| `AUTH_DB_POOL_MAX`                | `5`                                                    | Combien de connexions à la base ouvre la connexion des utilisateurs, en plus des 10 du serveur.                                                                                                                                                                                                                                                                                             |
| `MCP_DYNAMIC_REGISTRATION`        | `false`                                                | `true` laisse les clients MCP s’enregistrer eux-mêmes, ce dont la plupart ont besoin avant de se connecter. N’importe qui peut alors enregistrer un client sous n’importe quel nom ; la page de consentement indique que Peal ne l’a pas vérifié.                                                                                                                                           |

Better Auth lit aussi `BETTER_AUTH_TRUSTED_ORIGINS`, qui ajoute des origines comme `TRUSTED_ORIGINS`. Préférez `TRUSTED_ORIGINS`, que `media-cors` lit aussi.

### E-mail [#email]

| Variable         | Par défaut                                                                 | Rôle                                                                                                                                                                                                                               |
| ---------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MAIL_FROM`      | obligatoire en production ; `Peal <noreply@peal.localhost>`                | L’expéditeur, comme `Peal <noreply@example.com>` ou une adresse depuis laquelle votre service de messagerie peut envoyer.                                                                                                          |
| `RESEND_API_KEY` | non définie                                                                | Envoie les e-mails par l’API de Resend. Gardez-la secrète.                                                                                                                                                                         |
| `SMTP_URL`       | obligatoire en production sans `RESEND_API_KEY` ; `smtp://127.0.0.1:11025` | Le serveur SMTP, comme `smtp://utilisateur:motdepasse@mail.example.com:587`, ou `smtps://` pour du TLS dès le premier octet. Sert quand `RESEND_API_KEY` n’est pas définie. Gardez-la secrète quand elle contient un mot de passe. |

### Canaux [#channels]

| Variable                 | Par défaut  | Rôle                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------ | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PEAL_TOKEN_KEYS`        | non définie | Les clés qui chiffrent les jetons des canaux connectés : des entrées `idDeClé:clé` séparées par des virgules, comme `k2:<clé>,k1:<clé>`, chaque clé faisant 32 octets aléatoires en base64 (`openssl rand -base64 32`). La première clé chiffre et toutes les clés listées déchiffrent. Non définie ou vide, le serveur démarre, et la connexion d’un canal échoue. Une valeur mal formée arrête le serveur au démarrage. Gardez-en une copie : sans les clés, chaque canal doit être reconnecté. |
| `BLUESKY_CLIENT_KEYS`    | non définie | Les clés du client Bluesky de Peal, créées par `bun nx run peal-server:bluesky-key` : des entrées `idDeClé:clé` séparées par des virgules, la première signant. Elles demandent `PUBLIC_URL` en HTTPS sans port. Sans elles, seul un serveur sur `localhost` hors production connecte Bluesky, avec le client de développement. Une valeur mal formée arrête le serveur au démarrage.                                                                                                             |
| `LINKEDIN_CLIENT_ID`     | non définie | L’identifiant client de l’application enregistrée sur LinkedIn, avec les produits OpenID Connect et Share on LinkedIn (voir [LinkedIn](/self-hosting#linkedin)). Avec `LINKEDIN_CLIENT_SECRET`, les membres peuvent connecter LinkedIn ; sans les deux, LinkedIn n’est pas proposé. L’un sans l’autre arrête le serveur au démarrage.                                                                                                                                                             |
| `LINKEDIN_CLIENT_SECRET` | non définie | Le secret client principal de l’application. Gardez-le secret.                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `LINKEDIN_API_VERSION`   | `202610`    | La version de l’API de LinkedIn que Peal appelle, au format `AAAAMM`. LinkedIn retire une version un an après sa sortie : indiquez-en une plus récente pour devancer une version de Peal. Une valeur qui n’est pas un mois arrête le serveur au démarrage.                                                                                                                                                                                                                                        |
| `META_APP_ID`            | non définie | L’identifiant de l’application Meta, pris dans son tableau de bord, qui connecte les Pages Facebook et les comptes professionnels Instagram via Facebook Login. À définir avec `META_APP_SECRET`, ou aucune des deux : les Pages Facebook et Instagram ne sont proposées que si les deux le sont. L’une sans l’autre arrête le serveur au démarrage.                                                                                                                                              |
| `META_APP_SECRET`        | non définie | Le secret de cette application. Il signe aussi chaque appel à Facebook et Instagram (`appsecret_proof`) et vérifie les demandes de suppression de données de Meta. Gardez-le secret.                                                                                                                                                                                                                                                                                                              |
| `THREADS_APP_ID`         | non définie | L’identifiant Threads de la même application, que son cas d’usage Threads donne à part du principal. À définir avec `THREADS_APP_SECRET`, ou aucune des deux : Threads n’est proposé que si les deux le sont.                                                                                                                                                                                                                                                                                     |
| `THREADS_APP_SECRET`     | non définie | Le secret Threads, qui vérifie aussi les demandes de suppression de données de Threads. Gardez-le secret.                                                                                                                                                                                                                                                                                                                                                                                         |
| `TIKTOK_CLIENT_KEY`      | non définie | La clé client de l’application enregistrée sur TikTok for Developers, avec Login Kit, la Content Posting API en Direct Post et la Display API (voyez [TikTok](/self-hosting#tiktok)). Avec `TIKTOK_CLIENT_SECRET`, les membres peuvent connecter TikTok ; sans les deux, TikTok n’est pas proposé. L’une sans l’autre arrête le serveur au démarrage.                                                                                                                                             |
| `TIKTOK_CLIENT_SECRET`   | non définie | Le secret client de l’application. Gardez-le secret.                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `X_CLIENT_ID`            | non définie | L’identifiant client OAuth 2.0 de l’application enregistrée sur X, comme application web avec les permissions de lecture et d’écriture (voir [X](/self-hosting#x)). Avec `X_CLIENT_SECRET`, les membres peuvent connecter X ; sans les deux, X n’est pas proposé. L’un sans l’autre arrête le serveur au démarrage.                                                                                                                                                                               |
| `X_CLIENT_SECRET`        | non définie | Le secret client OAuth 2.0 de l’application. Gardez-le secret.                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `YOUTUBE_CLIENT_ID`      | non définie | L’identifiant du client OAuth d’application Web créé dans un projet Google Cloud où la YouTube Data API v3 est activée (voir [YouTube](/self-hosting#youtube)). Avec `YOUTUBE_CLIENT_SECRET`, les membres peuvent connecter des chaînes YouTube ; sans les deux, YouTube n’est pas proposé. L’un sans l’autre arrête le serveur au démarrage.                                                                                                                                                     |
| `YOUTUBE_CLIENT_SECRET`  | non définie | Le secret de ce client. Gardez-le secret.                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `YOUTUBE_DAILY_UPLOADS`  | `100`       | Combien de vidéos le serveur met en ligne sur YouTube par jour, sur toutes les chaînes, en unités du quota Video Uploads du projet Google, où une mise en ligne en coûte une ; les jours commencent à minuit, heure du Pacifique. Au-delà, une mise en ligne attend le jour suivant. Relevez-le quand Google accorde plus au projet. 0 ne met rien en ligne ; une valeur qui n’est pas un nombre entier arrête le serveur au démarrage.                                                           |

### Médias [#media]

| Variable                     | Par défaut                                             | Rôle                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PEAL_S3_ENDPOINT`           | obligatoire en production ; `http://127.0.0.1:18333`   | L’URL de l’API S3 qui stocke les médias, comme `https://<compte>.r2.cloudflarestorage.com`.                                                                                                                                                                                                                                                                                                                                                  |
| `PEAL_S3_BUCKET`             | obligatoire en production ; `peal-media`               | Le bucket où vont les médias.                                                                                                                                                                                                                                                                                                                                                                                                                |
| `PEAL_S3_ACCESS_KEY_ID`      | obligatoire en production ; la clé de développement    | La clé d’accès du stockage. Gardez-la secrète.                                                                                                                                                                                                                                                                                                                                                                                               |
| `PEAL_S3_SECRET_ACCESS_KEY`  | obligatoire en production ; le secret de développement | Le secret de cette clé. Gardez-le secret.                                                                                                                                                                                                                                                                                                                                                                                                    |
| `PEAL_S3_REGION`             | `auto`                                                 | La région pour laquelle les requêtes sont signées, comme `eu-west-1`. `auto` convient à Cloudflare R2.                                                                                                                                                                                                                                                                                                                                       |
| `PEAL_S3_FORCE_PATH_STYLE`   | `false` en production ; `true` sinon                   | `true` met le bucket dans le chemin de l’URL plutôt que dans son nom d’hôte, comme SeaweedFS le demande.                                                                                                                                                                                                                                                                                                                                     |
| `PEAL_S3_KEY_PREFIX`         | aucune                                                 | Un dossier sous lequel va chaque clé, comme `staging/`, pour que des instances partagent un bucket. Il finit par `/`.                                                                                                                                                                                                                                                                                                                        |
| `PEAL_MEDIA_PUBLIC_BASE_URL` | non définie                                            | L’adresse où le bucket est servi publiquement, s’il l’est, comme `https://media.example.com`. Non définie, les pages lisent les médias par des liens signés de courte durée.                                                                                                                                                                                                                                                                 |
| `TIKTOK_MEDIA_URL_PREFIX`    | non définie                                            | Le préfixe d’URL, ou `https://` et un domaine suivis d’un `/`, que vous avez vérifié pour l’application TikTok et sous lequel `PEAL_MEDIA_PUBLIC_BASE_URL` sert le stockage, comme `https://media.example.com/`. Avec lui, TikTok va chercher vidéos et photos dans le stockage ; sans lui, les vidéos partent en morceaux et les publications TikTok avec des photos sont refusées. Tout sauf une URL HTTPS arrête le serveur au démarrage. |
| `PEAL_FFPROBE_PATH`          | `ffprobe`                                              | Le programme ffprobe qui lit les dimensions, la durée et le codec d’une vidéo. L’image du serveur en contient un, à `/usr/local/bin/ffprobe`. Sans lui, les vidéos restent importées et ne sont pas lues.                                                                                                                                                                                                                                    |

### Assistant de rédaction [#ai]

| Variable                 | Par défaut                              | Rôle                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------ | --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PEAL_AI_PROVIDER`       | non définie : l’assistant est désactivé | `anthropic` pour l’API d’Anthropic, ou `openai-compatible` pour n’importe quel point d’accès qui sert `/chat/completions`, comme un serveur de modèles que vous faites tourner. Non définie ou vide, l’application web masque l’assistant et ses points d’accès répondent `AssistantUnavailable`. Toute autre valeur arrête le serveur au démarrage. |
| `PEAL_AI_API_KEY`        | non définie                             | La clé du fournisseur. Obligatoire avec `anthropic` ; avec `openai-compatible`, seulement pour un point d’accès qui en demande une. Gardez-la secrète.                                                                                                                                                                                               |
| `PEAL_AI_MODEL`          | `claude-opus-5-5` avec `anthropic`      | Le modèle qu’interroge l’assistant. Obligatoire avec `openai-compatible`.                                                                                                                                                                                                                                                                            |
| `PEAL_AI_BASE_URL`       | l’API d’Anthropic                       | L’URL de base de l’API, que suit `/chat/completions`, comme `http://127.0.0.1:8000/v1`. Obligatoire avec `openai-compatible` ; avec `anthropic`, seulement pour passer par un proxy. Le serveur l’appelle directement : elle peut se trouver sur un réseau privé.                                                                                    |
| `PEAL_AI_DAILY_REQUESTS` | `100`                                   | Combien de demandes chaque espace de travail peut envoyer à l’assistant par jour UTC, sur une instance qui ne facture pas ; avec la facturation, chaque abonnement fixe la sienne. `0` n’en laisse passer aucune. Une valeur négative ou mal formée arrête le serveur au démarrage.                                                                  |

Un fournisseur nommé sans les réglages qu’il demande arrête le serveur au démarrage, et l’erreur nomme la variable manquante. [Assistant de rédaction](/self-hosting#ai) explique le reste.

### Facturation [#billing]

| Variable                   | Par défaut                       | Rôle                                                                                                                                                                                                                  |
| -------------------------- | -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `STRIPE_SECRET_KEY`        | non définie : pas de facturation | La clé d’API Stripe qui facture les espaces de travail, comme `sk_live_…`. Non définie ou vide, il n’y a pas d’abonnement et rien n’est limité. Gardez-la secrète.                                                    |
| `STRIPE_WEBHOOK_SECRET`    | obligatoire avec une clé         | Le secret de signature du webhook qui envoie à `PUBLIC_URL/api/auth/stripe/webhook` les événements `customer.subscription.*`, comme `whsec_…`. Définie sans clé, elle arrête le serveur. Gardez-la secrète.           |
| `STRIPE_LOOKUP_KEY_PREFIX` | `peal`                           | Le début des clés de recherche des prix Stripe des abonnements : `<prefix>_<plan>_monthly` et `<prefix>_<plan>_yearly`. Lettres minuscules, chiffres et tirets bas ; une autre valeur arrête le serveur au démarrage. |
| `STRIPE_AUTOMATIC_TAX`     | `false`                          | `true` fait calculer la taxe par Stripe Tax au paiement, comme la TVA européenne, d’après l’adresse et le numéro de TVA du client, que le paiement demande alors. Activez d’abord Stripe Tax dans le compte Stripe.   |
| `STRIPE_API_URL`           | l’API de Stripe                  | Une autre adresse pour l’API de Stripe, comme `http://127.0.0.1:12111` pour stripe-mock dans les tests.                                                                                                               |

[Facturation](/self-hosting#billing) explique les abonnements et ce qu’ils limitent.

### Captcha [#captcha]

| Variable               | Par défaut                    | Rôle                                                                                                                                                                                                                  |
| ---------------------- | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TURNSTILE_SITE_KEY`   | non définie : pas de captcha  | La clé de site d’un widget Cloudflare Turnstile, que montrent les formulaires d’inscription et de réinitialisation du mot de passe. Définissez-la avec `TURNSTILE_SECRET_KEY` : l’une sans l’autre arrête le serveur. |
| `TURNSTILE_SECRET_KEY` | non définie : pas de captcha  | La clé secrète du widget, avec laquelle le serveur vérifie les jetons. Gardez-la secrète.                                                                                                                             |

### Télémétrie [#telemetry]

| Variable                      | Par défaut    | Rôle                                                                                                                                                                 |
| ----------------------------- | ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | non définie   | L’adresse OTLP/HTTP du collecteur OpenTelemetry qui reçoit les journaux, métriques et traces, comme `http://otel-collector:4318`. Non définie, rien n’est exporté.   |
| `OTEL_SERVICE_NAME`           | `peal-server` | Le nom de service sous lequel la télémétrie est envoyée.                                                                                                             |
| `OTEL_TRACES_EXPORTER`        | `otlp`        | `none` arrête l’export des traces une fois un point d’accès défini. `OTEL_METRICS_EXPORTER` et `OTEL_LOGS_EXPORTER` font de même pour les métriques et les journaux. |

Le serveur exporte la télémétrie en JSON sur HTTP : faites pointer le point d’accès vers le port OTLP/HTTP du collecteur, 4318 par défaut, et non vers son port gRPC. Il lit aussi ces variables OpenTelemetry, et aucune autre (`OTEL_EXPORTER_OTLP_PROTOCOL` comprise) :

- `OTEL_EXPORTER_OTLP_HEADERS`, `OTEL_EXPORTER_OTLP_COMPRESSION` et `OTEL_EXPORTER_OTLP_TIMEOUT`, ainsi que leurs variantes par signal et celles du point d’accès, comme `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` ;
- `OTEL_RESOURCE_ATTRIBUTES` et `OTEL_SERVICE_VERSION` ;
- `OTEL_SDK_DISABLED` ;
- les réglages de regroupement `OTEL_BSP_*` pour les traces et `OTEL_BLRP_*` pour les journaux ;
- `OTEL_METRIC_EXPORT_INTERVAL`, `OTEL_METRIC_EXPORT_TIMEOUT` et `OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE`.

### Exécuteur de tâches [#job-runner]

La bibliothèque qui exécute les tâches de Peal lit aussi ses propres réglages dans l’environnement, sous ces noms : `SHARDS_PER_GROUP`, `SHARD_GROUPS`, `AVAILABLE_SHARD_GROUPS`, `RUNNER_SHARD_WEIGHT`, `SHARD_LOCK_REFRESH_INTERVAL`, `SHARD_LOCK_EXPIRATION`, `SHARD_LOCK_DISABLE_ADVISORY`, `PREEMPTIVE_SHUTDOWN`, `ENTITY_MAILBOX_CAPACITY`, `ENTITY_MAILBOX_METRICS`, `MAX_RESIDENT_ENTITIES`, `UNPROCESSED_MESSAGE_BATCH_SIZE`, `ENTITY_MAX_IDLE_TIME`, `ENTITY_REGISTRATION_TIMEOUT`, `ENTITY_REPLY_POLL_INTERVAL`, `SEND_RETRY_INTERVAL`, `REFRESH_ASSIGNMENTS_INTERVAL`, `RUNNER_JOIN_DEBOUNCE`, `RUNNER_HEALTH_CHECK_INTERVAL`, `SIMULATE_REMOTE_SERIALIZATION`, `LISTEN_HOST` et `LISTEN_PORT`. Laissez-les non définies : Peal est testé avec leurs valeurs par défaut, et `SHARD_LOCK_DISABLE_ADVISORY=true` laisserait deux serveurs exécuter les mêmes tâches.

## Application web [#web-app]

| Variable             | Par défaut                                          | Rôle                                                                                                                                                                                                                                                       |
| -------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Elle y transmet `/api/*` et `/.well-known/oauth-*`, et s’en sert pour rendre les pages. Lue à chaque requête : un même build tourne avec n’importe quel serveur. |

Dans un conteneur, où Docker met dans `HOSTNAME` l’identifiant du conteneur, définissez-la à `0.0.0.0`, comme le fait l’image de l’application web.                                                               |
| `KEEP_ALIVE_TIMEOUT` | celle de Node                                       | Combien de temps, en millisecondes, une connexion inactive reste ouverte, pour un proxy placé devant qui garde ses connexions plus longtemps.                                                                                                              |
| `PEAL_RELEASE`       | `unknown`                                           | La version que nomment les [signalements d’erreurs](/self-hosting#web-errors) de l’application web, comme `2026.11.0`. Lue à chaque requête. La pile de production y met `PEAL_VERSION`.                                                                   |
| `PEAL_TERMS_URL`     | non définie                                         | L’adresse de vos conditions d’utilisation, comme `https://peal.example.com/terms`, vers laquelle la page de facturation renvoie avant une commande. Lue à chaque requête. Non définie, la page cite les conditions sans lien.                              |
| `NODE_ENV`           | `production` pour un build                          | L’application web construite tourne toujours en mode production, où `PEAL_API_URL` est obligatoire.                                                                                                                                                        |

## Ligne de commande [#command-line]

| Variable          | Par défaut              | Rôle                                                                                        |
| ----------------- | ----------------------- | ------------------------------------------------------------------------------------------- |
| `PEAL_API_URL`    | `http://localhost:3000` | L’adresse de l’instance, comme `https://peal.example.com`, sauf si `--api-url` est indiqué. |
| `PEAL_WORKSPACE`  | non définie             | L’espace de travail des commandes, par slug ou identifiant, sauf avec `--workspace`.        |

| `PEAL_CONFIG_DIR` | non définie             | Le dossier où sont enregistrées les connexions, dans `credentials.json`.                    |

## Pile Docker Compose [#compose]

`compose.production.yaml`, dans `packages/peal-docker`, transmet au serveur les réglages ci-dessus, et lit ceux-ci pour elle-même. Ceux marqués « obligatoire » arrêtent Compose, qui nomme celui qui manque. Voir [Avec Docker Compose et Caddy](/self-hosting#compose).

| Variable                                                                                                                  | Par défaut                                       | Rôle                                                                                                                                                                                                                                        |
| ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POSTGRES_PASSWORD`                                                                                                       | aucune : obligatoire                             | Le mot de passe de la base de données, avec lequel `DATABASE_URL` est construite : gardez-le compatible avec une URL, comme `openssl rand -hex 32`. Gardez-le secret.                                                                       |
| `GRAFANA_ADMIN_PASSWORD`                                                                                                  | aucune : obligatoire                             | Le mot de passe du compte `admin` de Grafana, défini au premier démarrage de Grafana. Gardez-le secret.                                                                                                                                     |
| `PEAL_DOMAIN`                                                                                                             | obligatoire avec Caddy                           | Le nom d’hôte de `PUBLIC_URL`, pour lequel Caddy (`compose.self-host.yaml`) obtient un certificat.                                                                                                                                          |
| `PEAL_SITE_DOMAIN`, `PEAL_DOCS_DOMAIN`                                                                                    | non définies                                     | Les noms d’hôte où Caddy (`compose.self-host.yaml`) sert le site vitrine et la documentation, une fois leurs blocs décommentés dans `self-host/Caddyfile`.                                                                                  |
| `PEAL_VERSION`                                                                                                            | `local`                                          | L’étiquette des images que la pile fait tourner et construit ; `PEAL_POSTGRES_VERSION` est celle de l’image Postgres.                                                                                                                       |
| `SITE_URL`, `SITE_DOCS_URL`                                                                                               | non définies                                     | Lues à la construction de l’image `static`. L’origine publique du site vitrine, pour les liens canoniques et vers les autres langues, et celle de la documentation, qui ajoute des liens vers elle. Non définie ou vide, chacune est omise. |
| `SITE_PLAUSIBLE_DOMAIN`, `SITE_PLAUSIBLE_HOST`                                                                            | non définies                                     | Lues à la construction de l’image `static`. Le domaine pour lequel le site vitrine compte les visites avec Plausible, et un Plausible auto-hébergé d’où le charger plutôt que celui de Plausible. Non défini ou vide, rien n’est compté.    |
| `DOCS_SITE_URL`                                                                                                           | non définie                                      | Lue à la construction de l’image `static`. L’origine publique de la documentation, pour les liens absolus de `llms.txt`, le plan du site et les images Open Graph ; non définie ou vide, les liens sont relatifs.                           |
| `DOCS_PLAUSIBLE_DOMAIN`, `DOCS_PLAUSIBLE_HOST`                                                                            | non définies                                     | Lues à la construction de l’image `static`. Le domaine pour lequel la documentation compte les visites avec Plausible, et un Plausible auto-hébergé d’où le charger. Non défini ou vide, rien n’est compté.                                 |
| `PEAL_POSTGRES_ARCHIVE_MODE`                                                                                              | `off`                                            | `on` archive les journaux de transactions (WAL) de Postgres avec pgBackRest, dans le bucket ci-dessous, pour restaurer les sauvegardes à n’importe quel moment.                                                                             |
| `PGBACKREST_REPO1_S3_ENDPOINT`, `PGBACKREST_REPO1_S3_BUCKET`, `PGBACKREST_REPO1_S3_KEY`, `PGBACKREST_REPO1_S3_KEY_SECRET` | non définies                                     | Le bucket où vont les sauvegardes, comme `<account>.r2.cloudflarestorage.com` et `peal-backups`, et une clé qui peut y lire et y écrire. Gardez la clé secrète.                                                                             |
| `PGBACKREST_REPO1_CIPHER_PASS`                                                                                            | non définie                                      | La phrase secrète qui chiffre les sauvegardes, comme `openssl rand -base64 48`. Gardez-la secrète, et gardez-en une copie loin du serveur : sans elle, les sauvegardes sont illisibles.                                                     |
| `PGBACKREST_REPO1_TYPE`, `PGBACKREST_REPO1_PATH`, `PGBACKREST_REPO1_S3_REGION`, `PGBACKREST_REPO1_S3_URI_STYLE`           | `s3`, `/peal`, `auto`, `path`                    | Le type de dépôt (`posix` pour un dossier), l’endroit où y vont les sauvegardes, la région pour laquelle les requêtes sont signées, et si le nom du bucket va dans le chemin ou dans le nom d’hôte (`host`).                                |
| `PEAL_GRAFANA_URL`                                                                                                        | `http://localhost:13000`                         | L’adresse où l’on ouvre Grafana.                                                                                                                                                                                                            |
| `PEAL_GRAFANA_ACCESS_TEAM`, `PEAL_GRAFANA_ACCESS_AUD`                                                                     | non définies                                     | Une équipe Cloudflare Zero Trust et l’étiquette d’audience de l’application Access placée devant Grafana. Définies, Grafana connecte, comme administrateurs, les personnes qu’Access laisse passer.                                         |
| `PEAL_GRAFANA_CONTACT_POINTS`                                                                                             | aucun point de contact                           | Le fichier de points de contact d’alerte que Grafana charge. `./config/production/grafana/alerting/telegram.yaml` envoie chaque alerte à la discussion Telegram `TELEGRAM_CHAT_ID`, par le bot `TELEGRAM_BOT_TOKEN`.                        |
| `PEAL_GRAFANA_HEARTBEAT`                                                                                                  | aucun battement                                  | `./config/production/grafana/alerting/heartbeat.yaml` envoie un battement de cœur à un service de surveillance extérieur toutes les 5 minutes environ, qui alerte quand il cesse. Voir [Surveiller de l’extérieur](/self-hosting#uptime).   |
| `PEAL_HEARTBEAT_URL`, `PEAL_HEARTBEAT_TOKEN`                                                                              | non définies                                     | L’adresse où Grafana envoie son battement de cœur, comme celle d’un point de terminaison externe de Gatus, et le jeton porteur que le service de surveillance a donné pour elle. Gardez le jeton secret.                                    |
| `PEAL_SERVER_PORT`, `PEAL_WEB_PORT`, `PEAL_SITE_PORT`, `PEAL_DOCS_PORT`, `PEAL_GRAFANA_PORT`, `PEAL_OTLP_HTTP_PORT`       | `3000`, `3001`, `4321`, `4322`, `13000`, `14318` | Les ports sur `127.0.0.1` que publient le serveur, l’application web, le site vitrine et la documentation (profil `static`), Grafana et le récepteur OTLP/HTTP du collecteur.                                                               |

## Outils [#tools]

`bun nx run peal-server:media-cors`, qui pose la règle CORS des imports sur le bucket, lit les variables `PEAL_S3_*` du stockage des médias, `PUBLIC_URL` et `TRUSTED_ORIGINS`, avec les mêmes valeurs par défaut que le serveur. `bun nx run peal-server:bluesky-key` ne lit rien.
