Le serveur, l’application web et la ligne de commande lisent de simples variables d’environnement : ils tournent sur n’importe quel hôte. Cette page liste chacune de celles qu’ils lisent. Les valeurs indiquées sont des exemples.

Le serveur tourne en mode production quand `NODE_ENV` vaut `production`, comme son image le définit. Les réglages marqués « obligatoire en production » n’y ont pas de valeur par défaut, et le serveur refuse de démarrer sans eux. Ailleurs, ils valent par défaut l’environnement de développement : un serveur lancé depuis les sources n’a besoin que de `DATABASE_URL`.

## Serveur [#server]

### Essentiel [#core]

| Variable                        | Par défaut                                          | Rôle                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                  | aucune : obligatoire                                | La base de données Postgres, comme `postgres://peal:secret@postgres:5432/peal`. Connectez-vous directement ou par un pooler en mode session, jamais en mode transaction.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `PUBLIC_URL`                    | obligatoire en production ; `http://localhost:3001` | L’adresse où l’on ouvre Peal : l’application web, comme `https://peal.example.com`. Les liens des e-mails, la connexion, les retours des plateformes et l’adresse du point d’accès MCP sont construits depuis son origine. Les clients MCP ne se connectent que si elle est en HTTPS, ou sur un hôte local comme `localhost`.                                                                                                                                                                                                                                                                                                                                                                   |
| `NODE_ENV`                      | `development`                                       | `production` active le mode production : réglages obligatoires, limites de débit de la connexion, et aucune valeur par défaut de développement.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `PORT`                          | `3000`                                              | Le port d’écoute du serveur HTTP.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `HOSTNAME`                      | `peal-server`                                       | Le nom du serveur parmi les exécuteurs de tâches enregistrés dans la base. Chaque processus serveur a besoin du sien ; Docker y met l’identifiant du conteneur.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `PEAL_CLUSTER_RETENTION`        | `30 days`                                           | Combien de temps les traces des tâches terminées, comme celle d’une publication diffusée, sont gardées avant qu’un nettoyage quotidien les supprime, en durée anglaise comme `7 days`. Les tâches encore en attente sont toujours gardées.                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `PEAL_ANALYTICS_CONCURRENCY`    | `16`                                                | Le nombre de canaux que les collectes horaires des chiffres des publications et des abonnés des comptes lisent chacune en même temps, un appel à la fois pour chacun, de `1` à `256`. Une collecte s’arrête 50 minutes après son heure et laisse le reste à la suivante : augmentez cette valeur quand le serveur journalise que la collecte n’a pas pu finir et que la métrique `peal.analytics.collection.left` reste au-dessus de zéro. Une autre valeur arrête le serveur.                                                                                                                                                                                                                  |
| `PEAL_ENGAGEMENT_CONCURRENCY`   | `8`                                                 | Le nombre de canaux que la collecte des commentaires, qui tourne toutes les dix minutes, lit en même temps, un appel à la fois pour chacun, de `1` à `256`. Une collecte s’arrête 8 minutes après son heure et laisse le reste à la suivante : augmentez cette valeur quand le serveur journalise que la collecte des commentaires n’a pas pu finir avant la suivante.                                                                                                                                                                                                                                                                                                                          |
| `PEAL_ENGAGEMENT_WINDOW_DAYS`   | `30`                                                | Le nombre de jours pendant lesquels Peal lit les commentaires d’une publication après sa mise en ligne, de `1` à `90`. Les commentaires sont des données personnelles de tiers, et chaque fil est supprimé {{keep-inbox-fr}} après la fin de sa fenêtre : une fenêtre plus longue les conserve plus longtemps, dites-le dans votre politique de confidentialité. Voir [Boîte de réception](/inbox#retention).                                                                                                                                                                                                                                                                                   |
| `PEAL_INBOX_PLATFORMS`          | non définie                                         | Les plateformes dont la [boîte de réception](/inbox#meta) lit les commentaires en plus de Mastodon et Bluesky, séparées par des virgules : `facebook`, `instagram`, ou les deux. Non définie ou vide, aucune. Leurs connexions demandent alors, en option, les autorisations des commentaires, que Meta n’accorde pour d’autres comptes que ceux des personnes de votre application qu’après son App Review. `facebook` demande `META_APP_ID` et `META_APP_SECRET` ; `instagram`, ceux-ci ou `INSTAGRAM_APP_ID` et `INSTAGRAM_APP_SECRET`. Tout autre nom, ou une plateforme sans son application, arrête le serveur au démarrage.                                                              |
| `PEAL_API_REQUESTS_PER_MINUTE`  | `600`                                               | Combien de requêtes par minute chaque clé d’API, et chaque application OAuth pour chaque utilisateur au nom duquel elle agit, peut envoyer à l’API et au point d’accès MCP réunis : un entier positif. Les sessions de l’application web ne sont pas comptées. Chaque réponse dit ce qui reste dans les en-têtes `RateLimit`, et au-delà de la limite le serveur répond 429 ([Limites de débit](/api-conventions#rate-limits)). Une valeur qui n’est pas un entier positif arrête le serveur au démarrage.                                                                                                                                                                                      |
| `PEAL_DOCS_URL`                 | non définie                                         | L’adresse de votre copie de cette documentation, comme `https://docs.example.com`. Avec elle, les documents qui indiquent aux programmes où se trouvent l’API et le point d’accès MCP (`/.well-known/api-catalog` et `/llms.txt`) renvoient vers ses pages ; sans elle, ils ne renvoient vers aucune documentation ([Découverte](/api-conventions#discovery)). Une valeur qui n’est pas une URL arrête le serveur au démarrage.                                                                                                                                                                                                                                                                 |
| `PEAL_LEGAL_RETENTION`          | `false`                                             | Si le serveur conserve ce que la loi française impose à un hébergeur pour identifier quiconque a contribué à un contenu : les connexions qui créent, modifient ou suppriment un contenu ({{keep-legal-connections-fr}}) et, à la fermeture d’un compte, les nom et adresse de son titulaire ({{keep-legal-identity-fr}}) et ses moyens de connexion ({{keep-legal-account-fr}}), lisibles uniquement par une réquisition. Définissez `true` si vous êtes établi en France, ou y proposez votre Peal, et stockez des contenus pour d’autres que vous ; laissez-la désactivée sinon. [Conservation légale](/self-hosting#legal-retention) dit qui y est tenu, et ce que produit sa désactivation. |
| `PEAL_PRIVACY_DECLARATION_FILE` | aucune                                              | Le chemin d’un fichier JSON qui déclare ce que vous seul savez de votre traitement : qui est le responsable de traitement et comment le joindre, l’adresse de votre politique de confidentialité, les prestataires auxquels vous recourez et votre autorité de contrôle. L’export des données de chaque utilisateur le reprend ([Déclaration de confidentialité](/self-hosting#privacy-declaration)). Sans elle, l’export indique qu’aucune n’a été déclarée ; un fichier absent ou mal formé arrête le serveur. La pile Compose la définit, et monte le fichier que nomme `PEAL_PRIVACY_DECLARATION`.                                                                                          |

### Connexion [#sign-in]

| Variable                          | Par défaut                                             | Rôle                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --------------------------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BETTER_AUTH_SECRET`              | obligatoire en production ; un secret de développement | Le secret qui signe les sessions et chiffre ce que la connexion stocke : au moins 32 caractères aléatoires, comme `openssl rand -base64 32`. Qui le connaît peut se connecter à la place de n’importe qui. Gardez-le secret. Il chiffre aussi les clés et codes de secours de la [validation en deux étapes](/settings#two-step) : le remplacer sans garder l’ancien dans `BETTER_AUTH_SECRETS` les rend illisibles, et personne qui l’a activée ne peut plus se connecter avant que l’équipe ne la réinitialise. |
| `BETTER_AUTH_SECRETS`             | non définie                                            | Pour changer de secret : des entrées `version:secret` séparées par des virgules, la plus récente en tête, comme `2:<nouveau>,1:<ancien>`. Lue par Better Auth lui-même : quand elle est définie, le secret de la première entrée sert, et les autres, avec `BETTER_AUTH_SECRET`, déchiffrent encore ce que les anciens secrets ont chiffré.                                                                                                                                                                       |
| `AUTH_IP_HEADERS`                 | obligatoire en production ; `x-forwarded-for`          | Les en-têtes, séparés par des virgules, qui portent l’adresse du client, que les limites de débit de la connexion et les signalements d’erreurs de l’application web comptent. Ne nommez qu’un en-tête que votre frontal définit en remplaçant celui du client : `cf-connecting-ip` derrière Cloudflare, `x-forwarded-for` derrière Caddy. Voir [Devant Peal](/self-hosting#reverse-proxy).                                                                                                                       |
| `AUTH_TRUSTED_PROXIES`            | aucune                                                 | Les adresses ou plages CIDR, séparées par des virgules, des proxies qui ajoutent à `X-Forwarded-For`. L’adresse du client est alors lue depuis la droite, après eux.                                                                                                                                                                                                                                                                                                                                              |
| `TRUSTED_ORIGINS`                 | aucune                                                 | Les origines, en plus de `PUBLIC_URL` et séparées par des virgules, autorisées à envoyer des requêtes connectées qui changent quelque chose. `media-cors` les laisse aussi importer des médias.                                                                                                                                                                                                                                                                                                                   |
| `AUTH_REQUIRE_EMAIL_VERIFICATION` | `true`                                                 | `false` permet de se connecter avant d’avoir confirmé son adresse e-mail.                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `AUTH_DB_POOL_MAX`                | `5`                                                    | Combien de connexions à la base ouvre la connexion des utilisateurs, en plus des 10 du serveur.                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `MCP_DYNAMIC_REGISTRATION`        | `false`                                                | `true` laisse les clients MCP s’enregistrer eux-mêmes, ce dont la plupart ont besoin avant de se connecter. N’importe qui peut alors enregistrer un client sous n’importe quel nom ; la page de consentement indique que Peal ne l’a pas vérifié.                                                                                                                                                                                                                                                                 |
| `PEAL_PARTNER_SELF_SERVICE`       | `false`                                                | `true` laisse les propriétaires et administrateurs de n’importe quel espace de travail lui ouvrir eux-mêmes un [compte partenaire](/embedding), dans ses paramètres. Sans valeur ou à `false`, seule l’équipe en ouvre un, depuis la [console d’administration](/staff#partners). Une autre valeur arrête le serveur.                                                                                                                                                                                             |
| `PEAL_STAFF_TWO_STEP`             | `false`                                                | `true` refuse la [console d’administration](/staff#two-step) aux membres de l’équipe dont le compte n’a pas activé la [validation en deux étapes](/settings#two-step) ; pour les autres, la console reste introuvable. Les membres l’activent eux-mêmes et les propriétaires peuvent l’exiger d’un espace de travail : ni l’un ni l’autre ne demande de réglage. Une autre valeur arrête le serveur.                                                                                                              |

Better Auth lit aussi `BETTER_AUTH_TRUSTED_ORIGINS`, qui ajoute des origines comme `TRUSTED_ORIGINS`. Préférez `TRUSTED_ORIGINS`, que `media-cors` lit aussi.

### E-mail [#email]

| Variable         | Par défaut                                                                 | Rôle                                                                                                                                                                                                                               |
| ---------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MAIL_FROM`      | obligatoire en production ; `Peal <noreply@peal.localhost>`                | L’expéditeur, comme `Peal <noreply@example.com>` ou une adresse depuis laquelle votre service de messagerie peut envoyer.                                                                                                          |
| `RESEND_API_KEY` | non définie                                                                | Envoie les e-mails par l’API de Resend. Gardez-la secrète.                                                                                                                                                                         |
| `SMTP_URL`       | obligatoire en production sans `RESEND_API_KEY` ; `smtp://127.0.0.1:11025` | Le serveur SMTP, comme `smtp://utilisateur:motdepasse@mail.example.com:587`, ou `smtps://` pour du TLS dès le premier octet. Sert quand `RESEND_API_KEY` n’est pas définie. Gardez-la secrète quand elle contient un mot de passe. |

### Médias [#media]

| Variable                      | Par défaut                                             | Rôle                                                                                                                                                                                                                                                                                                                                                                                                                                             |

### Télémétrie [#telemetry]

| Variable                      | Par défaut                                                                 | Rôle                                                                                                                                                                                                                                                                                                                 |
| ----------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | non définie                                                                | L’adresse OTLP/HTTP du collecteur OpenTelemetry qui reçoit les journaux, métriques et traces, comme `http://otel-collector:4318`. Non définie, rien n’est exporté.                                                                                                                                                   |
| `OTEL_SERVICE_NAME`           | `peal-server`                                                              | Le nom de service sous lequel la télémétrie est envoyée.                                                                                                                                                                                                                                                             |
| `OTEL_TRACES_EXPORTER`        | `otlp`                                                                     | `none` arrête l’export des traces une fois un point d’accès défini. `OTEL_METRICS_EXPORTER` et `OTEL_LOGS_EXPORTER` font de même pour les métriques et les journaux.                                                                                                                                                 |
| `OTEL_TRACES_SAMPLER`         | `parentbased_traceidratio` en production, `parentbased_always_on` ailleurs | Les traces exportées, par les noms d’échantillonneurs d’OpenTelemetry : `always_on`, `always_off`, `traceidratio`, `parentbased_always_on`, `parentbased_always_off` ou `parentbased_traceidratio`. Ceux en `parentbased_` suivent la décision avec laquelle une requête arrive. Une autre valeur arrête le serveur. |
| `OTEL_TRACES_SAMPLER_ARG`     | `0.1` en production, `1` ailleurs                                          | La part des traces que gardent les échantillonneurs `traceidratio`, de `0` à `1`. La production garde une trace sur dix sauf indication contraire.                                                                                                                                                                   |

L’échantillonneur décide au début d’une trace, avant que l’on sache comment elle finit. Pour que les traces que vous cherchez soient là, quel que soit le taux :

- chaque tentative de publication sur un canal est tracée, avec les appels à la plateforme qu’elle fait ;
- d’une trace non échantillonnée, le serveur exporte quand même les spans terminés par un bogue, les requêtes auxquelles il a répondu par un `5xx` et les spans qui ont duré 10 secondes ou plus, chacun avec ceux au-dessus de lui ;
- les journaux et les métriques ne sont jamais échantillonnés : chaque erreur est journalisée avec l’identifiant de sa trace, et chaque requête est comptée dans la métrique `peal.http.requests`, par classe de statut, que lisent les alertes de la pile.

`always_off` et `parentbased_always_off` désactivent tout cela : aucune trace ne commence sur le serveur.

Le serveur exporte la télémétrie en JSON sur HTTP : faites pointer le point d’accès vers le port OTLP/HTTP du collecteur, 4318 par défaut, et non vers son port gRPC. Il lit aussi ces variables OpenTelemetry, et aucune autre (`OTEL_EXPORTER_OTLP_PROTOCOL` comprise) :

- `OTEL_EXPORTER_OTLP_HEADERS`, `OTEL_EXPORTER_OTLP_COMPRESSION` et `OTEL_EXPORTER_OTLP_TIMEOUT`, ainsi que leurs variantes par signal et celles du point d’accès, comme `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` ;
- `OTEL_RESOURCE_ATTRIBUTES` et `OTEL_SERVICE_VERSION` ;
- `OTEL_SDK_DISABLED` ;
- les réglages de regroupement `OTEL_BSP_*` pour les traces et `OTEL_BLRP_*` pour les journaux ;
- `OTEL_METRIC_EXPORT_INTERVAL`, `OTEL_METRIC_EXPORT_TIMEOUT` et `OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE`.

## Outils [#tools]

`bun nx run peal-server:media-cors`, qui pose la règle CORS des imports sur le bucket, lit les variables `PEAL_S3_*` du stockage des médias, `PUBLIC_URL` et `TRUSTED_ORIGINS`, avec les mêmes valeurs par défaut que le serveur. `bun nx run peal-server:bluesky-key` ne lit rien.
