## Paging [#paging]

Lists that can grow without end are read a page at a time, newest first:

1. Send `limit`, the size of a page, in the query.
2. The answer is an object with the page's `items` and a `nextCursor`.
3. Pass `nextCursor` as `cursor` to read the next page, and stop when it is `null`.

A cursor is an opaque string, good for the list it came from, with the same filters: elsewhere it answers 400 `bad_request`.

| List                                     | A page holds | At most |
| ---------------------------------------- | ------------ | ------- |
| `GET …/posts/drafts`                     | 20           | 50      |
| `GET …/media`                            | 30           | 100     |
| `GET …/webhooks/{endpointId}/deliveries` | 30           | 100     |
| `GET …/activity`                         | 30           | 100     |
| `GET /api/me/notices`                    | 20           | 100     |

Paths starting with `…` are under `/api/workspaces/{workspaceId}`.

The first page:

<CodeGroup>

```bash curl
curl "https://api.example.com/api/workspaces/$WORKSPACE_ID/activity?limit=2" \
  -H "Authorization: Bearer $PEAL_API_KEY"
```

```ts TypeScript
const page = await peal.activity.list({ workspaceId, limit: "2" });
```

The next page, with the `nextCursor` above, and a loop that reads them all (the SDKs have no helper that does it for you):

<CodeGroup>

```bash curl
curl "https://api.example.com/api/workspaces/$WORKSPACE_ID/activity?limit=2&cursor=MDE5YTdiMzAtNmYxOC03YTk1LTlkMDctMWMyYjNhNGQ1ZTZm" \
  -H "Authorization: Bearer $PEAL_API_KEY"
```

```ts TypeScript
let cursor: string | undefined;

do {
  const page = await peal.activity.list({ workspaceId, limit: "100", cursor });

  for (const entry of page.items) {
    console.log(entry.operation, entry.status);
  }

  cursor = page.nextCursor ?? undefined;
} while (cursor !== undefined);
```

</CodeGroup>

### Lists that take a range [#ranges]

Two lists take a range instead, and answer everything in it at once:

| List                                             | What it answers                                                             | Range                 | Otherwise            |
| ------------------------------------------------ | --------------------------------------------------------------------------- | --------------------- | -------------------- |
| `GET …/posts?from=…&to=…`                        | The posts scheduled between two instants, `from` included and `to` excluded | At most 62 days apart | `invalid_time_range` |
| `GET …/analytics/summary?from=…&to=…&timeZone=…` | A sum of the posts published over a range of days, both included            | 366 days at most      | `invalid_date_range` |

The lists a workspace keeps short answer whole, as an array: its channels, members, pending invitations, API keys and webhook endpoints.
