A script or an agent that posts through the [HTTP API](/api-overview) can check a post before it sends it, wait for the outcome of a post that goes out now, send up to 50 posts in one request, import posts from a CSV file, and list the workspace's posts with filters. This page shows each request with an example. The [API reference](/reference) has every field.

## Before you start [#start]

Every endpoint here is under `/api/workspaces/{workspaceId}/posts`. The examples read the workspace's id from `$WORKSPACE_ID` and an [API key](/settings#api-keys), which looks like `peal_…`, from `$PEAL_API_KEY`. Ids are made up, and answers are abridged: a post always comes whole, as `GET …/posts/{postId}` answers it.

| Request                        | What it does                              | Needs                                        |
| ------------------------------ | ----------------------------------------- | -------------------------------------------- |
| `POST …/posts/validate`        | Checks a post, and makes nothing          | `post:read`, `channel:read`                  |
| `POST …/posts/send`            | Creates a post and sends it, now or later | `post:schedule`, `channel:read`              |
| `GET …/posts/{postId}/outcome` | Waits until a post has gone out           | `post:read`                                  |
| `POST …/posts/bulk`            | Creates and sends up to 50 posts          | `post:schedule`, `channel:read`              |
| `POST …/posts/import`          | Creates and sends the posts of a CSV file | `post:schedule`, `post:read`, `channel:read` |
| `GET …/posts/search`           | Lists the workspace's posts, with filters | `post:read`, `channel:read`                  |

A post that shows media also needs `media:read`. An OAuth access token needs the scope `workspace:publish` for `send`, `bulk` and `import` ([What each permission allows](/agents#scopes)).

What `send`, `bulk` and `import` publish reaches the platforms' public, and cannot be taken back from Peal once it is out. Until its time, cancel or unschedule a post.

## Check a post without making it [#validate]

`POST …/posts/validate` takes what `send` takes, or a draft, which has no `when`. It writes nothing. It answers 200 whether or not the post would go through, with `valid` and everything that would refuse it, all at once.

```bash
curl -X POST https://api.example.com/api/workspaces/$WORKSPACE_ID/posts/validate \
  -H "Authorization: Bearer $PEAL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "channelIds": ["0190f3a0-0000-7000-8000-00000000c001"],
    "content": {
      "text": "Our spring catalogue is out. Read it at https://example.com/spring #spring",
      "media": [],
      "overrides": []
    },
    "when": { "_tag": "at", "at": "2026-11-16T08:00:00Z", "timeZone": "Europe/Paris" }
  }'
```

```json
{
  "valid": true,
  "channels": [
    {
      "channelId": "0190f3a0-0000-7000-8000-00000000c001",
      "platform": "bluesky",
      "text": "Our spring catalogue is out. Read it at https://example.com/spring #spring",
      "textCounts": [
        { "length": 74, "maximum": 300, "unit": "graphemes" },
        { "length": 74, "maximum": 3000, "unit": "utf8Bytes" }
      ],
      "hashtags": { "count": 1, "maximum": null },
      "mentions": { "count": 0, "maximum": null },
      "links": { "count": 1, "maximum": null },
      "media": { "count": 0, "maximum": 4 },
      "parts": [],
      "violations": []
    }
  ],
  "violations": [],
  "unknownChannels": [],
  "unknownMedia": [],
  "schedule": "ok",
  "planLimit": null,
  "awaitsApproval": false,
  "duplicates": []
}
```

| Field             | What it holds                                                                                                                                                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `valid`           | True when nothing below refuses the post                                                                                                                                                                                             |
| `channels`        | One entry per channel of the workspace the post names, in the order given                                                                                                                                                            |
| `violations`      | What is wrong whatever the channel: no channel at all, or a text or options for a channel the post does not go to                                                                                                                    |
| `unknownChannels` | The channels it names that are not the workspace's                                                                                                                                                                                   |
| `unknownMedia`    | The media it shows that are not the workspace's, or not ready                                                                                                                                                                        |
| `schedule`        | `ok`; `inPast`, more than a minute ago; or `invalidTimeZone`, when the zone is no IANA zone. Null without `when`.                                                                                                                    |
| `planLimit`       | The limit of the workspace's plan the post would pass, as `PlanLimitReached` tells it. Null when the plan has room, on an instance that does not bill, or without `when`.                                                            |
| `awaitsApproval`  | Whether the post, sent as it is, would wait for an [approval](/review) before it is scheduled, as the workspace asks of this caller: it would be made, with the status `awaitingApproval`. It refuses nothing. False without `when`. |
| `duplicates`      | The channels that already have the same content from another post near its time, each with that post ([Duplicate posts](#duplicates)). None without `when`, or when the request allows duplicates.                                   |

Each entry of `channels` holds:

- `text`: the text the channel receives, which is its override there, or the post's own;
- `textCounts`: that text's length, counted as the channel's platform counts it, against each of its limits. Bluesky has two, in graphemes and in bytes;
- `hashtags`, `mentions`, `links` and `media`: how many the post holds (`count`) and the most the platform takes (`maximum`, null when Peal knows no limit for it). `links` counts different links;
- `parts`: the parts after the first of a [thread](/scheduling#threads), in order, each with its `part` (its place, from 1), its `text` on the channel and the same counts; none for a post alone. A platform that takes a post alone still lists them, and refuses them with `tooManyParts`;
- `violations`: every rule of the platform the post breaks, in any of its parts (text, media formats, sizes, counts and durations, options), and the account's own where its platform tells them. One about a later part names it by `part`. They read as in `PostContentInvalid` ([How refusals read](/agents#refusals)).

A post that would be refused answers 200 too, with `valid` false:

```json
{
  "valid": false,
  "channels": [
    {
      "channelId": "0190f3a0-0000-7000-8000-00000000c001",
      "platform": "bluesky",
      "textCounts": [
        { "length": 342, "maximum": 300, "unit": "graphemes" },
        { "length": 342, "maximum": 3000, "unit": "utf8Bytes" }
      ],
      "parts": [],
      "violations": [
        {
          "_tag": "textTooLong",
          "channelId": "0190f3a0-0000-7000-8000-00000000c001",
          "platform": "bluesky",
          "length": 342,
          "maximum": 300,
          "unit": "graphemes"
        }
      ]
    }
  ],
  "unknownChannels": ["0190f3a0-0000-7000-8000-00000000c009"],
  "schedule": "inPast"
}
```

Without `when`, the request is a draft's: neither the time, the plan's room nor duplicates are checked.

A post that is valid now can still be refused later: a channel disconnected, a plan's month filled meanwhile.

## Publish now and wait for the outcome [#wait]

`POST …/posts/send` answers as soon as the post is made, while it publishes. With `wait`, a number of seconds from 0 to 60, a post that goes out now is answered once every channel has its result:

```bash
curl -X POST "https://api.example.com/api/workspaces/$WORKSPACE_ID/posts/send?wait=30" \
  -H "Authorization: Bearer $PEAL_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 5f0c2b7e-3d1a-4e58-9a6b-2c4d8e1f7a90" \
  -d '{
    "channelIds": [
      "0190f3a0-0000-7000-8000-00000000c001",
      "0190f3a0-0000-7000-8000-00000000c002"
    ],
    "content": {
      "text": "Our spring catalogue is out. Read it at https://example.com/spring",
      "media": [],
      "overrides": []
    },
    "when": { "_tag": "now" }
  }'
```

```json
{
  "id": "0190f3a0-0000-7000-8000-00000000b001",
  "status": "finished",
  "outcome": "partiallyPublished",
  "targets": [
    {
      "id": "0190f3a0-0000-7000-8000-00000000d001",
      "channelId": "0190f3a0-0000-7000-8000-00000000c001",
      "status": "published",
      "publishedAt": "2026-11-16T08:00:02.000Z",
      "permalink": "https://social.example/@peal_example/115512345678901234",
      "failureReason": null
    },
    {
      "id": "0190f3a0-0000-7000-8000-00000000d002",
      "channelId": "0190f3a0-0000-7000-8000-00000000c002",
      "status": "failed",
      "publishedAt": null,
      "permalink": null,
      "failureReason": "tokenExpired"
    }
  ]
}
```

- The answer is 201 either way: the post was made.
- When every channel has its result within the wait, the post's `status` is `finished`, with its `outcome`. Each target is `published`, with its `permalink`, or `failed`, with its `failureReason`.
- When the time runs out first, the answer is the post as it stands, some targets still `pending` or `publishing`. It goes on publishing.
- A [thread](/scheduling#threads) has its result on a channel once every part went out there, or one failed: a target stays `publishing` between two parts, with `parts.live` listing those that are out. With a wait between parts longer than `wait`, the time runs out first.

`GET …/posts/{postId}/outcome` waits for the rest. It takes the same `wait`, and answers the post once every channel has its result, or as it stands when the time runs out: ask again then.

```bash
curl "https://api.example.com/api/workspaces/$WORKSPACE_ID/posts/0190f3a0-0000-7000-8000-00000000b001/outcome?wait=30" \
  -H "Authorization: Bearer $PEAL_API_KEY"
```

Without `wait`, it does not wait. A draft, a cancelled post and a post scheduled for later than the wait are answered at once, and so is a request that comes while the server, or the workspace (10 at once), has as many requests waiting as it lets: ask again then. Waiting changes nothing and holds nothing: the post publishes in its own job either way, and [webhooks](/webhooks#events) still tell how it went on each channel.

## Send several posts in one request [#bulk]

`POST …/posts/bulk` creates and sends up to 50 posts, each as `send` would. Each item is one post, with its own channels, content, options and time. The same content at several times is several items, and so is a post that goes out at a time of its own on each channel.

```bash
curl -X POST https://api.example.com/api/workspaces/$WORKSPACE_ID/posts/bulk \
  -H "Authorization: Bearer $PEAL_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 9b2e4d6f-1a3c-4b5d-8e7f-0a1b2c3d4e5f" \
  -d '{
    "posts": [
      {
        "channelIds": ["0190f3a0-0000-7000-8000-00000000c001"],
        "content": {
          "text": "Our spring catalogue is out. Read it at https://example.com/spring",
          "media": [],
          "overrides": []
        },
        "when": { "_tag": "at", "at": "2026-11-16T08:00:00Z", "timeZone": "Europe/Paris" }
      },
      {
        "channelIds": ["0190f3a0-0000-7000-8000-00000000c009"],
        "content": {
          "text": "Our spring catalogue is out. Read it at https://example.com/spring",
          "media": [],
          "overrides": []
        },
        "when": { "_tag": "at", "at": "2026-11-16T17:00:00Z", "timeZone": "America/New_York" }
      }
    ]
  }'
```

```json
{
  "created": 1,
  "refused": 1,
  "items": [
    {
      "_tag": "created",
      "index": 0,
      "replayed": false,
      "post": {
        "id": "0190f3a0-0000-7000-8000-00000000b002",
        "status": "scheduled",
        "schedule": {
          "at": "2026-11-16T08:00:00.000Z",
          "timeZone": "Europe/Paris"
        }
      }
    },
    {
      "_tag": "refused",
      "index": 1,
      "refusal": {
        "_tag": "UnknownChannels",
        "channelIds": ["0190f3a0-0000-7000-8000-00000000c009"]
      }
    }
  ]
}
```

- Items are taken in order, one at a time, each on its own. One refused keeps none of the others from being made, and nothing is undone.
- The answer is 200 whenever the request itself was read, even if every item was refused. `items` says, for each item by its place in the request (`index`, from 0), `created` with its post, or `refused` with what `send` would have answered for it alone, as data: its content's violations, unknown channels or media, a time gone by, the plan's limit, a duplicate.
- A request that cannot be read at all (malformed, no item, more than 50) answers 400, and makes nothing.
- The plan's limits hold across the request: once the month has no room, the items left are refused.
- Each item is checked against the posts made before it, the request's earlier items included, for the same content on the same channel ([Duplicate posts](#duplicates)).

An `Idempotency-Key` header makes the whole request safe to send again within 24 hours. Each item is kept under the key and its place: the same request sent again answers the posts it made, with `replayed` true, and makes those that were not made the first time if they now can be. An item that changed under the same key is refused with `IdempotencyKeyReused`. An item may carry an `idempotencyKey` of its own, which is used instead of the header's for that item.

## Import posts from a CSV file [#import]

`POST …/posts/import` creates and sends the posts a CSV file lists, one per row. The file's first line names the columns, in any order:

| Column            | Required | What it holds                                                                                                                                             |
| ----------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`            | yes      | The post's text                                                                                                                                           |
| `channels`        | yes      | Channel ids, separated by spaces, commas or semicolons                                                                                                    |
| `at`              | yes      | `now`; an instant with its offset, such as `2026-11-20T09:00:00Z`; or a local time without one, such as `2026-11-20 10:00`, read in the row's `time_zone` |
| `time_zone`       | no       | An IANA zone, such as `Europe/Paris`. UTC if left out.                                                                                                    |
| `media`           | no       | Ids of ready media of the workspace                                                                                                                       |
| `allow_duplicate` | no       | `true` or `false` ([Duplicate posts](#duplicates))                                                                                                        |
| `idempotency_key` | no       | The row's own idempotency key                                                                                                                             |

A row is a post alone, with one text for all its channels: a [thread](/scheduling#threads), a text of its own on a channel or a platform's options do not fit in a cell, and go through `send` or `bulk`. A file that names another column is refused whole.

Cells follow RFC 4180: a cell with a comma, a quote or a line break is written between double quotes, and a quote inside it is doubled. A file holds at most 100 rows under its first line, and 1,000,000 characters.

```csv title="posts.csv"
text,channels,at,time_zone,media
Our spring catalogue is out.,0190f3a0-0000-7000-8000-00000000c001 0190f3a0-0000-7000-8000-00000000c002,2026-11-20 10:00,Europe/Paris,0190f3a0-0000-7000-8000-00000000a001
"Last days: the ""spring"" prices end on Sunday, at midnight.",0190f3a0-0000-7000-8000-00000000c001,2026-11-27T09:00:00Z,,
```

The request is JSON, with the file's text in `csv`. Here `jq` writes it from the file:

```bash
jq -Rs '{ csv: ., dryRun: true }' posts.csv |
  curl -X POST https://api.example.com/api/workspaces/$WORKSPACE_ID/posts/import \
    -H "Authorization: Bearer $PEAL_API_KEY" \
    -H "Content-Type: application/json" \
    -d @-
```

```json
{
  "created": 0,
  "dryRun": true,
  "rows": [
    { "_tag": "valid", "row": 1 },
    { "_tag": "valid", "row": 2 }
  ]
}
```

The file is checked first, every row, as `validate` checks a post, and as the file it is: a row an earlier row leaves no room for in its month is refused with `PlanLimitReached`, one that says what an earlier row says, on the same channel less than 23 hours from it, with `DuplicatePost` (its `message` names that row, as there is no post to name yet), and one that carries an earlier row's `idempotency_key` with another post with `IdempotencyKeyReused`. Unless every row is valid, nothing is made. `dryRun: true` stops there even when every row is valid. Otherwise the rows are then made in order, as `bulk` makes its items.

`rows` holds one result per row, by its place under the first line, from 1. Blank lines are no rows, and are not counted. Cells follow RFC 4180 strictly, so that no text is ever cut short: a cell that holds a comma, a line break or a double quote is written between double quotes, a quote inside it twice, and a row ends after its last cell, without a comma.

| `_tag`       | Meaning                                                                                                                                                                                                                                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `created`    | The row's post was made: `post` holds it, and `replayed` says whether its idempotency key answered one made before.                                                                                                                                                                                                 |
| `valid`      | The row was checked and not made: a dry run, or another row kept the file from being imported.                                                                                                                                                                                                                      |
| `refused`    | `refusal` holds what `send` would have answered for it. A row that was valid is refused too when something changed since the check, or when it repeats an earlier row.                                                                                                                                              |
| `unreadable` | `problems` names the cells at fault: each `column`, `missing` when the row needs it, or `invalid` for what it holds. A row with more or fewer cells than the first line names is not read at all: `cells` says how many were `expected` and `found`. A comma in a text that is not between double quotes makes one. |

```json
{
  "created": 0,
  "dryRun": false,
  "rows": [
    { "_tag": "valid", "row": 1 },
    {
      "_tag": "unreadable",
      "row": 2,
      "problems": [{ "column": "at", "problem": "invalid" }]
    }
  ]
}
```

The answer is 200 once the file was read. A file that cannot be read at all answers 422 `ImportUnreadable`, and nothing is made. `problem` says why, and `column` which column when it is about one:

| `problem`           | The file                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------ |
| `empty`             | is empty                                                                                   |
| `unterminatedQuote` | has a quoted cell that never ends                                                          |
| `strayQuote`        | has a double quote inside a cell that is not between quotes, or text after a closing quote |
| `unknownColumn`     | names a column Peal does not know                                                          |
| `repeatedColumn`    | names the same column twice                                                                |
| `missingColumn`     | lacks a column it needs                                                                    |
| `tooManyRows`       | has more rows than one import takes                                                        |

```json
{ "_tag": "ImportUnreadable", "problem": "missingColumn", "column": "at" }
```

An `Idempotency-Key` header works as on `bulk`, by row.

## Duplicate posts [#duplicates]

A post made in one call is refused when another post of the workspace already sends the same content to one of its channels less than 23 hours from its time. It answers 409 `DuplicatePost`, and nothing is made:

```json
{
  "_tag": "DuplicatePost",
  "duplicates": [
    {
      "channelId": "0190f3a0-0000-7000-8000-00000000c001",
      "postId": "0190f3a0-0000-7000-8000-00000000b001"
    }
  ]
}
```

`duplicates` names each channel that has the content, with the earliest post that sends it there in that time.

- **The same content** is the text the channel receives and the same media, in the same order.
- **23 hours** is the shortest day a time zone has, so a post that repeats every day at the same local time is never refused.
- **Only posts that go out or went out count**, those that wait for an approval among them, as they go out once approved: not drafts, cancelled posts, nor a channel where the post failed.
- **What is checked**: `send`, each item of `bulk`, each row of `import`, the MCP tools `create_post` and `create_posts`, and `peal post`. Scheduling an existing draft, moving a post and reposting on a channel where it failed are never refused.
- **When it is meant**, send the request again with `allowDuplicate: true`, on the post or on the bulk item, or `allow_duplicate` set to `true` on the CSV row.

This is apart from idempotency keys. A key makes one request safe to send again. The duplicate refusal catches the request made twice.

`validate` tells the same beforehand, in `duplicates`.

## List posts [#search]

`GET …/posts/search` lists the workspace's posts, whatever their state, a page at a time: 20 unless `limit` says otherwise, 100 at most. Every filter given must hold.

| Parameter    | What it keeps                                                                                                                                        |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `status`     | `draft`, `awaitingApproval` (it waits for an [approval](/review), and keeps its time), `scheduled`, `publishing`, `finished` or `cancelled`          |
| `outcome`    | How a finished post ended: `published`, `partiallyPublished`, `unconfirmed`, `failed` or `cancelled`                                                 |
| `channelId`  | Posts with a target on that channel                                                                                                                  |
| `platform`   | Posts with a target on a connected channel of that platform                                                                                          |
| `from`, `to` | Posts scheduled from `from` (included) to `to` (excluded). Either leaves out posts without a time.                                                   |
| `createdVia` | `web`, `apiKey` or `application`                                                                                                                     |
| `authorId`   | Posts that user created                                                                                                                              |
| `sort`       | `createdDesc` (the default) or `createdAsc`, by creation; `scheduledDesc` or `scheduledAsc`, by scheduled instant, which list only posts with a time |
| `limit`      | How many posts a page holds, from 1 to 100                                                                                                           |
| `cursor`     | The `nextCursor` of the page before                                                                                                                  |

```bash
curl "https://api.example.com/api/workspaces/$WORKSPACE_ID/posts/search?status=finished&outcome=failed&platform=bluesky&sort=scheduledDesc&limit=50" \
  -H "Authorization: Bearer $PEAL_API_KEY"
```

```json
{
  "items": [
    {
      "id": "0190f3a0-0000-7000-8000-00000000b003",
      "status": "finished",
      "outcome": "failed",
      "schedule": {
        "at": "2026-11-12T08:00:00.000Z",
        "timeZone": "Europe/Paris"
      },
      "targets": [
        {
          "id": "0190f3a0-0000-7000-8000-00000000d003",
          "channelId": "0190f3a0-0000-7000-8000-00000000c001",
          "status": "failed",
          "permalink": null,
          "failureReason": "tokenExpired"
        }
      ]
    }
  ],
  "channels": [
    {
      "channelId": "0190f3a0-0000-7000-8000-00000000c001",
      "platform": "bluesky"
    }
  ],
  "nextCursor": "eyJhZnRlciI6IjAxOTBmM2EwIn0"
}
```

- Each post comes whole, with its targets, their status, address and failure reason.
- `channels` gives the platform of each channel the page names that is still connected, so a client names each target without another request.
- For the next page, pass `nextCursor` as `cursor`, with the same filters and sort. It is null on the last page.
- A cursor marks where its page ended: posts created, moved or deleted meanwhile make no page repeat a post or skip one.
- A cursor of another sort, or one no page gave, answers 400.

`GET …/posts?from=…&to=…` stays, for calendars: it lists the posts scheduled between two instants, at most 62 days apart, by scheduled instant, in one answer. Drafts are not among them.

## Add a post to a queue [#queues]

A queue is a weekly timetable of slots in a time zone ([Queues](/scheduling#queues)): `GET`, `POST …/queues`, `GET`, `PUT`, `DELETE …/queues/{queueId}` keep them, with post:read to read and post:update to change. `when: { "_tag": "queue", "queueId": "…" }` on `send`, on each item of `bulk` and on `validate` puts a post on the queue's next free slot instead of a time; leave `queueId` out for the workspace's default queue. The slot is decided in the transaction that saves the post, under the queue's lock, so posts sent together take different slots, and a request sent again with its `Idempotency-Key` takes none. A post that names no channel and no set goes to the queue's channels and channel set, and its answer's `warnings` name the queue's channels disconnected since (`queueChannelsDropped`).

```sh
curl -X POST "https://peal.example/api/workspaces/$WORKSPACE_ID/posts/send" \
  -H "Authorization: Bearer $PEAL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"channelIds": [], "content": {"text": "An evergreen tip.", "media": [], "overrides": []}, "when": {"_tag": "queue"}}'
```

`POST …/posts/{postId}/queue`, with `{ "queueId"?, "channelIds"? }`, puts a draft on the next free slot (on `channelIds`, else its own channels, else the queue's channels and channel set, as a post sent onto the queue, with the same `warnings`), or moves a scheduled post, or one awaiting approval, there. Its own slot counts as free: a post added again to its queue stays where it is, unless a slot before it was freed since, which it then takes. `GET …/queues/{queueId}/slots?count=…` previews the next slots, each with the post that holds it, and `nextFree`, where a post added now would go: advice, as nothing is held.

- A queue without a slot, or with every slot of the next 366 days taken, answers 409 `queue_has_no_room`, with `reason` `noSlots` or `full`.
- A queue that is not the workspace's, or a default the workspace does not have, answers 404 `queue_not_found`.
- The plan's room is counted in the slot's month: `plan_limit_reached` when it is full, never a later month.
- `validate` answers `queueSlot`, the slot the post would take now, at which everything else was checked, or `queueNoRoom`.

Posts carry the queue that placed them (`queueId`, null once it is deleted), and `GET …/posts/search?queueId=…` lists them.

Saving a queue's slots moves no post. `POST …/queues/{queueId}/reshuffle`, with no body, moves its waiting posts (scheduled or awaiting approval, after now) onto its slots as they are now, in the order of their times, those moved by hand included ([Move the waiting posts onto new slots](/scheduling#reshuffle)). Each move is a `reschedule` (the plan counted in the new month, `post.scheduled` told for a scheduled post), but for approvals: a scheduled post goes through the approval policy as the caller's, and a post awaiting approval keeps waiting at its new time, whoever calls, its request still the requester's and `post.approval_requested` told with the new time; a post on its slot is not written. It needs post:schedule, or post:create where posts wait for an approval, and answers what it did:

```json
{ "moved": 12, "unchanged": 3, "remaining": 0, "stoppedBy": null }
```

`remaining` counts the posts not placed when it stopped, and `stoppedBy` says why: `planLimit` (a month without room), `full` (no slot left within 366 days) or `changed` (the queue was saved, or a post added to it on a slot not yet reached, meanwhile). Call it again to go on; called twice, the second call moves nothing. A queue without a slot answers 409 `queue_has_no_room` (`noSlots`).

## Repeat a post [#recycling]

`POST …/recycling`, with `{ "postId", "every": { "count", "unit" }, "count"?, "until"?, "variants"?, "queueId"? }`, makes a post that is scheduled, publishing or out repeat ([how](/scheduling#recycling)): `unit` is `days` (1 to 365), `weeks` (1 to 52) or `months` (1 to 12); `count` is the number of posts in all, the source counted (2 to 100); `until` the last day, as `YYYY-MM-DD` in the source's zone; each variant is `{ "text", "overrides"? }`, 10 at most. It answers 201 with the rule, whose `coming` lists its next three posts and the variant each says. Starting, changing, pausing, resuming and stopping a rule needs post:schedule (or post:create where posts wait for an approval, for starting), never staff acting as a member; reading, post:read.

```sh
curl -X POST "https://peal.example/api/workspaces/$WORKSPACE_ID/recycling" \
  -H "Authorization: Bearer $PEAL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"postId": "'$POST_ID'", "every": {"count": 2, "unit": "weeks"}, "count": 6, "variants": [{"text": "Open all summer, as before."}]}'
```

`GET …/recycling` lists the rules, oldest first (`status`, `limit`, `cursor`), `GET …/recycling/{ruleId}` reads one, `PATCH` changes its `count` or `until` (null takes it away), its `variants` (an empty array takes them away) or pauses it (`paused`), `POST …/recycling/{ruleId}/resume` with `{ "variants"? }` sets a paused rule going again, or one that ended for `planLimit`, `contentRejected`, `noChannels`, `queueFull` or `sourceWithdrawn` (its post cancelled or taken back to draft, once it is scheduled again: 409 `post_not_recyclable` until then, or while another rule repeats it, and 409 `too_many_recycling_rules` past 100), and `DELETE` stops it: the posts it made stay. Each post a rule makes carries `recyclingId` and `occurrence` (its place, the source being 1), and `GET …/posts/search?recyclingId=…` lists them. Each post acts as the rule's starter as they are then: a key's rule stops once the key is revoked. Changing, pausing, resuming or stopping a rule needs post:schedule, or to be its starter acting as they started it: in the web app, through the same application or with the same key.

- A post that cannot repeat answers 409 `post_not_recyclable`, with `reason`: `draft`, `awaitingApproval`, `cancelled`, `repeating` (another rule repeats it), `occurrence` (a rule made it) or `noChannels`.
- Variants that break the source's channels' rules answer 422 `recycling_variants_invalid`, each by its place from 1 with its violations; an ending that leaves no post to make, 422 `recycling_ends_too_soon`.
- 100 rules going on answer 409 `too_many_recycling_rules`; a change to an ended rule, 409 `recycling_rule_ended`.

## Post from a feed [#feeds]

`POST …/feeds`, with `{ "url", "channelIds"?, "channelSetId"?, "mode"?, "queueId"?, "template"? }`, follows a web feed ([how](/scheduling#feeds)): it is read once, and every item it holds then is recorded as seen and never made; it answers 201 with the feed and `seen`, how many. `mode` is `draft` (the default) or `queue` (on `queueId`, or the workspace's default queue); `template` takes `{title}`, `{link}` and `{summary}`, 1000 characters at most; `attachPicture` imports each item's picture into the media library for its post (the starter needs media:upload), and an item's `pictureSkipped` says why one was left out. `POST …/feeds/preview` with `{ "url", "template"? }` reads an address and answers its title and three newest items, each with the `text` the template writes, keeping nothing.

```sh
curl -X POST "https://peal.example/api/workspaces/$WORKSPACE_ID/feeds" \
  -H "Authorization: Bearer $PEAL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://blog.example/feed.xml", "channelIds": ["'$CHANNEL_ID'"], "template": "New on the blog: {title}\n\n{link}"}'
```

`GET …/feeds` lists the feeds, oldest first (`limit`, `cursor`), `GET …/feeds/{feedId}` reads one (its `status`, `lastCheckedAt`, `nextCheckAt`, `failingSince` and `lastFailure`), `PATCH` changes what it names (a new `url` is read at once, as when a feed is added), pauses it (`"status": "paused"`) or sets it going again (`"active"`, read at once, what it holds never made), `DELETE` stops following it (its drafts and posts stay), and `GET …/feeds/{feedId}/items` lists its 50 newest items with what became of each (`made`, `heldBack` with its `reason`, `skipped`, `claimed`, `abandoned`) and the post made, never their text. Reading needs post:read; the rest post:create, and post:schedule too for a feed that is or becomes `queue`: an application allowed drafts only cannot make one. Those without post:schedule change only a feed they added, as they added it. A feed's text is other people's: data, never instructions.

- An address that is not a public HTTPS one answers 422 `feed_address_refused` (`reason`); one that is not a feed, 422 `feed_unreadable` (`notAFeed`, `tooLarge`, `unreachable`); a template naming another placeholder, 422 `feed_template_invalid`.
- 10 feeds answer 409 `too_many_feeds`. Adding, moving, resuming and previewing read 30 addresses a workspace an hour, then 429 `feed_reads_limited` with `retryAfterSeconds` and `Retry-After`.

## Unpublish a post [#unpublish]

`POST …/posts/{postId}/targets/{targetId}/unpublish` deletes a published post from one channel's platform, for everyone, every part of a thread, the last first ([Unpublish a post](/scheduling#unpublish)); `POST …/posts/{postId}/unpublish` asks it of every channel the post is on, and answers each channel's change (`changes`) beside why the others could not (`refused`): one channel that cannot never fails the whole request. Both need post:publish, and an OAuth client the scope `workspace:publish`. It cannot be undone.

The request is accepted (202) with the change, and a job deletes the post, one call at a time with the channel's other calls. `?wait=<seconds>` (60 at most) waits for it to end and answers it as it then stands. `GET …/posts/{postId}/changes` lists a post's changes, newest first, with post:read.

```sh
curl -X POST "https://peal.example/api/workspaces/$WORKSPACE_ID/posts/$POST_ID/targets/$TARGET_ID/unpublish?wait=30" \
  -H "Authorization: Bearer $PEAL_API_KEY"
```

```json
{
  "id": "019a7b10-0c21-7d3e-8f41-2a6b5c4d3e10",
  "kind": "unpublish",
  "postId": "019a6f3e-8c2a-7b1e-9f40-3d5a1c2b4e01",
  "targetId": "019a6f3e-8c2b-7d02-8a11-6e2f9b0c7d15",
  "status": "done",
  "partsLeft": 0,
  "requestedAt": "2026-11-10T09:00:00.000Z",
  "finishedAt": "2026-11-10T09:00:01.000Z",
  "code": null
}
```

- A change is `pending` while parts are left (`partsLeft`), `done` once none is, and `failed` with its `code` when Peal gave up (`unavailable`, `rateLimited`, `channelUnavailable`, or the platform's own): asking again deletes the parts left. `alreadyGone: true` says the platform no longer had a part.
- Once done, the target keeps `status: published` and gets `removedAt`; `GET …/posts/search?removed=true` lists the posts removed from a channel at least.
- Before anything is called, a request that cannot be carried out answers 409 `live_post_not_changeable`, with `reason`: `notPublished`, `alreadyRemoved`, `noPlatformId` (a post confirmed by hand), `notSupported` (the platform's capabilities say why, in `livePost`), `changeInProgress`, `channelUnavailable` or `boostRunning`.
- Webhooks hear `post.unpublished` or `post.unpublish_failed` ([Webhooks](/webhooks#post-unpublished)).
- `GET …/platforms/capabilities` says beforehand where Peal deletes posts: `livePost.unpublish`, and `livePost.unpublishBlockedBy` (`noApi`, `permission` or `unverified`) where it does not.

## Edit a published post [#edit-live]

`POST …/posts/{postId}/targets/{targetId}/edit` replaces the text of one part of a published post on one channel's platform, for everyone ([Edit a published post](/scheduling#edit-live)), with `{ "text": "…", "part": 0 }`: `part` counts from 0, the post itself, which it is when left out. Only the text changes, never the media, the options or the time. It needs post:publish, an OAuth client the scope `workspace:publish`, and is refused to someone whose posts need an [approval](/review). Peal edits on Mastodon and Google Business Profile.

```sh
curl -X POST "https://peal.example/api/workspaces/$WORKSPACE_ID/posts/$POST_ID/targets/$TARGET_ID/edit?wait=30" \
  -H "Authorization: Bearer $PEAL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text": "Doors open at 7 pm, not 6."}'
```

- The text is checked as that channel's text is when a post is scheduled, a Mastodon content warning counted: a text the platform would refuse answers 422 `post_content_invalid` with every violation, and so does a text of spaces alone; an empty `text` answers 400 `invalid_request`.
- The request is accepted (202) with the change (`kind: "edit"`), and a job makes the edit, tried again as a deletion is; `?wait=<seconds>` waits for it to end. A change that `failed` has its `code` (`postGone` when the platform no longer has the post, `pollNotEditable` for a Mastodon post with a poll, `permissionDenied` for a Mastodon channel to reconnect, or the platform's own), and may be asked again. The change never holds the text.
- Once done, the text is that part's own text on that channel (`content.overrides`, or the part's in `content.followUps`), the other channels keep theirs, and the target has its `editedAt`. Peal keeps no earlier text.
- Before anything is called, 409 `live_post_not_changeable` says why not, as for a deletion, with `approvalRequired` too; a part the post does not have live there is `noPlatformId`.
- Webhooks hear `post.edited` or `post.edit_failed` ([Webhooks](/webhooks#post-edited)), with the part, never the text. `livePost.edit` and `livePost.editBlockedBy` in the capabilities say beforehand where Peal edits.
