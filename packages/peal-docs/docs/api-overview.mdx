The web app, the command line and the MCP endpoint are built on the same HTTP API, so anything they do, your own code can do too.

[API conventions](/api-conventions) describes what every endpoint shares: request ids, the format of errors and every error code, paging, idempotency, rate limits, and how the API changes over time.

<Callout type="note" title="The API only grows">
  Fields, operations, values and errors are added; none is renamed, removed or
  made stricter. Write clients that ignore what they do not know
  ([Versioning](/api-conventions#versioning)).
</Callout>

## One contract [#contract]

The API is defined once, in the `peal-contract` package. The server implements that definition, the clients derive their types from it, and the [API reference](/reference) in these docs is generated from it, so the three cannot drift apart.

## Base URL [#base-url]

Requests go to the address you open Peal at, and every endpoint's path starts with `/api`: the web app forwards `/api/*` to the server. In these docs, `https://api.example.com` stands for that address; replace it with your own.

```bash
curl -i https://api.example.com/api/health
```

## Authentication [#authentication]

Apart from the health checks and the documents platforms read about Peal, every endpoint needs one of these:

- **An API key**, for scripts and integrations: send it as `Authorization: Bearer peal_…`. A key belongs to one workspace and holds some of the permissions of the member who created it, never more: a key without `post:schedule` neither schedules nor publishes. Members who may manage keys (owners and admins) create one with `POST /api/workspaces/{workspaceId}/api-keys` while signed in, and see the key only in that answer. A key may send 600 requests a minute ([Rate limits](/api-conventions#rate-limits)).
- **A partner key**, for a product that uses Peal for its own customers: send it as `Authorization: Bearer peal_partner_…`. It belongs to a partner account, creates and reads the workspaces that account owns under `/api/partner`, and acts inside each of them, and in no other workspace, with the permissions it was given ([Embedding Peal](/embedding)).
- **An OAuth access token**, which the [command line](/cli) and [MCP clients](/mcp) obtain when you sign them in, sent the same way. It acts as you, limited to what you agreed to: `workspace:read` reads, `workspace:write` does what your role allows but what puts posts out, and `workspace:publish` schedules and publishes ([What each permission allows](/agents#scopes)). Every endpoint that needs `post:schedule` needs `workspace:publish` from an OAuth token, and answers 403 without it.
- **The session cookie** of the web app, for the web app itself. A request that changes something with it must come from the web app's own origin.

With a session or an OAuth token, `GET /api/me` tells who you are, and lists your workspaces, with your role and permissions in each. An API key belongs to a workspace, not to a person, and gets 403 there.

## Workspaces [#workspaces]

A workspace's resources live under `/api/workspaces/{workspaceId}/`: `channels`, `posts`, `media`, `assistant`, `analytics`, `billing`, `webhooks`, `activity` and `api-keys`; `DELETE /api/workspaces/{workspaceId}` deletes the workspace itself, with everything in it ([Workspaces and your account](/settings#delete-workspace)). Each endpoint's reference names the permission it needs, such as `post:schedule` or `channel:connect`.

| Status | Meaning                                                                        |
| ------ | ------------------------------------------------------------------------------ |
| 401    | No credentials, or credentials that no longer work.                            |
| 403    | The credentials work, but do not allow this request, or the account is banned. |
| 404    | No such resource, or a workspace the caller does not belong to.                |

`POST /api/workspaces/{workspaceId}/posts/send` creates a post and sends it in one request, now or at an instant; `POST /api/workspaces/{workspaceId}/media/import` has the server fetch an image or a video from a public HTTPS address into the workspace's media. Sent with an `Idempotency-Key` header, a `send` request is safe to send again: within 24 hours, the same key with the same body answers the post the first request made, and another body answers 409 `IdempotencyKeyReused`. [Posting from an AI agent](/agents#api) shows both.

A script can also check a post without making it (`POST …/posts/validate`), wait for the outcome of a post that goes out now (`send?wait=30`, `GET …/posts/{postId}/outcome`), send up to 50 posts in one request (`POST …/posts/bulk`), import posts from a CSV file (`POST …/posts/import`) and list posts with filters (`GET …/posts/search`). A post made in one call whose content already goes to one of its channels less than 23 hours from its time answers 409 `DuplicatePost`, unless it says `allowDuplicate: true`. [Posting through the API](/posting-api) shows each with an example.

Errors answer with a JSON body in one format: a stable `code`, such as `post_content_invalid` or `connect_failed`, the same name as `_tag` (`PostContentInvalid`) for clients generated from the contract, a `message` for people, the `requestId`, and the details the reference lists. [Errors](/api-conventions#errors) describes it, and [Error codes](/api-conventions#error-codes) lists every code. The writing assistant's endpoints also answer 429 once the workspace has used its requests for the day, 503 when the instance has no AI provider, and 502 when the provider gave no answer the assistant could use. On an instance that bills, connecting a channel, scheduling a post or starting an upload the workspace's plan has no room for answers 402 `PlanLimitReached`, which names the `limit` (`channels`, `members`, `scheduledPosts`, `assistantRequests` or `mediaStorage`, in bytes) and what the plan `allowed` ([Plans and billing](/billing#limits)); `GET /api/workspaces/:workspaceId/billing` shows the plan, its allowances and the workspace's usage.

## Partner accounts [#partner]

A partner account owns one workspace for each customer of a product built on Peal. `/api/partner` answers its partner keys only: `GET /api/partner` reads the account and what it holds, and `/api/partner/workspaces` creates, lists, finds by `externalId`, changes and deletes its workspaces. A partner key then calls `/api/workspaces/{workspaceId}/…` for a workspace its account owns, and gets 404 for any other. `POST /api/workspaces/{workspaceId}/connect-links` answers a hosted, single-use link where the owner of a social account connects it without a Peal account. [Embedding Peal](/embedding) walks through the whole flow.

## Webhooks [#webhooks]

Rather than asking the API again and again, have Peal call your server when something happens in a workspace: a post went out or failed, a channel must be reconnected, a file is ready. Members who may manage webhooks (owners and admins), and API keys given that permission, add endpoints under `/api/workspaces/{workspaceId}/webhooks`. [Webhooks](/webhooks) lists every event with its schema, and tells how deliveries are signed, retried and verified.

## The activity log [#activity]

`GET /api/workspaces/{workspaceId}/activity` lists the requests that asked to change something in the workspace: who asked, through which key or application, which operation, and how it was answered. It needs `activity:read`, which owners hold ([The activity log](/settings#activity)).

## Your account [#me]

What belongs to you rather than to a workspace lives under `/api/me`: who you are (`GET /api/me`), your [notifications](/notifications#api) under `/api/me/notices`, and which of them are emailed, under `/api/me/notification-preferences`. The notification endpoints answer 403 to API keys, which belong to a workspace, and to OAuth tokens bound to one workspace, such as an MCP client's.

A copy of your data (`GET /api/me/export`), deleting your account (`DELETE /api/me`) and your connected applications (`/api/me/connected-apps`) answer only your own session in the web app: API keys, OAuth tokens and staff acting as you get 403 ([Workspaces and your account](/settings#api)).

## OpenAPI document [#openapi]

The OpenAPI 3.1 document of the API is public at `/api/openapi.json`, at the address you open Peal at, such as `https://api.example.com/api/openapi.json`. Use it to generate a client in another language or to import the API into an HTTP tool. The server also answers it at `/openapi.json` on its own address, such as `http://localhost:3000/openapi.json` for a server running from source, which the web app does not forward.

The API catalogue at `/.well-known/api-catalog` (RFC 9727) points programs to that document, to the [MCP endpoint](/mcp) and to where each gets a credential ([Discovery](/api-conventions#discovery)). `GET /api/changelog` lists what each release of the API added ([Changelog](/api-conventions#changelog)).
