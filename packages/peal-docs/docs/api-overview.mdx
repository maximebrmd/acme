The web app, the command line and the MCP endpoint are built on the same HTTP API, so anything they do, your own code can do too.

<Callout type="warning" title="Not stable yet">
  The API changes with every commit until the first release. Expect endpoints to
  be added, renamed and removed.
</Callout>

## One contract [#contract]

The API is defined once, in the `peal-contract` package. The server implements that definition, the clients derive their types from it, and the [API reference](/reference) in these docs is generated from it, so the three cannot drift apart.

## Base URL [#base-url]

Requests go to the address you open Peal at, and every endpoint's path starts with `/api`: the web app forwards `/api/*` to the server. In these docs, `https://api.example.com` stands for that address; replace it with your own.

```bash
curl -i https://api.example.com/api/health
```

## Authentication [#authentication]

Apart from the health checks and the documents platforms read about Peal, every endpoint needs one of these:

- **An API key**, for scripts and integrations: send it as `Authorization: Bearer peal_…`. A key belongs to one workspace and holds some of the permissions of the member who created it, never more. Members who may manage keys (owners and admins) create one with `POST /api/workspaces/{workspaceId}/api-keys` while signed in, and see the key only in that answer. A key may send 600 requests a minute.
- **An OAuth access token**, which the [command line](/cli) and [MCP clients](/mcp) obtain when you sign them in, sent the same way. It acts as you, limited to what you agreed to.
- **The session cookie** of the web app, for the web app itself. A request that changes something with it must come from the web app's own origin.

With a session or an OAuth token, `GET /api/me` tells who you are, and lists your workspaces, with your role and permissions in each. An API key belongs to a workspace, not to a person, and gets 403 there.

## Workspaces [#workspaces]

A workspace's resources live under `/api/workspaces/{workspaceId}/`: `channels`, `posts`, `media`, `assistant`, `analytics`, `billing` and `api-keys`; `DELETE /api/workspaces/{workspaceId}` deletes the workspace itself, with everything in it ([Workspaces and your account](/settings#delete-workspace)). Each endpoint's reference names the permission it needs, such as `post:schedule` or `channel:connect`.

| Status | Meaning                                                                        |
| ------ | ------------------------------------------------------------------------------ |
| 401    | No credentials, or credentials that no longer work.                            |
| 403    | The credentials work, but do not allow this request, or the account is banned. |
| 404    | No such resource, or a workspace the caller does not belong to.                |

Errors answer with a JSON body whose `_tag` names the error, such as `PostContentInvalid` or `ConnectFailed`, with the details the reference lists. The writing assistant's endpoints also answer 429 once the workspace has used its requests for the day, 503 when the instance has no AI provider, and 502 when the provider gave no answer the assistant could use. On an instance that bills, connecting a channel, scheduling a post or starting an upload the workspace's plan has no room for answers 402 `PlanLimitReached`, which names the `limit` (`channels`, `members`, `scheduledPosts`, `assistantRequests` or `mediaStorage`, in bytes) and what the plan `allowed` ([Plans and billing](/billing#limits)); `GET /api/workspaces/:workspaceId/billing` shows the plan, its allowances and the workspace's usage.

## Your account [#me]

What belongs to you rather than to a workspace lives under `/api/me`: who you are (`GET /api/me`), your [notifications](/notifications#api) under `/api/me/notices`, and which of them are emailed, under `/api/me/notification-preferences`. The notification endpoints answer 403 to API keys, which belong to a workspace, and to OAuth tokens bound to one workspace, such as an MCP client's.

A copy of your data (`GET /api/me/export`), deleting your account (`DELETE /api/me`) and your connected applications (`/api/me/connected-apps`) answer only your own session in the web app: API keys, OAuth tokens and staff acting as you get 403 ([Workspaces and your account](/settings#api)).

## OpenAPI document [#openapi]

The server publishes its OpenAPI 3.1 document at `/openapi.json` on its own address, such as `http://localhost:3000/openapi.json` for a server running from source; the web app does not forward it. Use it to generate a client in another language or to import the API into an HTTP tool.

## Reference [#reference]

The [API reference](/reference) has a page for each endpoint, grouped by tag, with its parameters, request and response schemas, and code samples.
