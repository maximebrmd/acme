Peal keeps images and videos in any S3-compatible store. Browsers upload to the bucket directly, so the bucket needs an upload rule as well as the server's settings.

## Media storage [#media-storage]

| Setting                                                                                    | Required | What it does                                                                                   |
| ------------------------------------------------------------------------------------------ | -------- | ---------------------------------------------------------------------------------------------- |
| `PEAL_S3_ENDPOINT`, `PEAL_S3_BUCKET`, `PEAL_S3_ACCESS_KEY_ID`, `PEAL_S3_SECRET_ACCESS_KEY` | Yes      | The store, the bucket and the key. The server's key needs only to read and write objects.      |
| `PEAL_MEDIA_PUBLIC_BASE_URL`                                                               | No       | The bucket's public address, if it is also served publicly (see [Public links](#public-links)) |

[Environment variables](/self-hosting/environment-variables#media) lists the other media settings, with their defaults.

### On Cloudflare R2 in the EU [#r2-eu]

To keep media in the EU on Cloudflare R2, create the bucket in R2's EU jurisdiction, in the dashboard or with Wrangler:

```sh
wrangler r2 bucket create <name> --jurisdiction eu
```

Then reach it at the `.eu.` endpoint, `https://<account>.eu.r2.cloudflarestorage.com`, in `PEAL_S3_ENDPOINT`. Wrangler's other bucket commands need `--jurisdiction eu` too. The same goes for a backup bucket, whose endpoint is a host without a scheme.

<Callout type="warning" title="The jurisdiction is for good">
  A bucket's jurisdiction cannot be changed later.
</Callout>

### The upload rule [#cors]

Browsers send media straight to the bucket, with requests the server signs. The bucket must let the web app's origin send them: a CORS rule that allows `PUT` from that origin with the `Content-Type` and `If-None-Match` headers.

With the server's variables set, and `PUBLIC_URL` and `TRUSTED_ORIGINS` naming the web app's origins, this command puts the rule on the bucket, keeping its other rules:

```sh
bun nx run peal-server:media-cors
```

It also prints the same policy for Cloudflare R2's dashboard (R2 › the bucket › Settings › CORS policy). Running it again changes nothing. Its access key must be allowed to change the bucket's settings.

### Unfinished uploads [#multipart]

Large videos go up in parts. An upload left unfinished keeps its parts in the store until something aborts it. The server sweeps the media folder every hour, on one server at a time:

- an upload never completed is deleted, its media and its file, a day after it started (`PEAL_MEDIA_SWEEP_PENDING_AFTER`);
- a multipart upload left open is aborted a day after it started (`PEAL_MEDIA_SWEEP_UPLOADS_AFTER`);
- a file under `media/` that no media holds, such as one sent with a link signed before its media was deleted, is deleted once it is a day old (`PEAL_MEDIA_SWEEP_ORPHANS_AFTER`);
- the files of a deleted workspace that the store did not delete at once are deleted again until none is left.

Each run deletes 500 of each at most (`PEAL_MEDIA_SWEEP_BATCH`) and leaves the rest to the next; a file the store refuses to delete is counted and left. They touch only keys under `media/` that Peal writes, below `PEAL_S3_KEY_PREFIX`, never the erasure ledger or another instance's prefix. A sweep that keeps failing raises the `peal-media-sweep-failing` alert.

The sweeps run in production only, unless `PEAL_MEDIA_SWEEPS` says otherwise. `off` stops them all.

#### Which database the folder belongs to [#media-owner]

The pending and orphan sweeps delete what the database does not know of, so they need the database to be the bucket's newest truth:

- The first run writes `media/.owner`, naming the database by a random id it keeps. From then on, those two sweeps run only while the marker names this database. They stop, deleting nothing, when it names another, or when it is gone. A second server pointed at the same bucket and prefix with a database of its own is stopped this way.
- A restore keeps the database's id, so the marker cannot tell a restored database from the one it was. Turn the sweeps off (`PEAL_MEDIA_SWEEPS=off`) before starting a server on a restored database, and keep them off until the restore is final. As a last guard, the orphan sweep stops without deleting when a page of the listing holds more files the database does not know of than `PEAL_MEDIA_SWEEP_ORPHANS_LIMIT` (100), or than a fifth of 50 old files or more.
- Each stop raises the `peal-media-sweep-refused` alert. When the database is meant to own the folder (a new server's database restored from backups, once the restore is final), hand the folder over once:

```sh
docker compose … run --rm --no-deps server packages/peal-server/src/claim-media-folder.ts
```

It writes the marker naming this database, whatever it named, and changes nothing else.

As a second guard, add a lifecycle rule that aborts incomplete multipart uploads, on the media folder alone. Put the rule's prefix before `media/` when you set `PEAL_S3_KEY_PREFIX`, such as `staging/media/`. With Cloudflare R2, whose buckets also abort them after seven days by default (add `--jurisdiction eu` for a bucket in the EU jurisdiction):

```sh
wrangler r2 bucket lifecycle add <bucket> abort-unfinished-uploads media/ --abort-multipart-days 2
```

With an S3 API, where the store supports lifecycle rules, save the rule as `lifecycle.json`:

```json
{
  "Rules": [
    {
      "ID": "abort-unfinished-uploads",
      "Status": "Enabled",
      "Filter": { "Prefix": "media/" },
      "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 2 }
    }
  ]
}
```

and put it on the bucket (add `--endpoint-url` for a store other than AWS):

```sh
aws s3api put-bucket-lifecycle-configuration --bucket <bucket> --lifecycle-configuration file://lifecycle.json
```

<Callout type="warning" title="One configuration per bucket">
  On an S3 API, this replaces every lifecycle rule the bucket had, the erasure
  ledger's included: put them all in the same file. Never add an expiration to
  `media/`, which would delete media in use.
</Callout>

### Reading the files [#probe]

Once a file is stored, the server reads it: an image's dimensions with sharp, a video's dimensions, duration and codec with ffprobe, which the server's image ships. A video uploaded to a server without ffprobe stays uploaded, marked as unread, until it is completed again on a server that has it.

### Public links [#public-links]

Pages show media through short-lived signed links. If the bucket is also served publicly, as through an R2 custom domain, set `PEAL_MEDIA_PUBLIC_BASE_URL` to that address, and links to media use it instead.
