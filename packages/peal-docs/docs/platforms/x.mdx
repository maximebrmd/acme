## Connect [#connect]

Under **X**, choose **Connect X**, sign in on X and allow Peal. It asks to:

- read and write posts;
- upload media;
- stay connected, so it can renew its access without you.

**Channels** offers X once the Peal server is set up for it (see [On your own server](#self-hosting)).

### How X counts length [#length]

X counts a post's length its own way, and Peal counts the same, so a post it accepts fits on X (see [Length on each channel](/guides/posts#write)):

- A link counts 23 characters whatever its length, written with `https://` or without, as `peal.social` (a domain X knows, so not `localhost`).
- An emoji, or a character outside the Latin, Greek and Cyrillic scripts, counts 2.

## Options [#options]

No option is required, and each is sent only when you choose it. **API name** is the option's name through the API. **Parts** says what it applies to in a [thread](/guides/posts#threads).

| Option                        | API name             | Values                                                   | Left out                | Parts                             |
| ----------------------------- | -------------------- | -------------------------------------------------------- | ----------------------- | --------------------------------- |
| **Who can reply**             | `replySettings`      | `following`, `mentionedUsers`, `subscribers`, `verified` | Everyone                | The first part                    |
| **Community**                 | `communityId`        | The community's number, digits only                      | The account's followers | The first part                    |
| **Also share with followers** | `shareWithFollowers` | Yes or no; only with a community                         | No                      | The first part                    |
| **Paid partnership**          | `paidPartnership`    | Yes or no                                                | No                      | Every part                        |
| **Made with AI**              | `madeWithAi`         | Yes or no                                                | No                      | Every part with images or a video |

X does not document which accounts may use each of these. When X refuses a post that carries them:

| X's answer                                                 | The channel reads                                                                                        | What to do                           |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| Names one of the options (the field, or the community)     | **Failed**, with the code `optionRefused`                                                                | Change the options and post it again |
| Refuses it for anything else, such as a restricted account | X's own problem type, as for a post without options (`client-forbidden`, or `http403` when X names none) | Changing the options will not help   |

With `optionRefused`, Peal does not send the post again. X's message is not kept, so the channel does not say which option X refused.

## Comments [#comments]

Peal does not read comments on X yet.

## On Peal Cloud: billed at X's rates [#billing]

X bills each call to its API, and on Peal Cloud Peal passes it on at X's published rates, with nothing added ([X, at X's rates](/guides/workspace/billing#x)). So:

- an X account is connected only once the billing account has a payment method on per-account pricing;
- each post sent to X, each part of a thread, is billed at X's rate for a post ({{x-post-en}}), or for a post with a link ({{x-post-link-en}});
- X's counts and followers are read only once a member who manages billing turns X's reads on for the workspace, on the billing page, each read billed at X's rate, once a UTC day;
- the billing account's monthly ceiling for X bounds all of it: a thread with no room for all its parts is not sent at all, and the composer says so before; room can still be taken between its parts (another post or X channel of the account, X's reads), and the thread is then cut there.

A post refused for billing fails without being sent (`paymentMethodRequired`, `paymentFailed`, `perAccountPricingRequired`, `xCeilingReached`), and a thread cut part way says where (`xThreadCut`). A server you run yourself bills nothing for X.

## On your own server [#self-hosting]

A self-hosted server offers X once its app is registered: see [X](/self-hosting/platforms#x). Until then, **Channels** does not offer it.
