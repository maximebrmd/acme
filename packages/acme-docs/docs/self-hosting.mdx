Acme reaches every outside service through a port with a self-hostable default, so a self-hosted instance needs only two services of its own: Postgres and an S3-compatible object store. Everything else is optional and stays off until you configure it.

<Callout type="warning" title="Before the first release">
  Acme has not been released yet, and there are no published images to run. This
  page describes the self-hosting model the code follows. Variables that are not
  listed below are not settled yet, and every value shown is an example.
</Callout>

## Services [#services]

| Service        | Needed   | What Acme uses it for                                                                                               | Options                                                                            |
| -------------- | -------- | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Postgres       | Yes      | All data, and the durable jobs that publish posts, refresh platform tokens and pull analytics. Acme needs no Redis. | Any Postgres server                                                                |
| Object storage | Yes      | Uploaded media                                                                                                      | Any S3-compatible API                                                              |
| Email          | Optional | Email notifications                                                                                                 | Resend, or any SMTP server                                                         |
| Billing        | Optional | Plans and subscriptions                                                                                             | Stripe. Without a key, billing is off and no plan limits apply.                    |
| Captcha        | Optional | Bot protection                                                                                                      | Cloudflare Turnstile. Without a key, the captcha is off.                           |
| AI             | Optional | AI features                                                                                                         | Any OpenAI-compatible endpoint, or an Anthropic API key                            |
| Telemetry      | Optional | Logs, metrics and traces                                                                                            | Any OpenTelemetry (OTLP) collector. Nothing is exported unless an endpoint is set. |

Acme's own deployment stores media on Cloudflare R2, and its development stack runs SeaweedFS for storage and Mailpit for email. A self-hosted instance can use any of these, or any other store and mail server that speaks the same protocols.

## Environment variables [#environment-variables]

The server and the web app read plain environment variables, so their images run on any host. The variables they read today follow.

### Server [#server]

| Variable                      | Default       | Example                                   | What it does                                                                                                                              |
| ----------------------------- | ------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                | none          | `postgres://acme:acme@postgres:5432/acme` | The Postgres database. Required: the server does not start without it.                                                                    |
| `PORT`                        | `3000`        | `8080`                                    | The port the HTTP server listens on.                                                                                                      |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | unset         | `http://otel-collector:4318`              | The OTLP/HTTP endpoint of the OpenTelemetry collector that receives logs, metrics and traces. Unset, nothing is exported.                 |
| `OTEL_SERVICE_NAME`           | `acme-server` | `acme-sandbox`                            | The service name that telemetry is reported under.                                                                                        |
| `OTEL_TRACES_EXPORTER`        | `otlp`        | `none`                                    | `none` stops exporting traces once an endpoint is set. `OTEL_METRICS_EXPORTER` and `OTEL_LOGS_EXPORTER` do the same for metrics and logs. |

At startup, the server applies the database migrations it has not applied yet, and only listens once they are done.

The server exports telemetry as JSON over HTTP, so point the endpoint at the collector's OTLP/HTTP port, 4318 by default, rather than its gRPC one. It also reads these OpenTelemetry variables, and no others (`OTEL_EXPORTER_OTLP_PROTOCOL` included):

- `OTEL_EXPORTER_OTLP_HEADERS`, `OTEL_EXPORTER_OTLP_COMPRESSION` and `OTEL_EXPORTER_OTLP_TIMEOUT`, and the per-signal forms of these and of the endpoint, such as `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`;
- `OTEL_RESOURCE_ATTRIBUTES` and `OTEL_SERVICE_VERSION`;
- `OTEL_SDK_DISABLED`;
- the batching settings `OTEL_BSP_*` for traces and `OTEL_BLRP_*` for logs;
- `OTEL_METRIC_EXPORT_INTERVAL`, `OTEL_METRIC_EXPORT_TIMEOUT` and `OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE`.

### Web app [#web-app]

| Variable       | Default                                               | Example                   | What it does                                                                                                       |
| -------------- | ----------------------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `ACME_API_URL` | none in production, `http://localhost:3000` otherwise | `http://acme-server:3000` | Where the web app reaches the server. It forwards the browser's `/api/*` requests there and renders pages with it. |
| `PORT`         | `3000`                                                | `8080`                    | The port the web app listens on.                                                                                   |

The command-line tool reads `ACME_API_URL` too, unless `--api-url` is given.

The variables for storage, email, billing, captcha and AI will be listed here as each adapter ships.

## In front of Acme [#reverse-proxy]

Run a reverse proxy that terminates TLS, such as Caddy, in front of the server, and expose only the proxy.

The server answers two probes:

- `GET /health` answers `204 No Content` as soon as the server is up, whatever the state of its database, which suits a container health check.
- `GET /ready` answers `204 No Content` when the database answers as well, and `503 Service Unavailable` with a `DatabaseUnavailable` error when it does not, so a load balancer can hold traffic back until then.
