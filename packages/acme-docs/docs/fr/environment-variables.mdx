Le serveur, l’application web et la ligne de commande lisent de simples variables d’environnement : ils tournent sur n’importe quel hôte. Cette page liste chacune de celles qu’ils lisent. Les valeurs indiquées sont des exemples.

Le serveur tourne en mode production quand `NODE_ENV` vaut `production`, comme son image le définit. Les réglages marqués « obligatoire en production » n’y ont pas de valeur par défaut, et le serveur refuse de démarrer sans eux. Ailleurs, ils valent par défaut l’environnement de développement : un serveur lancé depuis les sources n’a besoin que de `DATABASE_URL`.

## Serveur [#server]

### Essentiel [#core]

| Variable                 | Par défaut                                          | Rôle                                                                                                                                                                                                                                                                                                                          |
| ------------------------ | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`           | aucune : obligatoire                                | La base de données Postgres, comme `postgres://acme:secret@postgres:5432/acme`. Connectez-vous directement ou par un pooler en mode session, jamais en mode transaction.                                                                                                                                                      |
| `PUBLIC_URL`             | obligatoire en production ; `http://localhost:3001` | L’adresse où l’on ouvre Acme : l’application web, comme `https://acme.example.com`. Les liens des e-mails, la connexion, les retours des plateformes et l’adresse du point d’accès MCP sont construits depuis son origine. Les clients MCP ne se connectent que si elle est en HTTPS, ou sur un hôte local comme `localhost`. |
| `NODE_ENV`               | `development`                                       | `production` active le mode production : réglages obligatoires, limites de débit de la connexion, et aucune valeur par défaut de développement.                                                                                                                                                                               |
| `PORT`                   | `3000`                                              | Le port d’écoute du serveur HTTP.                                                                                                                                                                                                                                                                                             |
| `HOSTNAME`               | `acme-server`                                       | Le nom du serveur parmi les exécuteurs de tâches enregistrés dans la base. Chaque processus serveur a besoin du sien ; Docker y met l’identifiant du conteneur.                                                                                                                                                               |
| `ACME_CLUSTER_RETENTION` | `30 days`                                           | Combien de temps les traces des tâches terminées, comme celle d’une publication diffusée, sont gardées avant qu’un nettoyage quotidien les supprime, en durée anglaise comme `7 days`. Les tâches encore en attente sont toujours gardées.                                                                                    |

### Connexion [#sign-in]

| Variable                          | Par défaut                                             | Rôle                                                                                                                                                                                                                                                                                                                                        |
| --------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BETTER_AUTH_SECRET`              | obligatoire en production ; un secret de développement | Le secret qui signe les sessions et chiffre ce que la connexion stocke : au moins 32 caractères aléatoires, comme `openssl rand -base64 32`. Qui le connaît peut se connecter à la place de n’importe qui. Gardez-le secret.                                                                                                                |
| `BETTER_AUTH_SECRETS`             | non définie                                            | Pour changer de secret : des entrées `version:secret` séparées par des virgules, la plus récente en tête, comme `2:<nouveau>,1:<ancien>`. Lue par Better Auth lui-même : quand elle est définie, le secret de la première entrée sert, et les autres, avec `BETTER_AUTH_SECRET`, déchiffrent encore ce que les anciens secrets ont chiffré. |
| `AUTH_IP_HEADERS`                 | obligatoire en production ; `x-forwarded-for`          | Les en-têtes, séparés par des virgules, qui portent l’adresse du client, que les limites de débit de la connexion comptent. Ne nommez qu’un en-tête que votre frontal définit en remplaçant celui du client : `cf-connecting-ip` derrière Cloudflare, `x-forwarded-for` derrière Caddy. Voir [Devant Acme](/self-hosting#reverse-proxy).    |
| `AUTH_TRUSTED_PROXIES`            | aucune                                                 | Les adresses ou plages CIDR, séparées par des virgules, des proxies qui ajoutent à `X-Forwarded-For`. L’adresse du client est alors lue depuis la droite, après eux.                                                                                                                                                                        |
| `TRUSTED_ORIGINS`                 | aucune                                                 | Les origines, en plus de `PUBLIC_URL` et séparées par des virgules, autorisées à envoyer des requêtes connectées qui changent quelque chose. `media-cors` les laisse aussi importer des médias.                                                                                                                                             |
| `AUTH_REQUIRE_EMAIL_VERIFICATION` | `true`                                                 | `false` permet de se connecter avant d’avoir confirmé son adresse e-mail.                                                                                                                                                                                                                                                                   |
| `AUTH_DB_POOL_MAX`                | `5`                                                    | Combien de connexions à la base ouvre la connexion des utilisateurs, en plus des 10 du serveur.                                                                                                                                                                                                                                             |
| `MCP_DYNAMIC_REGISTRATION`        | `false`                                                | `true` laisse les clients MCP s’enregistrer eux-mêmes, ce dont la plupart ont besoin avant de se connecter. N’importe qui peut alors enregistrer un client sous n’importe quel nom ; la page de consentement indique qu’Acme ne l’a pas vérifié.                                                                                            |

Better Auth lit aussi `BETTER_AUTH_TRUSTED_ORIGINS`, qui ajoute des origines comme `TRUSTED_ORIGINS`. Préférez `TRUSTED_ORIGINS`, que `media-cors` lit aussi.

### E-mail [#email]

| Variable         | Par défaut                                                                 | Rôle                                                                                                                                                                                                                               |
| ---------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MAIL_FROM`      | obligatoire en production ; `Acme <noreply@acme.localhost>`                | L’expéditeur, comme `Acme <noreply@example.com>` ou une adresse depuis laquelle votre service de messagerie peut envoyer.                                                                                                          |
| `RESEND_API_KEY` | non définie                                                                | Envoie les e-mails par l’API de Resend. Gardez-la secrète.                                                                                                                                                                         |
| `SMTP_URL`       | obligatoire en production sans `RESEND_API_KEY` ; `smtp://127.0.0.1:11025` | Le serveur SMTP, comme `smtp://utilisateur:motdepasse@mail.example.com:587`, ou `smtps://` pour du TLS dès le premier octet. Sert quand `RESEND_API_KEY` n’est pas définie. Gardez-la secrète quand elle contient un mot de passe. |

### Canaux [#channels]

| Variable              | Par défaut  | Rôle                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ACME_TOKEN_KEYS`     | non définie | Les clés qui chiffrent les jetons des canaux connectés : des entrées `idDeClé:clé` séparées par des virgules, comme `k2:<clé>,k1:<clé>`, chaque clé faisant 32 octets aléatoires en base64 (`openssl rand -base64 32`). La première clé chiffre et toutes les clés listées déchiffrent. Non définie ou vide, le serveur démarre, et la connexion d’un canal échoue. Une valeur mal formée arrête le serveur au démarrage. Gardez-en une copie : sans les clés, chaque canal doit être reconnecté. |
| `BLUESKY_CLIENT_KEYS` | non définie | Les clés du client Bluesky d’Acme, créées par `bun nx run acme-server:bluesky-key` : des entrées `idDeClé:clé` séparées par des virgules, la première signant. Elles demandent `PUBLIC_URL` en HTTPS sans port. Sans elles, seul un serveur sur `localhost` hors production connecte Bluesky, avec le client de développement. Une valeur mal formée arrête le serveur au démarrage.                                                                                                              |

### Médias [#media]

| Variable                     | Par défaut                                             | Rôle                                                                                                                                                                                                      |
| ---------------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ACME_S3_ENDPOINT`           | obligatoire en production ; `http://127.0.0.1:18333`   | L’URL de l’API S3 qui stocke les médias, comme `https://<compte>.r2.cloudflarestorage.com`.                                                                                                               |
| `ACME_S3_BUCKET`             | obligatoire en production ; `acme-media`               | Le bucket où vont les médias.                                                                                                                                                                             |
| `ACME_S3_ACCESS_KEY_ID`      | obligatoire en production ; la clé de développement    | La clé d’accès du stockage. Gardez-la secrète.                                                                                                                                                            |
| `ACME_S3_SECRET_ACCESS_KEY`  | obligatoire en production ; le secret de développement | Le secret de cette clé. Gardez-le secret.                                                                                                                                                                 |
| `ACME_S3_REGION`             | `auto`                                                 | La région pour laquelle les requêtes sont signées, comme `eu-west-1`. `auto` convient à Cloudflare R2.                                                                                                    |
| `ACME_S3_FORCE_PATH_STYLE`   | `false` en production ; `true` sinon                   | `true` met le bucket dans le chemin de l’URL plutôt que dans son nom d’hôte, comme SeaweedFS le demande.                                                                                                  |
| `ACME_S3_KEY_PREFIX`         | aucune                                                 | Un dossier sous lequel va chaque clé, comme `staging/`, pour que des instances partagent un bucket. Il finit par `/`.                                                                                     |
| `ACME_MEDIA_PUBLIC_BASE_URL` | non définie                                            | L’adresse où le bucket est servi publiquement, s’il l’est, comme `https://media.example.com`. Non définie, les pages lisent les médias par des liens signés de courte durée.                              |
| `ACME_FFPROBE_PATH`          | `ffprobe`                                              | Le programme ffprobe qui lit les dimensions, la durée et le codec d’une vidéo. L’image du serveur en contient un, à `/usr/local/bin/ffprobe`. Sans lui, les vidéos restent importées et ne sont pas lues. |

### Assistant de rédaction [#ai]

| Variable                 | Par défaut                              | Rôle                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------ | --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ACME_AI_PROVIDER`       | non définie : l’assistant est désactivé | `anthropic` pour l’API d’Anthropic, ou `openai-compatible` pour n’importe quel point d’accès qui sert `/chat/completions`, comme un serveur de modèles que vous faites tourner. Non définie ou vide, l’application web masque l’assistant et ses points d’accès répondent `AssistantUnavailable`. Toute autre valeur arrête le serveur au démarrage. |
| `ACME_AI_API_KEY`        | non définie                             | La clé du fournisseur. Obligatoire avec `anthropic` ; avec `openai-compatible`, seulement pour un point d’accès qui en demande une. Gardez-la secrète.                                                                                                                                                                                               |
| `ACME_AI_MODEL`          | `claude-opus-5-5` avec `anthropic`      | Le modèle qu’interroge l’assistant. Obligatoire avec `openai-compatible`.                                                                                                                                                                                                                                                                            |
| `ACME_AI_BASE_URL`       | l’API d’Anthropic                       | L’URL de base de l’API, que suit `/chat/completions`, comme `http://127.0.0.1:8000/v1`. Obligatoire avec `openai-compatible` ; avec `anthropic`, seulement pour passer par un proxy. Le serveur l’appelle directement : elle peut se trouver sur un réseau privé.                                                                                    |
| `ACME_AI_DAILY_REQUESTS` | `100`                                   | Combien de demandes chaque espace de travail peut envoyer à l’assistant par jour UTC, sur une instance qui ne facture pas ; avec la facturation, chaque abonnement fixe la sienne. `0` n’en laisse passer aucune. Une valeur négative ou mal formée arrête le serveur au démarrage.                                                                  |

Un fournisseur nommé sans les réglages qu’il demande arrête le serveur au démarrage, et l’erreur nomme la variable manquante. [Assistant de rédaction](/self-hosting#ai) explique le reste.

### Facturation [#billing]

| Variable                | Par défaut                       | Rôle                                                                                                                                                                                                                |
| ----------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `STRIPE_SECRET_KEY`     | non définie : pas de facturation | La clé d’API Stripe qui facture les espaces de travail, comme `sk_live_…`. Non définie ou vide, il n’y a pas d’abonnement et rien n’est limité. Gardez-la secrète.                                                  |
| `STRIPE_WEBHOOK_SECRET` | obligatoire avec une clé         | Le secret de signature du webhook qui envoie à `PUBLIC_URL/api/auth/stripe/webhook` les événements `customer.subscription.*`, comme `whsec_…`. Définie sans clé, elle arrête le serveur. Gardez-la secrète.         |
| `STRIPE_PRICE_PRO`      | obligatoire avec une clé         | L’identifiant du prix mensuel de l’abonnement Pro, comme `price_…`.                                                                                                                                                 |
| `STRIPE_PRICE_BUSINESS` | obligatoire avec une clé         | L’identifiant du prix mensuel de l’abonnement Business.                                                                                                                                                             |
| `STRIPE_AUTOMATIC_TAX`  | `false`                          | `true` fait calculer la taxe par Stripe Tax au paiement, comme la TVA européenne, d’après l’adresse et le numéro de TVA du client, que le paiement demande alors. Activez d’abord Stripe Tax dans le compte Stripe. |
| `STRIPE_API_URL`        | l’API de Stripe                  | Une autre adresse pour l’API de Stripe, comme `http://127.0.0.1:12111` pour stripe-mock dans les tests.                                                                                                             |

[Facturation](/self-hosting#billing) explique les abonnements et ce qu’ils limitent.

### Captcha [#captcha]

| Variable               | Par défaut                    | Rôle                                                                                                                                                                                                                  |
| ---------------------- | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TURNSTILE_SITE_KEY`   | non définie : pas de captcha  | La clé de site d’un widget Cloudflare Turnstile, que montrent les formulaires d’inscription et de réinitialisation du mot de passe. Définissez-la avec `TURNSTILE_SECRET_KEY` : l’une sans l’autre arrête le serveur. |
| `TURNSTILE_SECRET_KEY` | non définie : pas de captcha  | La clé secrète du widget, avec laquelle le serveur vérifie les jetons. Gardez-la secrète.                                                                                                                             |
| `TURNSTILE_VERIFY_URL` | le `siteverify` de Cloudflare | Une autre adresse où vérifier les jetons, comme une fausse dans les tests.                                                                                                                                            |

### Télémétrie [#telemetry]

| Variable                      | Par défaut    | Rôle                                                                                                                                                                 |
| ----------------------------- | ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | non définie   | L’adresse OTLP/HTTP du collecteur OpenTelemetry qui reçoit les journaux, métriques et traces, comme `http://otel-collector:4318`. Non définie, rien n’est exporté.   |
| `OTEL_SERVICE_NAME`           | `acme-server` | Le nom de service sous lequel la télémétrie est envoyée.                                                                                                             |
| `OTEL_TRACES_EXPORTER`        | `otlp`        | `none` arrête l’export des traces une fois un point d’accès défini. `OTEL_METRICS_EXPORTER` et `OTEL_LOGS_EXPORTER` font de même pour les métriques et les journaux. |

Le serveur exporte la télémétrie en JSON sur HTTP : faites pointer le point d’accès vers le port OTLP/HTTP du collecteur, 4318 par défaut, et non vers son port gRPC. Il lit aussi ces variables OpenTelemetry, et aucune autre (`OTEL_EXPORTER_OTLP_PROTOCOL` comprise) :

- `OTEL_EXPORTER_OTLP_HEADERS`, `OTEL_EXPORTER_OTLP_COMPRESSION` et `OTEL_EXPORTER_OTLP_TIMEOUT`, ainsi que leurs variantes par signal et celles du point d’accès, comme `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` ;
- `OTEL_RESOURCE_ATTRIBUTES` et `OTEL_SERVICE_VERSION` ;
- `OTEL_SDK_DISABLED` ;
- les réglages de regroupement `OTEL_BSP_*` pour les traces et `OTEL_BLRP_*` pour les journaux ;
- `OTEL_METRIC_EXPORT_INTERVAL`, `OTEL_METRIC_EXPORT_TIMEOUT` et `OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE`.

### Exécuteur de tâches [#job-runner]

La bibliothèque qui exécute les tâches d’Acme lit aussi ses propres réglages dans l’environnement, sous ces noms : `SHARDS_PER_GROUP`, `SHARD_GROUPS`, `AVAILABLE_SHARD_GROUPS`, `RUNNER_SHARD_WEIGHT`, `SHARD_LOCK_REFRESH_INTERVAL`, `SHARD_LOCK_EXPIRATION`, `SHARD_LOCK_DISABLE_ADVISORY`, `PREEMPTIVE_SHUTDOWN`, `ENTITY_MAILBOX_CAPACITY`, `ENTITY_MAILBOX_METRICS`, `MAX_RESIDENT_ENTITIES`, `UNPROCESSED_MESSAGE_BATCH_SIZE`, `ENTITY_MAX_IDLE_TIME`, `ENTITY_REGISTRATION_TIMEOUT`, `ENTITY_REPLY_POLL_INTERVAL`, `SEND_RETRY_INTERVAL`, `REFRESH_ASSIGNMENTS_INTERVAL`, `RUNNER_JOIN_DEBOUNCE`, `RUNNER_HEALTH_CHECK_INTERVAL`, `SIMULATE_REMOTE_SERIALIZATION`, `LISTEN_HOST` et `LISTEN_PORT`. Laissez-les non définies : Acme est testé avec leurs valeurs par défaut, et `SHARD_LOCK_DISABLE_ADVISORY=true` laisserait deux serveurs exécuter les mêmes tâches.

## Application web [#web-app]

| Variable             | Par défaut                                          | Rôle                                                                                                                                                                                                                                                       |
| -------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ACME_API_URL`       | obligatoire en production ; `http://localhost:3000` | L’adresse à laquelle l’application web joint le serveur, comme `http://acme-server:3000`. Elle y transmet `/api/*` et `/.well-known/oauth-*`, et s’en sert pour rendre les pages. Lue à chaque requête : un même build tourne avec n’importe quel serveur. |
| `PORT`               | `3000`                                              | Le port d’écoute de l’application web.                                                                                                                                                                                                                     |
| `HOSTNAME`           | `0.0.0.0`                                           | L’adresse d’écoute de l’application web. Dans un conteneur, où Docker met dans `HOSTNAME` l’identifiant du conteneur, définissez-la à `0.0.0.0`.                                                                                                           |
| `KEEP_ALIVE_TIMEOUT` | celle de Node                                       | Combien de temps, en millisecondes, une connexion inactive reste ouverte, pour un proxy placé devant qui garde ses connexions plus longtemps.                                                                                                              |
| `NODE_ENV`           | `production` pour un build                          | L’application web construite tourne toujours en mode production, où `ACME_API_URL` est obligatoire.                                                                                                                                                        |

## Ligne de commande [#command-line]

| Variable          | Par défaut              | Rôle                                                                                        |
| ----------------- | ----------------------- | ------------------------------------------------------------------------------------------- |
| `ACME_API_URL`    | `http://localhost:3000` | L’adresse de l’instance, comme `https://acme.example.com`, sauf si `--api-url` est indiqué. |
| `ACME_CONFIG_DIR` | non définie             | Le dossier où sont enregistrées les connexions, dans `credentials.json`.                    |
| `XDG_CONFIG_HOME` | non définie             | Sans `ACME_CONFIG_DIR`, les connexions vont dans son dossier `acme`.                        |
| `APPDATA`         | définie par Windows     | Sans l’une ni l’autre, les connexions vont dans son dossier `acme`.                         |
| `HOME`            | définie par le système  | Sinon, les connexions vont dans `~/.config/acme`.                                           |

## Outils [#tools]

`bun nx run acme-server:media-cors`, qui pose la règle CORS des imports sur le bucket, lit les variables `ACME_S3_*` du stockage des médias, `PUBLIC_URL` et `TRUSTED_ORIGINS`, avec les mêmes valeurs par défaut que le serveur. `bun nx run acme-server:bluesky-key` ne lit rien.
